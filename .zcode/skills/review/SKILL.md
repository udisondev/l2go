# review — ревью-конвейер задачи

Единица — одна задача из `план/pN.md`. Состояние конвейера — файлы: статус задачи в плане и
реестр находок `план/ревью/<ID>.md` (создаётся при первом ревью задачи; заготовок не заводим).
Ты — ведущая сессия-оркестратор: спавнишь ревьюеров сабагентами, сливаешь и верифицируешь
находки, правишь, ведёшь реестр. Реализация (S7) — твоя обычная работа. Останавливаешься только
в точках владельца. Инварианты конвейера — в AGENTS.md; они обязательны и здесь.

## Режимы

- **Автономный** («проведи задачу через харнес», «продолжи»): идёшь по стадиям подряд S0→S8,
  останавливаясь только в точках владельца; после S8 — выжимка и 👀.
- **Ручной** (`/review <ID>`): исполняешь только контрольные стадии, положенные задаче сейчас.

## Определение состояния

1. Прочитай раздел задачи в `план/pN.md` (статус, ревью-профиль) и реестр, если есть.
2. Предохранители: ворота красные или не прогнаны → сначала ворота (`make check`; на машине без
   make/gcc — покомпонентно: gofmt/vet/build/test/staticcheck@v0.8.1/checkdeps, оговори это);
   ревью реализации не стартует, пока не закрыто ревью плана; ✅ не ставит никто, кроме
   владельца.
3. Очередная стадия — первая незакрытая из таблицы; «закрытость» определяется по реестру и
   статусу задачи, не по памяти чата.

## Стадии

| # | Стадия | Исполнитель | Выход |
|---|---|---|---|
| S0 | проработка плана задачи | владелец + ты | план согласован владельцем |
| S1 | самопроверка плана | ты | чеклист чист: инварианты AGENTS.md, матрица ADR-0005, план тестов, фальсифицируемые критерии |
| S2 | ревью плана | сабагенты-роли (параллельно, слепо) | слитый дедуплицированный список находок |
| S3 | верификация находок | ты; споры — владелец | реестр заполнен: подтверждена/отклонена/владельцу |
| S4 | исправление плана | ты | каждая подтверждённая закрыта правкой + аргументацией |
| S5 | замыкание | затронутые роли (сабагенты) | авторы находок подтвердили адресацию |
| S6 | свежий взгляд | 3 сабагента без истории | «лучше не найдено» либо подтверждённо лучше → рестарт в S2 |
| S7 | реализация | ты (TDD, ворота) | ворота зелёные |
| S8 | ревью реализации | сабагенты: профильные роли + тестировщик | ноль подтверждённых блокеров/мажоров |
| S9 | приёмка | владелец | ✅ |

Ревью-профиль — из строки задачи; без строки — дефолты ADR-0006 (код мира: инвариантщик,
конкурентщик, прагматик; семантика: +доменщик; горячий путь: +перформансер; протокол/шлюз:
+безопасник; доки/скрипты: облегчённый режим — S1 + ворота + один ревьюер + владелец).

## Точки остановки на владельце

1. Спор в S3: находку нельзя ни подтвердить, ни отвергнуть свидетельством.
2. Исчерпан бюджет любой стадии — что делать дальше.
3. Приёмка S9: выжимка и 👀 → ✅ (только владелец).

Форма вопроса владельцу: суть решения, варианты, твой рекомендованный выбор с причиной.

## Находка

Действительна только со свидетельством одного из пяти видов:

1. место + нарушенное правило (файл:строка / пункт плана / инвариант / ADR);
2. сценарий отказа: вход → неверный исход;
3. трасса интерливинга: шаги по регионам/тикам → нарушение конкурентного инварианта;
4. числа бенчмарка против бюджета или baseline;
5. воспроизводимый злой вход: байты или действия → паника/дюп/выход за границы.

Серьёзность: блокер / мажор / минор. Циклы перезапускают только блокеры и мажоры; миноры
собираются пачкой. Выход из ревью-цикла = ноль подтверждённых блокеров/мажоров (миноры могут
остаться записанными). Верификация (S3) = воспроизвести свидетельство: пройти по месту, прогнать
проверку, собрать трассу; конфликт мнений решается свидетельством, не голосами.

## Реестр план/ревью/<ID>.md

Создаётся при первом входе в контрольную стадию. Формат:

```markdown
# Реестр находок <ID>

- Задача: <раздел в план/pN.md>
- Ревью-профиль: <роли>
- Бюджеты: план 0/2 · рестарты 0/2 · ревью реализации 0/3

## Находки

| ID | Стадия | Роль | Утверждение | Свидетельство | Серьёзность | Статус | Решение |
|---|---|---|---|---|---|---|---|

Статусы: подтверждена · отклонена · владельцу · закрыта (правкой).

## Отклонённые (память анти-петли)

| ID | Утверждение | Причина отклонения | Раунд |
|---|---|---|---|

Переоткрытие отклонённой: новый ID, ссылка на старый, новое свидетельство — иначе
не рассматривается.

## Исправления

| ID | Правка | Аргументация (альтернативы и почему хуже) | Чем проверяется закрытие |
|---|---|---|---|

## Раунды

(раунд, стадия, участники, вердикты замыканий и свежего взгляда)
```

ID — сквозные по задаче: F1, F2, … Раунды бюджетов инкрементируй в шапке.

## Спавн ревьюеров

Каждый ревьюер — отдельный сабагент (general-purpose), параллельно; до слияния находок друг
друга не видят. Промпт = шапка + мандат роли + объект ревью + список чтения. Ревьюер читает
первоисточники сам — копий текстов в промпт не класть (дрейф копий).

Шапка (в каждый промпт, дополни объектом и ролью):

> Ты — ревьюер-<роль> конвейера задачи <ID> репозитория la2 (рабочий каталог — корень репо).
> Прочитай первоисточники: AGENTS.md и <список по роли>. Объект ревью: <спецификация задачи /
> финальный план / диф>. Найди находки. Находка действительна только со свидетельством одного
> из видов: место+нарушенное правило; сценарий отказа; трасса интерливинга; числа бенчмарка;
> воспроизводимый злой вход. Серьёзность: блокер/мажор/минор. Выход: список находок
> {утверждение, свидетельство, серьёзность, предложение}. Без свидетельства — не находка.
> Правки не делай, только находки.

Мандаты и списки чтения:

| Роль | Мандат | Чтение |
|---|---|---|
| инвариантщик | буква правил: инварианты и решения проекта | AGENTS.md; ADR задачи |
| конкурентщик | интерливинги за пределами -race: окна хэндоффа, порядок писем, побег указателя на сущность в замыкании/сообщении, чтение снапшота после флипа владельца, горутины-утечки, буфер лока | AGENTS.md (инв. 4, 7–9); ADR-0003 |
| перформансер | горячие пути: есть ли бенчмарк и честен ли, аллокации, baseline до оптимизации; и обратное — сложность «ради скорости» без измерения | docs/perf.md; ADR-0005 (реестр горячих путей) |
| безопасник | недоверенный вход: границы доверия, валидация на применении, reserve→commit, малформенные пакеты, переполнения; лицензионная гигиена портов и данных | AGENTS.md (референсы/лицензии); ADR-0001 |
| доменщик | семантика мира/протокола, корректность и атрибуция портов из GPL-референсов, поведение | AGENTS.md (референсы); research/r4 |
| прагматик | простота, YAGNI, скоуп («заодно ещё»), именование, читаемость | docs/codestyle.md |
| тестировщик (S8) | покрытие, фальсифицируемость критериев, race-стресс окон хэндоффа, golden-тесты протокола | AGENTS.md (тесты и ворота) |

Слияние: дедупликация (одно свидетельство — одна находка), конфликт мнений → свидетельство или
владельцу.

## S5 — замыкание

Повторно спавнируй только роли, чьи подтверждённые находки правились. Промпт: их находки +
дельта (что изменилось с их прошлого взгляда), вопрос «адресовано ли». Полный ре-ревью всего
объекта не устраивать.

## S6 — свежий взгляд

Три сабагента, промпт без истории итераций: исходная проблема задачи + финальный план. Вопрос:
«решение состоятельно? предложи конкретно лучше, с трейдоффами». Рестарт (возврат в S2) — только
если альтернатива конкретна и превосходство подтверждено верификацией по свидетельствам; иначе
«лучше не найдено» фиксируется в реестре. Бюджет рестартов ≤2, дальше — владельцу.

## S8 — ревью реализации

Панель: профильные роли + тестировщик. Дополнительно к ролям — двусторонняя трассировка
(поручается тестировщику или отдельному сабагенту):

- каждый пункт финального плана → артефакт (файл / тест / коммит);
- каждый значимый кусок диффа → пункт плана или запись-отклонение в реестре с аргументацией.

Цикл: находки → верификация → правки кода (твоя обычная работа, TDD, ворота) → повторное
замыкание только по оставшимся. До нуля подтверждённых блокеров/мажоров, ≤3 раунда.

## S9 — выжимка владельцу

Формат: что сделано (по пунктам плана); статус ворот; подтверждённые находки и их закрытие;
отклонённые (коротко); отклонения от плана; вопросы. Переведи статус задачи в 👀, запиши
прогресс в `план/прогресс.md`. ✅ ставит только владелец.
