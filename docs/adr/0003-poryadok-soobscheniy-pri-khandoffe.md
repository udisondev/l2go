# ADR-0003: Транспорт и владение — потоковая модель мира (v10)

**Статус:** draft (v10.2 — редизайн по дизайн-сессии с владельцем + правки циклов 1–2 ревью,
§14. История v1–v9 — в git: v8 = 5398d72, v9.4 = 45ad4ae. Правило завершения циклов: до
отсутствия замечаний; отвергнутые — §12).

## 1. Глоссарий (для сессий, не видевших обсуждения)

| Термин | Значение |
|---|---|
| **Сущность** | Игрок, моб, NPC — единица состояния (HP, позиция, инвентарь). Имеет вечный уникальный `id`. |
| **Слуга** | Пет/саммон игрока. НЕ отдельная сущность транспорта: адресуется как `(ownerID, slot)`. |
| **Регион** | Горутина-актор, тикающая свои сущности и мутирующая их состояние. Единица параллелизма. |
| **Ящик** | Личная очередь сущности: MPSC FIFO, адрес вечен, никогда не переезжает. Единственная точка входа писем сущности. |
| **Читатель** | Регион, имеющий право разбирать ящик. В каждый момент — ровно один (или никто, в окне переезда). |
| **Курсор** | Позиция «дочитано досюда» в ящике. Передаётся только в чемодане. |
| **Чемодан** | Пакет переезда: состояние сущности (единственный указатель) + курсор + недообработанная пачка + transfer-журнал + dirty-флаги + слуги. |
| **Черновик** | Копия сущности в регионе-приёмщике ДО подтверждения: не читает ящик, не эмитит эффектов, не персистит, не публикуется. |
| **Владелец** | Подтвержденный читатель = единственный, кто мутирует состояние, публикует снапшот, пишет персист. |
| **Лок переезда** | Флаг-состояние «еду» на сущности + накопление писем в ящике. НЕ мьютекс: никто никогда не ждёт. |
| **Порция** | Пачка писем, изъятая из ящиков региона на границе тика. Единица детерминированной свёртки. |
| **Изъятие vs применение** | Изъятие = атомарная установка водяного знака на границу прочитанного (одно действие в тике читателя). Применение = обработка изъятого. Между ними возможна недообработанная пачка. |
| **Водяной знак** | Синоним курсора: позиция потребления ящика. Сбор сегментов очереди — только ниже знака. |
| **Контрольное письмо** | Письмо региону как таковому (чемодан, ack, подтверждение, retire) — в ящик региона, не в ящики сущностей. |
| **Грац** | Окно после ДЕСПАВНА сущности, в котором ещё возможны письма-страгглеры; по истечении — финальный дроп по классам и компакция записи карты. |
| **Смерть vs деспавн** | Смерть игрока = состояние «лежит» (ждёт ресс/ToV — долго). Деспавн = логаут, удаление персонажа, истечение трупа моба. GC — только по деспавну. |
| **SoA** | Structure of Arrays: пер-тиковый проход по плоским массивам полей сущностей (кеш-дружелюбно); работа тика, не события. |
| **AoI** | Area of Interest — что и с какой частотой видит клиент; предмет ADR-0004. |
| **Шлюз** | Пограничный слой входа: пакеты клиентов и wall-clock события scheduler'а назначаются в порции; единственное место настенных часов. |
| **Advisory-вход** | Данные, прочитанные регионом из снапшота соседа и повлиявшие на геймплейное решение; логируется в порцию (D5) как вход. |
| **Класс письма** | fire-and-forget / reliable-until-delivered / transfer (см. §7). |
| **Метроном** | Диспетчер тиков ADR-0002: 10 Гц, no barrier. |

## 2. Контекст и цель

Один процесс, регионы-акторы, каналы надёжны и FIFO, тик-модель ADR-0002 (никто никого не
ждёт). Гарантии-цели: at-most-once на письмо; exactly-once эффекта (включая рестарт);
порядок одного отправителя при любых переездах; единственный владелец всегда; ящики без потерь;
граница регионов маскируется интерполяцией и лагом. Производительность: 10k+ онлайна, бюджет
шага региона p99 ≤ 10–20 мс (числа — §11).

**Мировоззрение v10:** мир — детерминированная свёртка над потоками:

```
входы:   пакеты клиентов → шлюз → ящики сущностей (слепой push, без маршрутизации)
движок:  мир = fold(тик, состояние, порции)        — детерминированная функция
выходы:  три потребителя результата тика: (а) пакеты игрокам; (б) бухгалтерия на диск
         (WAL + снапшоты); (в) публикация снапшота для соседних регионов
```

Персистенция — не «слой», а потребитель выходного потока. Событие принадлежит потоку
сущности → журнал сделок едет в чемодане (см. §8).

## 3. Сущность и ящик

- Сущность = запись с полями состояния + **ящик** (заголовок ящика лежит рядом с записью —
  кеш-локальность тика). Ящик: MPSC FIFO (multi-producer, single-consumer с мигрирующим
  потребителем); аллокируется при создании сущности всегда (ленивость отвергнута — гонка
  двойного создания; цена ≈ 5–10 МБ на 50k сущностей).
- **Глобальная карта `id → ящик`:** запись при рождении, никогда не перезаписывается.
  Запись в карту — через `atomic.Pointer` на COW-версию (или sharded RWMutex); чтение — один
  atomic.Load, без блокировок. **Дисциплина отправителя: lookup → enqueue смежные операции,
  указатель ящика между отправками не кешируется.** **Деспавн — порядок компакции:**
  (1) ящику выставляется dead-флаг, проверяемый в enqueue (поздний страгглер получает
  классовый дроп + метрику, а не тихую потерю); установка флага + финальный дрен и
  проверка-флага+push в enqueue идут под одним мьютексом этапа-1 (§11); (2) финальный дрен
  по классам; (3) свап карты
  на синглтон «мёртв» (бюджет компакции — метрика). Смерть игрока — НЕ деспавн (ress ждёт
  долго). ID никогда не переиспользуются.
- В ящике: очередь писем; курсор-водяной знак потребления (двигает только подтверждённый
  читатель; сбор сегментов — только ниже знака, в том числе в окне переезда); поле `owner`
  (кто читатель; пишется создателем и протоколом переезда — никогда игровой логикой); маркер
  домена; маркер смерти; читательский журнал для отладки (кто/когда разбирал).
- **Рождения и спавны:** таймеры респавна — состояние региона-владельца точки спавна, тикают
  в его тике (детерминированно, отдельный спавн-сервис не нужен); рождение = аллокация ящика
  + запись в карту + установка читателя; смерть — маркер в ящике (И1).
- Конверт письма: `{to (id | (ownerID, slot)), fromID, class, attrs, payload}`. `fromID` —
  вечный ID отправителя (сущность / сервисная шарда / шлюз). `attrs` — флаги, включая «интент
  привязан к позиции/моменту» (резолв — валидацией на применении у читателя).

## 4. Отправка и разбор

- **Отправка — слепой push:** lookup `id → ящик`, enqueue. Никакой маршрутизации, никаких
  проверок свежести адреса, никакого ожидания. Эпохи, seq, перенаправления, reorder-буферы —
  отсутствуют как класс (историческая реализация — v9, git).
- **Разбор — на границе тика:** регион обходит своих сущностей по **сортированному слайсу**
  (детерминизм, И10), изымает порции писем, применяет к состоянию. **Изъятие = один атомарный
  store водяного знака на границу прочитанного**; применение — после; недообработанная пачка
  (изъято, но не применено, например в момент заморозки) едет в чемодане; при аборте
  отправитель доигрывает свою пачку до возобновления чтения. Валидация — на применении: домен
  (класс письма против домена сущности), радиус, живость, attrs-привязка. Допуски валидации
  отложенной пачки — P0.10.
- **Переполнение ящика живого адресата:** transfer/reliable живому НЕ дропаются никогда
  (рост объёма пренебрежим: transfer редок, reliable ограничен отправителем) — память лечится
  окнами/капами обработки; fire-and-forget — коалесинг/дроп по per-box капу с метрикой.
  Финальный дроп — только мёртвому (после граца), по классам (§7 согласован).
- **Две почтовые системы:** письма сущностям — в ящики; контрольные письма региону (чемоданы,
  ack, подтверждения, отбой) — в ящик региона. Выбор — по типу адресата (поле в таксономии).
- **Единая декларация очереди:** у каждой очереди системы (ящик, ящик региона, исходящий
  буфер клиента) явно заданы: ограничение, политика переполнения (никогда не блокировать;
  дропнуть по классу; скоалесить), метрики (глубина, латентность). Блокирующих ожиданий в
  конвейере нет нигде (единственное исключение — мьютекс этапа-1 внутри enqueue, §11:
  микросекунды, не затрагивает читателя) — негде спрятаться «скрытому ожиданию».

## 5. Переезд (хэндофф)

Инициируется **в собственном тике** региона-владельца (пересечение границы с гистерезисом,
телепорт, вход в инстанс, логаут). Конкуренция поводов (граница против телепорта) — ровно один
победитель (CAS по флагу), проигравшие — отложенные намерения, исполнятся следующим тиком.

```
RB (тик, одним блоком; шаги идемпотентны; состояние попытки — память региона):
1. флаг «еду» (лок-состояние): RB ПРЕКРАЩАЕТ читать ящик — письма копятся сами
2. чемодан = {состояние (единственный указатель!), курсор, недообработанная пачка,
   transfer-журнал, dirty-флаги, слуги-слоты}
3. send чемодан → RC (контрольный ящик); таймер T_ack
4. Вася заморожен, публикуется в снапшоте RB (видимость не рвётся); владение НЕ менялось

RC:
- разворачивает ЧЕРНОВИК: держатель состояния+курсора (НЕ разыменовывается до подтверждения;
  при аборте — выбрасывается целиком), НЕ ЧИТАЕТ ящик, НЕ эмитит эффектов, НЕ персистит,
  НЕ публикуется
- send install-ack{entity, attempt} → RB

RB по ack:
5. install-ack несёт {entity, attempt}: флип owner выполняется ТОЛЬКО если попытка ещё
   жива (in-flight у RB); попытка мертва (абортнута/превзойдена) → no-op + контрольное
   retire{entity, attempt} → RC (гасит черновик). Это защита от «медленный RC ожил
   после аборта и прислал поздний ack» — устаревший флип непредставим
6. флип = ТОЧКА НЕВОЗВРАТА: после неё попытка неделима, abort невозможен; потеря
   confirm-ack → копия RB забывается по таймеру (liveness-only, алерт), владение
   уже у RC, redirect не нужен (адрес вечен)
7. по confirm-ack: копия забывается; удержание в write-behind персисте RB — УСЛОВНОЕ,
   до снапшота Васи@новая-эпоха на диске RC (см. §8)
8. RC (владелец) применяет недообработанную пачку чемодана, затем возобновляет чтение
   ящика со знака; симуляция, публикация, персист

Авария «нет ack за T_ack» (ДО флипа) → retransmit чемодана (≤2) → ABORT:
   RB снимает флаг, ДОИГРЫВАЕТ свою недообработанную пачку, возобновляет чтение со
   знака (изъятое при заморозке вернулось пачкой; неизъятое стоит ниже знака — двойного
   применения нет), симуляция продолжается. Откат позиции нет.
   Retire-письма RC: при аборте, при забвении попытки, при деспавне сущности — всегда
   от текущего владельца (приоритетная полоса); гасят только НЕподтверждённые черновики,
   никогда — продвинутого во владельца; TTL-GC черновика — только по доказанной смерти
   (retire/аборт), голый TTL запрещён. Дубль чемодана (retransmit) идемпототен на RC по
   ключу попытки: до активации — заменить, после — no-op. Все таймеры (T_ack, cooldown,
   забвение) — в тиках/симуляционном времени (D1).
```

- Номер попытки — собственный счётчик сущности (в памяти, не в персисте; с рестартом умирает
  вместе с черновиком — коллизий нет).
- Freeze-бюджет — в тиках: окно ≈ чемодан + ack + флип + подтверждение (4 контрольных хопа =
  до ~8 тиков при 10 Гц, хвост ~0.8 с); abort = стойка ≤ T_ack×3 без телепорт-назад;
  T_ack — в тиках (5–10). Двойной фриз подряд (телепорт в момент пересечения): один
  победитель (И7), суммарное окно ≤ одного бюджета + одна отгрузка (интент смены владельца
  резолвится источником до отгрузки). Per-entity cooldown (сотни мс) против зигзага; гистерезис — несущее
  предположение (r0/r3). Исходящий буфер самому замороженному жив: клиент видит движение мира.
- Контрольные письма — приоритетной полосой с бюджетом; при исчерпании падают в обычный разбор
  (не дропаются). Чемоданы тика коалесятся.

## 6. Слуги

Слуга — слот состояния хозяина (slot 0 — позиционный пет/саммон; 1..3 — кубики). Записи в
карте и ящика нет; письмо слуге `(ownerID, slot)` падает в **ящик хозяина**. HP/позиция/команды
мутируются регионом-владельцем хозяина. Снапшот хозяина публикует `servants[]` под стабильным
протокольным objectId (AoI-дедуп по составному ключу — требование в ADR-0004). Слуга — обычный
mover (follow/stand/attack); телепорт-поводок — только аномалия; инвариант R_leash ≤ глубины
читаемых снапшотов; потеря цели из AoI → стоп+возврат. Смерть = слот-флаг с позицией трупа;
ресс = снятие флага; логаут = деспавн. Исходящие действия слуги — от fromID хозяина.

## 7. Классы доставки

| Класс | Поведение при финальном дропе | Примеры |
|---|---|---|
| fire-and-forget | молча дроп | урон, бродкаст |
| reliable-until-delivered | уведомление владельцу отправителя + алерт | аггро, KillCredit, XP, контроли |
| transfer | дроп = чистый abort | Reserve/Commit, spoil/sweep, подбор лута |

Дроп transfer/reliable живому адресату невозможен (переполнение — §4: копятся, объём
пренебрежим; fire-and-forget дропается по капу с метрикой); финальный дроп — только мёртвому
(dead-флаг/после граца деспавна), по классам, с метрикой; ≠0 финальных дропов reliable/transfer
— инцидент. Ретраев отправителя нет: письмо либо лежит в ящике, либо адресат мёртв.

## 8. Персистенция — потребитель выходного потока (фаза 5)

- Пишет только ВЛАДЕЛЕЦ (черновик не пишет ничего, включая shutdown-путь T3).
- **WAL transferID, journal-before-apply:** Reserve/Commit/Abort несут полный payload
  переноса **и предусловие** (условие источника: жив, состояние, эпоха) — при реплее
  **предусловие проверяется РАНЬШЕ Committed-доказательства**: не выполняется в
  восстановленном состоянии → transfer откатывается, даже при наличии доказательства
  (закрывает «смерть → death-drop → подбор → kill -9 в окне ≤60 с»: жертва откатилась живой,
  а лутер остался с вещью). Group-commit fsync ДО применения Commit. Резолв transferID
  глобален: предусловие выполнено + есть Committed-доказательство (WAL ∪ transfer-журнал
  сущности) → коммитится у обеих сторон; Reserved без Committed → Abort + компенсация.
  Transfer-журнал `{transferID, фаза, payload, предусловие}` — состояние сущности (едет в
  чемодане и снапшотах владельца) — переживает смену владельца и обрезку; обрезка WAL-записи
  — только после резолва всех сторон; субъект резолва — инициатор. Каскадный откат
  (лутер успел передарить в окне ≤60 с) — OQ §13.
- **Снапшоты write-behind** per-owner (30–60 с), атомарная замена, чексуммы. Потеря при kill -9:
  ≤60 с волатильной статики. **Условное удержание:** предыдущий владелец не вытесняет
  сущность из персиста до снапшота с новой эпохой на диске нового владельца (замыкается
  snapshot-persist-ack — контрольное письмо; каскадно по цепочкам переездов; интервалы —
  симуляционное время, T2-фриз их останавливает). Маркер владения {id, owner, epoch} пишется
  той же атомарной заменой сразу после первого WAL-взноса нового владельца. Восстановление:
  директива владения из маркеров (коллизии по max-epoch; внутри эпохи — по свежести),
  состояние — из персиста победившей записи; волатильное (письма в ящиках, исходящие буферы,
  номера попыток, читатели) с рестартом умирает — и письма, и читатели.
- Эпоха в v10 — метка персиста/маркера (не транспортная): инкремент при каждом завершённом
  переезде.

## 9. Надзор (let-it-crash на уровне владения)

Владение не отбирается никогда; recovery-домен зависшего актора — процесс. T1 ≈ 2 с — лаг
региона: лог + pprof. T2 ≈ 5–10 с — фриз мира + пейдж (оператор: разморозить/hold). T3 ≈ 60 с —
graceful: стоп метронома и логинов, flush снапшотов + WAL (черновики не флашатся), exit.
Backstop: systemd `sd_notify` + `Restart=on-failure` + старт-лимит; kill -9 корректен всегда.
После рестарта — WAL-реплей + очередь логинов ступенями. Реплей-логи входов переживают рестарт
(§10) — авария воспроизводима.

## 10. Детерминизм и реплей

Правила (уровень AGENTS):

- **D1:** dt = (количество тиков с прошлого шага) × период метронома — по счётчику тиков, не
  по настенным часам (дропнутый тик по-прежнему даёт dt=2×период; анти-чит-свойство ADR-0002
  сохранено). Это уточнение инварианта 7 AGENTS/ADR-0002 (было: монотонные часы) — при акцепте
  v10 инвариант 7 переформулируется вместе с четвёртым. Настенные часы — только в шлюзе входа
  (назначение порции). **Wall-clock события** (осада в 20:00, манор, расписания) — второй
  внешний источник входов наравне с пакетами клиентов: scheduler-актор отправляет их письмами
  через шлюз, назначаются в порции, логируются (D5); политика пропущенных после T3 — OQ.
- **D2:** RNG региона тика — сеяный от (regionID, tick); общего RNG нет.
- **D3:** обход сущностей в тике — по сортированному слайсу id; итерация по map в игровой
  логике запрещена.
- **D4:** все события между сущностями — только письма через ящики (внутрирегионные тоже);
  пер-тиковая работа (фаза A геодаты) — не события, остаётся SoA-проходом. **Чтение чужого
  снапшота в игровой логике — только через advisory-API, который логирует чтение в порцию
  (~20 б/чтение); прямой дереференс снапшота соседа вне модуля репликации запрещён** (уровень
  D3). Реплей-харнесс инъектирует залогированные advisory-значения как входы — не перечитывает
  реконструированные снапшоты. Снапшоты вне advisory-API — строго репликация к клиенту,
  входом свёртки не являются.
- **D5:** лог порций: для каждого ящика — последовательность (письма, границы тиков
  **с номерами тиков**), advisory-входы; плюс лог переездов (сущность, регион, тик завершения).
  Заголовки — всегда; payloads — кольцевым буфером или по флагу (адаптивно; advisory-входы
  логируются всегда, под выпадение не подпадают); fsync не требуется.
- **D6:** реплей-харнесс — продукционная фича с фазы 3: прогон лога порций (с письмами,
  advisory-входами и переездами) через тот же fold. Каждый производственный баг =
  воспроизводимый тест. Расхождение реплея = красный тест; D1–D3 полисятся по построению,
  D4 — по построению через advisory-API (не по расхождению реплея).

Быстрый локальный маршрут (внутрирегионные вызовы мимо ящика) — опция по измерениям фазы 4,
только с эквивалентным логированием (по умолчанию выключена).

## 11. Цена и производительность (прикидки первого порядка; фальсифицируются фазой 4)

- Горячий путь дешевле v9.4: минус epoch/seq/reorder-проверки с каждого письма.
- Опрос ящиков: ~0.2% бюджета тика (заголовок рядом с записью сущности).
- Память ящиков: ~5–10 МБ на 50k сущностей.
- Переезды: ~80/с × десятки КБ — доли процента ядра.
- Унифицированность (всё через ящики): при пике 1M событий/с ≈ 10% одного ядра против прямых
  вызовов — принято по умолчанию (простота/реплей); быстрый маршрут — фаза 4.
- Логи реплея: единицы % CPU, до ~100 МБ/с диска в пике — адаптивная политика D5.
- **Цена владения транспортным ядром:** MPSC с мигрирующим читателем и водяным знаком —
  нетривиальный конкурентный код. Этап 1 реализации — мьютекс внутри enqueue (неблокирующий
  для читателя и отправителей на чтение), контракт тот же; переход на lock-free — по
  измерениям фазы 4. Обязательные модель/стресс-тесты инвариантов И2/И4/И5 на инжектируемом
  шве + `-race` — с фазы 3 (реплей их НЕ покрывает: лог пишется после очереди).
- Настоящий риск производительности проекта — не транспорт, а «проблема города» (knownlist,
  ADR-0004); v10 её не касается и не мешает её решать потоково.

## 12. Отвергнутые альтернативы (реестр; не поднимаются без новых доказательств)

История v1–v9 — git (5398d72, 45ad4ae). Актуальные отвержения v10:

1. **Эпохи/seq/перенаправления как транспорт** (v9) — superseded ящиком: адрес вечен,
   перенаправлять нечего; порядок и отсутствие дублей — следствие единственной FIFO-очереди.
2. **Рекламация владения** (v2–v8) — superseded черновиком (владение не отбирается).
3. **Компаунд-поезда слуг** (v4–v8) — superseded слотами-субсущностями.
4. **Координатор владения** — гонки структурно отсутствуют (инициатор — текущий владелец).
5. **Общий шкаф состояния** (разделяемая запись + указатель владельца) — отвергнут: обмен
   «невозможно по построению» на «запрещено дисциплиной»; состояние передаётся единственным
   указателем в чемодане.
6. **Буквальный мьютекс на сущности** — отвергнут: блокирующее ожидание ломает ADR-0002;
   лок = флаг-состояние + ящик-буфер.
7. **Черновик читает ящик** — отвергнуто: двигает водяной знак до подтверждения, аборт терял
   бы сегменты; чтение — только у подтверждённого владельца.
8. **Ленивое создание ящиков** — отвергнуто (гонка двойного создания); аллокация всегда.
9. **Полный seq-TCP; синхронный хэндофф; пул конвертов; запрет трейда при переезде** — из
   истории (git).

## 13. Открытые вопросы

1. Корабли/пассажиры — кандидат ADR-0005. 2. Взаимоубийство у границы (порядок двух смертей) —
фаза 4. 3. Групповые телепорт-бёрсты — метрики фазы 6. 4. Death-drop у границы — фаза 5.
5. Гварды (немигрирующие преследователи, как слуги) — P0.10. 6. Карантин региона по контексту
крэша. 7. Быстрый локальный маршрут — фаза 4 по измерениям. 8. Ретенция реплей-логов и
инструментарий тайм-тревела — фаза 3+. 9. Политика пропущенных wall-clock событий после T3.
10. Каскадный откат transfer (передаривание в окне ≤60 с до kill -9) — компенсация, фаза 5.

## 15. Гарантии (честные)

- **At-most-once на письмо:** ровно один push, ровно одно изъятие; путей дублей нет.
- **Exactly-once эффекта:** + WAL/transfer-журнал (§8), включая рестарт и реплей.
- **Порядок отправителя:** FIFO ящика по построению, при любых переездах (курсор).
- **Единственный владелец:** флип owner после install-ack; черновик ничего не делает; второй
  читатель непредставим; в окне — ноль читателей (письма копятся).
- **Ящики без потерь:** порции изымаются, но не теряются; переполнение — политика класса.
- **Граница:** freeze-p99 с бюджетом; abort = стойка ≤ T_ack×3 без телепорт-назад; авария
  процесса = фриз/рестарт по лестнице (инцидент-класс).
- **Воспроизводимость:** D1–D6 → реплей бит-в-бит по логу порций.

## 16. Последствия

- P0.9: транспортный компонент = {карта id→ящик, MPSC-очередь с мигрирующим читателем и
  водяным знаком, конверт, контрольный ящик региона, **advisory-API (снапшот-типы
  инкапсулированы в модуле репликации — прямой дереференс невозможен физически)**,
  инжектируемый шов}. P0.10: таксономия
  несёт классы, composite-адресацию, attrs, домен-политику, выбор почтовой системы.
  Компакция карты — в обязательных модель/стресс-тестах (наряду с И2/И4/И5).
- Фаза 3 обязана родиться с: ящиками, реплей-харнессом, детерминированными обходами.
- ADR-0004 (knownlist): потоковая рамка (соединение потоков с ограничителями частоты);
  составной ключ AoI-дедупа; выбор источника по max-epoch в окне переезда; **hold-last:
  источник старой эпохи держится до появления новой** (анти-мигание на стыке переезда).
- При акцепте — AGENTS.md: инварианты И1–И12 (ниже) + D1–D6; переформулировать инвариант 4
  (ящик/курсор/черновик) И инвариант 7 (dt = тики × период, не часы — уточнение ADR-0002).

**Инварианты И1–И12:** И1 адрес вечен, ID не переиспользуются, смерть = маркер. И2 у ящика
ровно один читатель (или ноль в окне); передача читателя = курсор в чемодане; водяной знак
двигает только владелец. И3 состояние — единственный указатель, передаётся только в чемодане.
И4 письмо: один push, одно изъятие. И5 порядок = порядок push; между ящиками не определён.
И6 никакого ожидания: лок = флаг + буфер. И7 конкуренция за переезд: один победитель. И8
черновик пассивен. И9 предметы/деньги — только transfer + journal-before-apply. И10 D1–D3.
И11 слуга без ящика. И12 отправка — только через транспорт.
