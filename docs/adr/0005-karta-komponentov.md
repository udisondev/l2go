# ADR-0005: Карта компонентов и правила зависимостей (package-driven)

**Статус:** draft (исполнение P0.9; на акцепте владельца).

## Контекст

Фаза 1 своим первым коммитом создаёт пакеты протокола, крипты и headless-клиента; каждая
агентская сессия без единой карты решает структурные микрорешения заново — связность
становится лотереей (мотивировка P0.9 из r2). Все содержательные границы уже решены
принятыми ADR и разбором референсов: модель тика (ADR-0002), транспорт/владение
(ADR-0003 §16), репликация/AoI (ADR-0004 «Последствия»), топология процессов и модель
владения буфером (r4), восемь принципов исполнения владельца (план/p0.md, пополнение P0.9;
гайды [docs/codestyle.md](../codestyle.md) и [docs/perf.md](../perf.md)).

## Решение

1. **Единица проектирования — пакет Go.** Карта компонентов = проверяемый граф импортов,
   а не диаграмма: границы компонентов = границы пакетов, контракт живёт в коде и
   проверяется компилятором; wire-up (сборка зависимостей) — только в `cmd/`.
2. **Топология процессов** (r4, решение владельца): LoginServer — один процесс на все миры;
   GameServer — процесс на каждый мир; стык login↔game всегда сетевой (gRPC с фазы 3,
   семантика из pkg/rpc interlude); внутри game-процесса RPC отсутствует по построению
   (ящики/снапшоты — общая память, r0). gRPC живёт только в пограничных пакетах
   (`loginlink`, `admin`, harness); пакеты мира его не импортируют.
3. **Раскладка:** `internal/` — всё доменное и служебное приложения; `pkg/` — публичный
   импортируемый API для внешних проектов (репо публичное, GPLv3) с жёстким критерием:
   пакет уже сейчас без доменных зависимостей и полезен вне la2 (не «потенциально» —
   принцип 6); переезд в `pkg/` — отдельное решение. Первый житель — `pkg/bufpool`
   (порт interlude, фаза 1). Крипта доменна (блоуфиш/XOR протокола L2) — `internal/crypto`.
4. **Несетевые сервисы** (пати/чат/клан/маркет) — **акторы-шарды на том же транспорте**
   (решение владельца): собственные адреса, письма через те же ящики, fromID сервиса — в
   конверте; реплей D1–D6 покрывает их без отдельных механизмов; детализация шардирования —
   фаза 3+.
5. **Матрица зависимостей** (кому разрешён импорт кого; всё, что не разрешено, — запрещено):

| Пакет | Разрешено импортировать | Рождение |
|---|---|---|
| `internal/version` | — | есть |
| `internal/crypto` | — | фаза 1 (порт) |
| `pkg/bufpool` | — | фаза 1 (порт) |
| `internal/protocol` | crypto, pkg/bufpool | фаза 1 |
| `internal/l2client` | protocol, crypto | фаза 1 |
| `cmd/pcap-analyzer`, `cmd/l2client` | — (инструменты) | фаза 1 |
| `internal/data` | — | фаза 2 |
| `internal/geo` | — | фаза 2 |
| `internal/net` | protocol, crypto | скелет — P0.9; реализация — фаза 3 |
| `internal/gateway` | net, protocol, transport | скелет — P0.9; реализация — фаза 3 |
| `internal/transport` | — | скелет — P0.9; реализация — фаза 3 |
| `internal/world` | transport, replica, encode, data, geo | скелет — P0.9; каркас — фаза 3 |
| `internal/replica` | transport | скелет — P0.9; реализация — фазы 3–4 |
| `internal/encode` | protocol, replica, pkg/bufpool | скелет — P0.9; реализация — фазы 3–4 |
| `internal/svc` | transport | скелет — P0.9; сервисы — фаза 3+ |
| `internal/persist` | transport | скелет — P0.9; реализация — фаза 5 |
| `internal/loginlink` | — (gRPC, фаза 3) | скелет — P0.9 |
| `internal/admin` | — (gRPC, фаза 3+) | скелет — P0.9 |
| `cmd/logind`, `cmd/gamed`, `cmd/replay` | всё внутреннее (wire-up) | фаза 3 |

   `cmd/*` не ограничены (только сборка). Новый верхнеуровневый пакет — правка этого ADR.
   Скелеты P0.9 — только типы и интерфейсы на границах (без поведения): их наполнение —
   фазы 1–5; таксономия сообщений и модель сущности — P0.10 поверх этих пакетов.

6. **Реестр горячих путей** (правило «путь рождается с бенчмарком» — принцип 3):

| Горячий путь | Пакет-хозяин | Бенчмарк с фазы |
|---|---|---|
| Пакет-писатель (40 Б пакет, 0 аллокаций) | `protocol` | 1 |
| Криптографический блок (блоуфиш/XOR) | `crypto` | 1 |
| BufPool Get/Put по бакетам | `pkg/bufpool` | 1 |
| Геодата: canMove/пасфайнд | `geo` | 2 |
| Enqueue/изъятие ящика (MPSC, водяной знак) | `transport` | 3 |
| Отправка письма (lookup + enqueue) | `transport` | 3 |
| Join AoI / затравка / пересборка view set | `replica` | 3–4 (join-бенч — ADR-0004) |
| Энкод/композ кадра, криптоблок | `encode` | 3–4 |
| Тик региона / SoA-проход | `world` | 4 |

7. **Проверка правил:** `scripts/checkdeps.sh` (в `make check`): матрица из п. 5 навязывается
   графу импортов через `go list -deps`; нарушение = красный билд; пакет вне матрицы = красный.
   Дополнительно — ревью-чеклист AGENTS.md и перечитывание карты на старте каждой фазы.

## Альтернативы (отвергнуты)

- **Карта как research-документ без статуса ADR** — правила зависимостей не защищены
  «меняется только ADR»; владелец выбрал ADR (блок 0).
- **Только секция в AGENTS.md** — AGENTS.md теряет форму инвариантов и разбухает.
- **`pkg/` для всего служебного** (cargo-cult golang-standards/project-layout) — pkg без
  внешних потребителей различие не несёт; принят критерий «уже generic».
- **Каталог граничных интерфейсов «на каждый компонент»** (enterprise-стиль) — против
  package-driven (интерфейсы у потребителя, возвращаем конкретные типы — codestyle §2/§8).
- **gRPC/RPC-фреймворк внутри game-процесса** — противоречит r0/ADR-0003 (один процесс,
  ящики в общей памяти); gRPC — только стыки (r4).
- **Сервисы как библиотеки регионов** — пати на три региона требует межрегионального
  протокола согласования и выпадает из единого реплей-конвейера; отвергнуто (блок 1).

## Последствия

- Фаза 1: `pkg/bufpool`, `internal/crypto`, `internal/protocol`, `internal/l2client`,
  `cmd/l2client`, `cmd/pcap-analyzer` — по конвенциям codestyle/perf (писатели, views,
  BytePool, TCP_NODELAY/deadlines).
- Фаза 3: реализации `net`/`gateway`/`transport`/`world` (каркас конкурентности в минимальной
  экспозиции), `cmd/logind`/`cmd/gamed`, `cmd/replay`, gRPC `loginlink`; фаза 3 обязана
  родиться с ящиками и реплей-харнессом (ADR-0003 §16).
- P0.10: наполняет `transport` (классы/attrs/домены, таксономия), `world` (модель сущности),
  `replica` (черновик формата снапшота) — типами поверх скелетов.

## Цена решения

- Скелеты — «мёртвый» код до своих фаз: цена контракта в коде (компилятор ловит расхождения
  молча и рано).
- Матрица ограничивает свободу: каждый новый верхнеуровневый пакет или ребро — правка ADR
  (сознательно: структурные решения не должны приниматься молча).
- Скрипт проверки требует сопровождения синхронно матрице (дубль в одном файле — приемлемо).

## Проверка решения

- `make check` собирает скелеты (контракт компилируется) и гоняет `checkdeps` (матрица
  краснеет на нарушении — проверяется намеренным нарушением один раз, как red-proof P0.2).
- Каждый путь из реестра п. 6 получает бенчмарк в фазе своего рождения; регресс-бюджеты —
  фаза 4 (таблица P0.2).
- На старте каждой фазы карта перечитывается; расхождение карта↔код = баг карты или кода.
