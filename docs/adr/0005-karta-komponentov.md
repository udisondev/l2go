# ADR-0005: Карта компонентов и правила зависимостей (package-driven)

**Статус:** draft.

## Контекст

Первые же коммиты создают пакеты протокола, крипты и headless-клиента; без единой карты
каждая сессия решает структурные вопросы заново — связность становится лотереей.
Содержательные границы уже зафиксированы принятыми решениями: модель тика, транспорт и
владение, репликация/видимость, топология процессов, модель владения буфером, принципы
исполнения (package-driven design, TDD, бенчмарки на горячих путях, оборачивание ошибок,
slog, простота, гайды стиля и производительности).

## Решение

1. **Единица проектирования — пакет Go.** Карта компонентов = проверяемый граф импортов, а
   не диаграмма: границы компонентов = границы пакетов, контракт живёт в коде и проверяется
   компилятором; wire-up (сборка зависимостей) — только в `cmd/`.
2. **Топология процессов.** LoginServer — один процесс на все миры; GameServer — процесс на
   каждый мир; стык login↔game всегда сетевой (gRPC; семантика: RegisterSession / Kick /
   онлайн-статистика). Внутри игрового процесса RPC отсутствует по построению: ящики и
   снапшоты живут в общей памяти. gRPC — только в пограничных пакетах (`loginlink`,
   `admin`, harness); пакеты мира его не импортируют.
3. **Раскладка.** `internal/` — всё доменное и служебное приложения; `pkg/` — публичный
   импортируемый API для внешних проектов (репозиторий публичный, GPLv3) с жёстким
   критерием: пакет уже сейчас не имеет доменных зависимостей и полезен вне проекта — не
   «потенциально»; переезд в `pkg/` — отдельное решение. Первый житель — `pkg/bufpool`
   (бакетный пул байтовых буферов). Крипта доменна (блоуфиш/XOR протокола L2) —
   `internal/crypto`.
4. **Несетевые сервисы** (пати/чат/клан/маркет) — акторы-шарды на том же транспорте:
   собственные адреса, письма через те же ящики, fromID сервиса — в конверте; реплей
   покрывает их без отдельных механизмов; детализация шардирования — при реализации.
5. **Матрица зависимостей** (кому разрешён импорт кого; всё, что не разрешено, — запрещено;
   пакет вне матрицы — ошибка):

| Пакет | Разрешено импортировать |
|---|---|
| `internal/version` | — |
| `internal/crypto` | — |
| `pkg/bufpool` | — |
| `internal/data` | — |
| `internal/geo` | — |
| `internal/transport` | — |
| `internal/protocol` | crypto, pkg/bufpool |
| `internal/net` | protocol, crypto |
| `internal/gateway` | net, protocol, transport |
| `internal/replica` | transport |
| `internal/encode` | protocol, replica, pkg/bufpool |
| `internal/world` | transport, replica, encode, data, geo |
| `internal/svc` | transport |
| `internal/persist` | transport |
| `internal/l2client` | protocol, crypto |
| `internal/loginlink` | — |
| `internal/admin` | — |
| `cmd/*` | всё внутреннее (только wire-up) |

   Скелеты границ уже в репозитории — только типы и интерфейсы, без поведения; реализации
   появляются вместе с кодом своих компонентов. Таксономия сообщений и модель сущности
   наполнят типы поверх скелетов. Новый верхнеуровневый пакет или новое ребро — правка
   этого решения.

6. **Реестр горячих путей** (правило: бенчмарк появляется вместе с первым кодом пути):

| Горячий путь | Пакет-хозяин |
|---|---|
| Пакет-писатель (40-байтовый пакет, 0 аллокаций) | `protocol` |
| Криптографический блок (блоуфиш/XOR) | `crypto` |
| Пул буферов Get/Put по бакетам | `pkg/bufpool` |
| Геодата: canMove/пасфайнд | `geo` |
| Enqueue/изъятие ящика (MPSC, водяной знак) | `transport` |
| Отправка письма (lookup + enqueue) | `transport` |
| Join AoI / затравка / пересборка видимости | `replica` |
| Энкод/композиция кадра, криптоблок | `encode` |
| Тик региона / SoA-проход | `world` |

7. **Проверка правил:** цель `make checkdeps` (входит в `make check`) навязывает матрицу
   графу импортов; нарушение или пакет вне матрицы = красный билд. Дополнительно —
   ревью-чеклист и перечитывание карты на старте новых этапов.

## Альтернативы (отвергнуты)

- Карта как исследовательский документ без статуса решения — правила зависимостей не
  защищены от тихих изменений.
- Только секция в правилах для агентов — файл теряет форму инвариантов и разбухает.
- `pkg/` для всего служебного — без внешних потребителей различие не несёт.
- Каталог граничных интерфейсов «на каждый компонент» — против package-driven: интерфейсы
  маленькие, определяются потребителем, возвращаются конкретные типы.
- RPC-фреймворк внутри игрового процесса — противоречит однопроцессной модели (ящики в
  общей памяти).
- Сервисы как библиотеки регионов — пати на три региона требует межрегионального
  протокола согласования и выпадает из единого конвейера реплея.

## Последствия

- Очередь появления пакетов: крипта, протокол, пул буферов, headless-клиент → датапак и
  геодата → сетевые границы, транспорт, мир, сервисы → репликация и энкод → персистентность.
- Таксономия сообщений и модель сущности ложатся типами на эти пакеты.

## Цена решения

- Скелеты — «мёртвый» код до появления реализаций: цена контракта в коде (компилятор ловит
  расхождения рано и молча не даёт им разъехаться).
- Матрица ограничивает свободу: каждый новый пакет или ребро — правка этого решения
  (сознательно: структурные решения не принимаются молча).
- Скрипт проверки дублирует матрицу и требует синхронных правок.

## Проверка решения

- `make check` собирает скелеты (контракт компилируется) и гоняет проверку матрицы; ворота
  доказанно краснеют на нарушении (проверяется намеренным нарушением один раз).
- Каждый путь из реестра получает бенчмарк при рождении; регресс-бюджеты — когда появится
  базовая линия измерений под нагрузкой.
- Расхождение карта↔код = баг карты или кода; на старте новых этапов карта перечитывается.
