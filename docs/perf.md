# perf.md — правила производительности la2

Обязателен при работе над горячими путями, сетью, бенчмарками и тюнингом. Правила выведены
из измерений: переносим выводы, а не чужие числа — любое тюнинговое значение подтверждается
своим бенчмарком. Инварианты проекта выше этого гайда.

## 0. Дисциплина

- Оптимизация без baseline запрещена: сначала замер, потом изменение, потом «до/после».
- Профилировать только под нагрузкой: pprof (CPU; heap `inuse_space` для утечек; goroutine;
  contention); `go build -gcflags="-m"` (escape); `GODEBUG=schedtrace=1000,scheddetail=1`,
  `GODEBUG=netpoll=1`; бенчмарки на `b.Loop()`.
- Методология замеров: выделенное железо, governor=performance, турбо/C-states off, пиннинг
  ядер, 20 прогонов × 3 с, автоповтор при CV > 15%, пороги надёжности 5%/15%.
- GOGC/GOMEMLIMIT: не трогать без профиля; GOMEMLIMIT в контейнерах обязателен (ниже лимита
  OOM-killer'а); `GOGC=off` — только в паре с GOMEMLIMIT.

## 1. Аллокации (горячие пути: тик региона, энкод-стадия, крипта)

- Пул буферов (BytePool): Get → Reset → использование → **Put обязателен**; только
  короткоживущие объекты с простым reset.
- Преаллокация: размер известен — `make([]T, 0, n)`; заполняется целиком — `make([]T, n)` с
  записью по индексу; map — `make(map[K]V, n)`. При вариативном размере — не преаллоцировать.
- Без interface boxing на горячем пути: значения не класть в интерфейсы/`[]any` (детектор —
  `runtime.convT2E` в профиле); передавать указатель, не большую структуру.
- Escape: «вернуть указатель» ≠ heap — верить только `-gcflags="-m"`; воевать с escape по
  профилю, не на глаз.
- Поля структур — по убыванию размера (проверять fieldalignment); часто пишущиеся разными
  горутинами поля — в разных 64-байтных линиях кеша.
- Батчинг схлопывает фиксированную стоимость: пер-клиентский слэб кадра и криптоблок —
  правильная форма; аллокации падают на порядок, пакетная крипта — ~2× по времени.
- Слайс-вид вместо копии (клиентские пакеты — представления над буфером коннекта); копия
  обязательна, только когда владелец буфера переиспользует его раньше потребителя.

## 2. Статика: геодата/датапак (mmap)

- Читать прямо со страниц (`unix.Mmap`); `ReadAt` поверх mmap — не zero-copy, только уход
  от syscall: промежуточное вычитывание статике запрещено.
- Подслайс из пула, уходящий в долгоживущий объект, — копировать, иначе удерживает весь
  бакет.

## 3. Игровые соединения (gateway/net)

- Модель — горутина на соединение поверх netpoller. Враги: долгие CPU-bound горутины на
  коннект-пути, per-request аллокации, общий мьютекс между обработчиками.
- **TCP_NODELAY — обязательно** (игровой трафик — мелкие latency-критичные записи, Нагл
  убивает латентность).
- Read/write deadlines на каждом соединении + heartbeat: горутина чтения без deadline —
  утечка, умноженная на число соединений.
- Исходящий кадр флашится целиком (пер-клиентский FIFO); выбор «буферизовать/флашить» — по
  p99 своих бенчмарков.
- Backpressure: bounded-очередь + non-blocking send + `default` (дроп по классу или
  закрытие); данные для медленного клиента не копятся в памяти без лимита; TCP flow control —
  не замена (медленный читатель блокирует Write и весь fan-out).
- Подготовка ОС под 10k+: `ulimit -n`; sysctl `net.core.somaxconn`,
  `net.ipv4.ip_local_port_range`, `tcp_tw_reuse`, `tcp_fin_timeout`; keepalive idle 30–60 с,
  interval 10–15 с, probes 3–5 (`SetKeepAlivePeriod` управляет только idle); SO_RCVBUF/
  SO_SNDBUF — по BDP = bandwidth × RTT, не чужие числа.
- Метрики по фазам соединения (dial / handshake / io / close); логи — только по аномалиям,
  с сэмплированием.

## 4. Конкурентность (в рамках инвариантов проекта)

- Воркер-пул — только для стейтлес-работы (энкод-стадия, стыки); размер ≈ ядра для CPU-bound;
  для состояния мира запрещён. Unbounded-спавн горутин запрещён.
- Атомики — тривиальные операции и CAS-флаги; задача сложнее — менять структуру (ящик,
  сообщение владельцу), не наращивать атомики.
- Публикация через atomic swap — только глубокая иммутабельность (defensive copy внутренних
  map/slice); большие редко меняемые таблицы — сегментированный COW (клонируется изменённый
  сегмент + атомарная подмена целиком).
- Инициализация «единожды» — `sync.Once`/`OnceValue(s)`; самодельный CAS — только по
  доказательству профиля.

## 5. Версии Go (проект на 1.27)

- Апгрейд версии Go = обязательный прогон бенч-набора до/после (реестр горячих путей).
- Релевантное из трекинга 1.24–1.27: Swiss maps (быстрее map); 1.26 — малые аллокации,
  `io.ReadAll` ~2×; 1.27 — GC быстрее на мелких объектах, `encoding/binary` +15–20%,
  **JSON-энкод −48–51%** — если JSON появится на горячем пути, уходить на
  `encoding/json/v2`.

## 6. Сервисные стыки (gRPC; не игровой путь)

- HTTP-клиенты стыков: body вычитывать до Close (иначе нет переиспользования соединения);
  кастомный Transport, лимит `MaxConnsPerHost`, короткие таймауты + ретраи с backoff;
  буферы 4–8 КБ.
