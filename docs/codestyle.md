# codestyle.md — правила Go-кода la2

Обязателен в каждом PR. Перечитывается перед написанием или правкой кода. Приоритет:
инварианты проекта выше этого гайда; гайд выше личных предпочтений.

## Принципы

1. **Package-driven design:** единица проектирования — пакет; карта компонентов = граф
   импортов; интерфейсы маленькие, на стороне потребителя; никаких enterprise-контрактов и
   DI-реестров; wire-up только в `cmd/`.
2. **TDD:** тест до кода, обязан краснеть; в PR виден тест-первый порядок.
3. **Бенчмарки на все горячие пути:** путь рождается вместе с `BenchmarkXxx` в том же пакете.
4. **Ошибки с контекстом:** на границе пакета — всегда `%w` + идентификаторы.
5. **Логирование — slog напрямую:** настройка один раз в `cmd/`, логгер не пробрасывается.
6. **Простота превыше умного кода:** абстракции — только аргументированные; guards, минимум
   вложенности.

## 1. Простота

- Простейший способ, достигающий цели. Умный код требует доказательств необходимости.
- Осознанная сложность — только с обоснованием в комментарии и тестом.
- Порядок средств: ядро языка → stdlib → внутренние пакеты → новая зависимость.

## 2. Абстракции

- Абстракция вводится только при: (а) ≥2 реальных реализаций сейчас; (б) штатный шов;
  (в) доказанное устранение дублирования. «Понадобится потом» — не аргумент.
- Интерфейсы: 1–2 метода, в пакете-потребителе, внутренние не экспортируются. Принимаем
  интерфейсы, возвращаем конкретные типы. Интерфейс «для моков» запрещён.
- Дженерики — только при реальной параметричности типов; не замена интерфейсам.

## 3. Вложенность

- Guard clause: отказное условие — в начале блока и сразу выход; основной путь — с
  минимальным отступом.
- `else` после ветки с выходом — не нужен.
- Сложное условие — в именованную булеву переменную, не разрыв `if` по строкам.
- Больше 2–3 уровней вложенности — рефакторить: выделить функцию, инвертировать условие,
  пометить выход (`break loop`).

## 4. Именование

- MixedCaps; акронимы целиком в одном регистре: `URL`, `ID`, `HTTP`, `appID`, `ServeHTTP`.
- Длина имени пропорциональна области видимости. Без кодирования типа (`users`, не
  `userSlice`) и без обрезания букв (`Sandbox`, не `Sbx`).
- Ресивер — 1–2 буквы, сокращение типа, одинаковое во всех методах; не `this`/`self`.
- Геттеры без `Get`: `Counts`; дорогое вычисление — `Compute`/`Fetch`.
- Константы — MixedCaps (без `MAX_X`/`kX`), имя по роли, не по значению.
- Пакет — короткое строчное слово; `util`/`common`/`misc`/`api`/`types` запрещены;
  идентификаторы не повторяют имя пакета (`ring.New`, не `ring.NewRing`).

## 5. Ошибки

- `error` — последнее возвращаемое значение; тип возврата — `error`, не конкретный.
- Через границу пакета — всегда `%w` + контекст-идентификаторы (`npcID`, файл:строка,
  опкод/офсет, `transferID`). Внутри пакета допустим `return err`.
- Строки ошибок: со строчной буквы, без точки в конце.
- Ошибка обрабатывается ровно один раз: вернуть, залогировать или посчитать — не комбинировать.
- Игнор ошибки через `_` запрещён; осознанный пропуск — только с комментарием.
- In-band ошибки (`-1`, `nil`, `""` как признак) запрещены: `(value, ok)` или `error`.
- Паника — только механизм надзора; `Must`-хелперы — только старт и тесты.

## 6. Логирование

- `slog.SetDefault` один раз в `cmd/` (формат/уровень из окружения); далее — пакетные вызовы
  со структурированными полями-идентификаторами.
- Логгер не пробрасывается полями/параметрами; библиотечные пакеты `SetDefault` не трогают.
- Горячие пути — `Debug` (за `slog.Enabled`) или метрики, не `Info`.
- Лог — наблюдаемость процесса, в детерминированную свёртку не входит.

## 7. Функции

- Синхронные по умолчанию: параллелизм добавляет вызывающий.
- Указатели ради «экономии байтов» (`*string`, `*int`) запрещены.
- Ресиверы: при сомнении — указатель; все методы одного типа — одного вида.
- `defer` — сразу после захвата ресурса.
- Именованные результаты — для ясности обязательств, не ради naked return.
- `context.Context` — первым параметром, в структурах не хранится; в тике мира контекста нет.

## 8. Пакеты

- Границы компонентов = границы пакетов; правила зависимостей проверяет граф импортов;
  сборка зависимостей (wire-up) — только в `cmd/`.
- Группы импортов: stdlib → сторонние → свои, между группами пустая строка.
- Dot-import — только тесты; blank-import — только `main`/тесты; переименование — только
  при коллизии.
- Экспорт минимален: не экспортировать «на всякий случай»; каждый экспорт — doc-комментарий.
- Циклы импортов и зависимости вверх запрещены.
- `var xs []T` (nil-слайс) предпочтительнее `xs := []T{}`; исключение — JSON-границы.

## 9. Конкурентность

- Горутина запускается только с известным способом завершения; время жизни очевидно из кода
  или задокументировано.
- Синхронизация — только разрешёнными проектом механизмами: ящик, atomic-свап снапшота,
  иммутабельная статика. Внутри региона мьютексов нет.
- Библиотечный API не запускает горутины молча; параллелизм выбирает вызывающий.

## 10. Тесты

- Тест до кода, красный обязателен (ошибка компиляции — тоже красный).
- Сообщение об ошибке теста: вход, got, want — `t.Errorf("Foo(%q) = %d; want %d", ...)`.
- Table-driven тесты; для нового пакета — пример использования (`Example...`).
- Горячий путь — с бенчмарком; аллокационно-чувствительные — проверка нуля аллокаций.

## 11. Механика

- `gofmt`/`goimports` без обсуждений; диф мимо gofmt — реджект.
- Комментарий объясняет «почему», не пересказывает «что». Doc-комментарий — полное
  предложение, начинается с имени, точка в конце.
- Мёртвый и закомментированный код не коммитится.
- Литералы составных типов — с именами полей.
- Нулевое значение типа проектируется полезным: `New` не обязателен для корректной работы.
