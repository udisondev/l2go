# r3 — Исполнение мира: модель тика, граница, пати

Фиксация дизайн-сессии 2026-09-08. Продолжение [r0.md](r0.md) (архитектура мира) и
[r2.md](r2.md) (дорожная карта): закрывает блокирующий вопрос №1 (модель тика — решение также в
[ADR-0002](../docs/adr/0002-model-tika.md)), детализирует поведение на границе регионов и
non-spatial события пати, вносит поправки к r0/r1 (паттерн r1: поздний файл уточняет ранний,
ранние не переписываются).

## TL;DR

- **Модель тика: общий метроном без барьера.** Диспетчер-метроном 10 Гц будит активные регионы
  non-blocking send'ом в cap-1 канал; исполнитель тика — своя горутина региона; «воркер-пул» —
  Go-шедулер. Опоздавший регион пропускает такт (коалесинг-дроп), а не копит догоняющую очередь.
- **Барьер убит:** консистентный кат мира на тике N не нужен ни одному потребителю, а клиент его
  и так не наблюдает (сеть). Кадр = max по регионам — глобальная точка синхронзации, с которой
  борется весь r0.
- **Граница:** бег/бой/кайт расписаны таймлайнами; хэндофф — freeze-at-mark ≤1–2 тика;
  наблюдатели ничего не видят (AoI с ключом по entity-ID); TCP-коннект не принадлежит региону.
- **Ghost = снапшот:** канонический механизм кросс-граничной видимости один — чтение снапшота
  соседа. Отдельные «ghost-реплики с пушем» не строятся (закрыт вопрос о дублировании из r2).
- **Пати — две трубы:** членство (редкое) — пати-актор; статусы HP/баффы (частое) — напрямую
  регион→регион по ID через директорию. Монотонность бесплатна из single-writer.
- **Поправки к r0:** Interlude ≠ C5 (C5 = Oath of Blood; Interlude — следующая, неофиц. C6);
  «потолок Mobius 3–5k» — оценка без источника, не факт.

## 1. Модель тика (= ADR-0002)

### Переменные решения

«Модель тика» — четыре независимые оси; спор в r0 шёл потому, что они были склеены:

1. **Исполнитель тика региона** — своя горутина или воркер из пула.
2. **Ожидание** — жёсткий барьер на кадр или никто никого не ждёт.
3. **Доставка тика** — центральный метроном или персональный таймер на регион.
4. **Семантика под отставанием** — копить пропущенные тики или коалесить (максимум один ждущий,
   остальные дропаются).

### Почему не пул воркеров + барьер (r0 «компромисс»)

1. Противоречит собственному r0: пул теряет халявный single-writer (надо гарантировать, что
   регион не исполняют два воркера); пинить регион к воркеру = «своя горутина» с лишним слоем.
2. Арифметика хвостов: кадр = max по сотням регионов с тяжёлохвостым шагом = худший из них,
   каждый кадр. Толпа на городском споте растянет кадр всем, включая пустой лес. Осада вынесена
   из барьера, а городской спот — нет.
3. У продукта барьера нет покупателя. Консистентный кат мира на тике N не нужен: knownlist
   (устаревание на тик — норма по r0), прицельные проверки (оптимистичны у атакующего, авторитет
   у владельца), AoE (валидация у владельцев), LOS (гео статична, позиции advisory), пати-окно
   (eventual), экономика (2PC, не кадры), расписания (wall-clock), персист (write-behind
   per-owner). Контрольный: даже с катом на сервере клиент его не наблюдает — сеть доставляет
   пакеты с разбросом в десятки мс, глобально одновременный мир не наблюдаем в принципе.

Из r0-компромисса выживает: осада/инстансы — отдельный диспетчер и бюджет. Умирает: пул и
барьер для основного мира.

### Почему не персональные тикеры на регион

Работоспособно и изолированно, но: нет глобального номера тика (логи/логические часы хуже
стыкуются); перегрузка утаивается — каждый регион тихо самособрасывается до 7 Гц, размазанный
коллапс без единой точки наблюдения; нет одного места для адаптивного троттлинга/стаггера.
Запасной вариант (если метроном покажет thundering herd — см. фальсификацию).

### Решение: метроном без барьера

**Метроном общий, но никто не ждёт опоздавших — опоздавший сам пропускает долю.**

Диспетчер — одна горутина, тикер 10 Гц, активный сет; на каждый такт N — non-blocking send в
cap-1 канал каждого активного региона; провалившийся send = дропнутый тик + бесплатная метрика
перегрузки per-region:

```go
const worldTickHz = 10                            // частота: тиков в секунду
const worldTickPeriod = time.Second / worldTickHz // период: 100ms

ticker := time.NewTicker(worldTickPeriod)
tick := uint64(0)
for range ticker.C {
    tick++
    for _, r := range active.Load() {
        select {
        case r.tickCh <- tick:   // разбудить регион тиком N
        default:                 // канал полон — регион ещё в прошлом тике
            r.dropped.Add(1)     // коалесинг: тик дропнут, очередь не копится
        }
    }
}
```

Регион — loop из скетча r0, дисциплинированный (drain-then-step, капы фаз из r1, ack):

```go
for {
    select {
    case msg := <-r.mailbox:
        r.handle(msg)              // будит спящий регион; ack хэндоффа — здесь
    case n := <-r.tick:
        now := time.Now()
        dt := now.Sub(r.lastTick)  // реальное dt: 100ms, 200ms после дропа тика
        r.lastTick = now
        r.drainMailbox(bounded)    // мейлбокс = входная очередь тика: сначала входы
        r.phaseA(dt)               // дёшево, все сущности (r1): интерполяция, бакеты
        r.phaseB(capped)           // дорого, с капом (r1): line-walk, A*; излишек — дальше
        r.publishSnapshot()        // atomic.Pointer.Store — единственная точка публикации
        r.doneTick.Store(n)        // ack без канала: атомарная запись, диспетчер НЕ ждёт
    }
}
```

Вотчдог — наблюдатель, не исполнитель: регион с `текущийТик − doneTick > k` подряд → лог, дамп
pprof, алерт. Паника внутри шага — `recover` на тик: деградирует регион, не мир; повторяющиеся —
заморозка региона + алерт.

### Гц и дисциплина dt

10 Гц — конфигурационная константа (период 100 мс = `time.Second / worldTickHz`), не метрика
мониторинга. `time.Ticker` (не sleep-цикл): привязан к стене времени, не дрейфует от долгой
обработки, канал ёмкости 1 сам дропает такты для медленного получателя — наша семантика
коалесинга встроена. Фактическая частота региона (прирост doneTick/с) — вот это уже метрика.

**Внутри тика запрещено предполагать dt = 100 мс**: дропнутый тик даёт dt = 200 мс, поэтому фаза
A принимает dt параметром по монотонным часам (`time.Now()` в Go несёт монотонное чтение).
Захардкоженный dt — классическая ошибка игровых лупов: после дропа тика анти-чит начнёт ловить
своих. Обоснование числа: снапшот соседа устаревает на 0–100 мс — невидимо на фоне сетевого
лага 50–150 мс; скорости атак L2 — сотни мс; выше 10 Гц растёт фиксированная плата за тик без
выигрыша в наблюдаемости. Tuning-число, фаза 4 (боты).

Числа здравого смысла: ~500 активных регионов × ~1 мс среднего шага ≈ 0.5 с CPU на кадр ≈ 5
занятых ядер из 32–64 — с запасом до батчинга фазы A.

### Деградация под нагрузкой и обратимость

Худший случай (толпа в городе): барьер → лаг всем; метроном → отстаёт только регион, его
снапшоты чуть старее, вотчдог светит лампочкой, регион режется надвое. Плюс одна ручка
осознанной деградации: перегрелось — диспетчер переводит мир на 5 Гц целиком.

Обратимость: ack'и (`doneTick`) у диспетчера уже есть → debug-барьер («ждать все ack'и N») —
~20 строк за флагом; нужен для dev-проверок инвариантов на согласованном кате (ант-дюп тесты).
Обратное направление (пул+барьер → per-region) — переделка исполняющей модели. Выбрана сторона
с дешёвой ошибкой.

### Фальсификация (проверка ботами, фаза 4)

1. Спайки шедулер-латентности на границе кадра от толпы проснувшихся разом → лечится бакетным
   стаггером (активный сет режется на 10 корзин с шагом 10 мс) или откатом на персональные
   тикеры.
2. Найдётся фича, требующая консистентного ката → почти наверняка off-loop контент (инстанс/
   скриптованный рейд) со своим катом, либо debug-барьер.
3. Дроп-метрика систематически горячая при зелёных бенчмарках → ошиблись в бюджете шага.

### Цены (честно)

Глобального «тик N» для отладки не существует — реплей/дебаг через per-owner трейсы с корреляцией
по id сообщений; backpressure кадра не автоматический — его заменяют капы (фаза B,
drain-mailbox) + вотчдог, и это код, который надо не забывать писать; маленький плумбинг
диспетчера.

## 2. Модель исполнения

Каждый регион сам обрабатывает свои события; в основном мире нет прикладного воркер-пула.

| Роль | Чем является |
|---|---|
| Метроном | 1 горутина-диспетчер |
| Исполнитель региона | своя горутина региона (мейлбокс + тик) |
| «Воркер-пул» | планировщик Go (неявный, рантаймовый) |
| «Воркеры» | потоки ОС под управлением Go-шедулера |

500 проснувшихся регионов шедулер раскидывает по ядрам сам (work-stealing, M:N). Прикладной пул
— ловушка: следить «регион не исполняют два воркера» пришлось бы нам; пиннинг региона к воркеру
= своя горутина с лишним плумбингом; иллюзия контроля CPU-бюджета (бюджет защищают капы +
коалесинг + вотчдог).

**Граница законности пула:** допустим для стейтлес-работы (крипто/сериализация пакетов,
стартовая предобработка geodata, отчёты валидации — хоть errgroup с пулом); запрещён для
состояния мира — только горутина региона-владельца, без исключений.

## 3. Поведение на границе регионов

> **Superseded (2026-09-09, v10):** порядок хэндоффа в сценарии 1 и механика страгглеров/
> FIFO в сценарии 3 (epoch/seq/drain-варианты из «Остаточных вопросов» п.1) заменены решением
> [ADR-0003](../docs/adr/0003-poryadok-soobscheniy-pri-khandoffe.md) — потоковой моделью:
> личный ящик сущности с вечным адресом, черновик-владение с флипом после install-ack,
> курсор ящика едет в чемодане, слуги — слоты состояния хозяина. Принципы разделения
> видимости/владения (сценарии 2–3) остаются в силе.

Два несущих факта: **видимость отделена от владения** (видеть — через снапшоты соседа, мутировать
— только владелец) и **адресация по стабильному ID через директорию** (`id → регион-владелец`).

**Решение по ghost:** канонический механизм видимости — чтение снапшота соседа (lock-free,
`atomic.Pointer.Load`). Отдельные ghost-реплики с пушем не строятся — это дублирование второго
механизма для той же задачи (закрыт вопрос дублирования из r2 §Открытые вопросы).

### Сценарий 1: бег через границу

Геометрическая граница обложена липкой зоной (гистерезис): владение переключается только при
заходе в соседа с запасом — иначе бег вдоль линии = хэндофф каждый тик.

```
tick N    (RA):  P пересёк порог с запасом → P.migrating = true (входящие буферить)
                сериализовать P (in-process: копия структуры, боевое состояние в пейлоаде)
                send(RB.mailbox, Adopt{P, state}); P заморожен со стороны RA
tick N+1  (RB):  install P → симулируется RB → снапшот опубликован
                директория: flip P: RA → RB          // точка линеаризации
tick N+2  (RA):  ack → grace-forwarding сообщений по старой директории → таймер → forget
```

- Наблюдатели не видят ничего: knownlist = объединение «свои + снапшоты соседей» с ключом по
  entity-ID; ID переживает хэндофф → меняется источник данных, не видимость. Требование к AoI:
  дедупликация по ID (уйдёт в ADR-0004).
- Сам P не видит ничего: его knownlist собирает RA до флипа, RB после — та же дедупликация.
- TCP-коннект не принадлежит региону: пакеты адресуются по ID → директория → владелец → коннект.
  Хэндофф — внутреннее дело мира.
- Заморозка ≤1–2 тика (100–200 мс) маскируется клиентским предсказанием; нагнанный отрезок
  поглощает бакет скорости (CAP 1–2 с хода, r1).

### Сценарий 2: бой через границу

```
tick N    (RA):  таймер удара A → range-чек по снапшоту RB (advisory ≤1 тик) + LOS (глобальная
                geo, локально) → оффенс-половина (статы A рядом)
                send(RB.mailbox, ApplyDamage{to: B, swing})   // fire-and-forget
tick N+1  (RB):  валидация по текущей B (жива/в радиусе+толеранс/не телепортнулась) →
                дефенс-половина → HP −= dmg → бродкаст HP → при смерти KillCredit → RA
```

Урон аддитивен — eventual, без транзакций (2PC только для предметов). Обратный поток
симметричен и параллелен: чистый обмен сообщениями → дедлок невозможен по построению. Стейл-
снапшот лечится валидацией на применении (выбегание = «взмах без урона», как в живом L2; заодно
закрывает эксплойты). AoE через границу: список целей из своих + снапшота соседа (advisory),
`ApplyDamage` каждому владельцу, каждый валидирует. Доплата за границу — один хоп ≈ 50–150 мс
к применению — неощутимо против скоростей атак в сотни мс.

### Сценарий 3: кайт через границу (горячий путь PvP)

B под атакой убегает RA→RB, A догоняет. Хэндофф B несёт боевое состояние (цель, флаги, таймеры
атак, баффы с остатками, аггро-таблицу для моба). Опасное место — удар в полёте; три случая
сходятся в одну точку:

- директория старая, B в `migrating` → RA буферизует и доигрывает после флипа;
- директория новая → доставлено в RB напрямую;
- отправитель прочитал директорию за миг до флипа → grace-forwarding в RA.

Каждый удар существует в одном экземпляре и применяется ровно один раз текущим единственным
владельцем. **Порядок** сообщений в окне флипа — предмет ADR-0003 (seq-numbers per entity /
drain-before-flip / epoch в директории). Дальше — сценарий 2, затем хэндофф A тем же
протоколом; мигрируют хоть оба одновременно (маршрутизация через директорию + двусторонний
forwarding сходятся). Дрожание вдоль линии гасит гистерезис; видимость/атакуемость не рвутся —
они через снапшоты и от владения не зависят.

### Восприятие игрока

| Событие | Восприятие |
|---|---|
| Пересечение границы | ничего |
| Своя симуляция в окне хэндоффа | ≤100–200 мс, замаскировано предсказанием |
| Наблюдатели | ничего: ID постоянен, источник данных меняется под капотом |
| Бой через границу | урон на ~50–150 мс позже; выбегание = «взмах без урона» |

## 4. Пати и non-spatial события

> **Упрощено в ADR-0003 v10 (2026-09-09):** «частая труба» статусов больше не нужна как
> отдельный механизм — `MemberStatus` падает слепым push'ем в **личный ящик** игрока-получателя,
> а его регион-читатель по классу письма кладёт в исходящий поток (UI). Редкая труба
> (членство — пати-актор) без изменений. Ниже — исторический разбор двух труб.

Вопрос «сопартиец в моём регионе, но вне knownlist — как я вижу, что его бьют» ломает инстинкт
«видеть = knownlist»: пати-окно — **UI-подписка по partyID**, не мировая видимость. Слои r0
разводят это сами.

Владение: HP/MP/CP, баффы, флаги члена — его состояние → регион-владелец (single-writer);
состав пати — пати-актор (non-spatial, шардинг по partyID); пакеты получателю — регион
получателя.

**Две трубы:**

- Редкая (членство): пати-актор мутирует состав → рассылает реплику [id1..id9] регионам-владельцам → те хранят её в состоянии своих сущностей. После этого центру в частой трубе места нет.
- Частая (статусы): регион-владелец B применил урон → смотрит partyID и список членов в
  состоянии B → для каждого M: `directory.lookup(M)` → `send(owner(M).mailbox, MemberStatus{B, hp, mp, cp})` → регион M компонует пакет пати-окна → коннект M. Член в том же регионе — локально тем же тиком; в инстансе — тот же маршрут (инстанс = просто другой владелец в директории).

Свойства: **монотонность бесплатна** — все изменения HP одного члена исходят из одного региона-
владельца → per-source FIFO без интерливинга; через хэндофф порядок сохраняет гарантия ADR-0003.
**Eventual достаточен** — пати-окно advisory, авторитет у владельца. **Нет горячего центра** —
пати-актор не реле́ит частые события (иначе бутылочное горлышко в бою девятки). «Под атакой»
клиент выводит сам из HP/PvP-флага; баффы — та же труба (клиентский рендер — вопрос пакета,
Interlude рисует их при таргете).

Морщины на будущее: троттлинг частой трубы (порог дельты HP/MP + минимальный интервал на члена —
иначе каждый тик регена девяти членов = спам); XP/лут — та же маршрутизация, но гарантии строже:
доля XP — мутация состояния члена (сообщение его владельцу), распределение лута — территория
фазы 5 (предметы, 2PC).

## 5. Поправки к r0/r1

- **Interlude ≠ C5.** C5 = Oath of Blood (сент. 2006); Interlude — 2007, следующая за C5,
  неофициально C6, пограничье эр Chaotic Chronicle/Chaotic Throne. Косметика, на архитектуру
  не влияет.
- **«Потолок Mobius ~3–5k»** — оценка без источника; форумы скорее «L2J тянет 5000+, узкое
  место — клиентский FPS». Ориентир для дизайна, не факт.
- Противоречие тик-секций r0 (воркер-пул+барьер vs goroutine-per-region) закрыто — ADR-0002.
- Ghost-реплики и снапшоты унифицированы: снапшот — единственный механизм видимости (§3).

## 6. Мико-ручки (дефолты выбраны, тюнинг — фаза 4)

- Частота основного мира: **10 Гц**; осадный/олимпийский диспетчеры — свои константы.
- Рассылка тика всем разом; **бакетный стаггер** — ручка при фальсификаторе №1.
- Пробуждение спящего региона — по сообщению в мейлбокс, с немедленным первым тиком (клиент в
  этот момент грузится, 100 мс невидимы).
- Политика паники региона: recover → тик считается проваленным → повторные → заморозка + алерт.
- Freeze-at-mark в хэндоффе (простота, окно ≤1–2 тика); warm-handover (симулировать до ack,
  слать финальную дельту) — оптимизация на потом, не менять семантику владения.
