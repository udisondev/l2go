# AGENTS.md — правила для агентных сессий

Этот файл читается первым в каждой сессии. Нарушение инвариантов = реджект. Источник теории —
`research/` (r0 — архитектура мира, r1 — geodata/движение, r2 — дорожная карта, r3 — исполнение
мира, r4 — разбор референсов владельца interlude/la2go), решений — `docs/adr/` (процесс:
`docs/adr/README.md`), планов и прогресса — `план/`.

## Инварианты (не обсуждуются в PR, меняют только новым ADR)

1. **Single-writer:** мутация сущности — только в горутине региона-владельца. Никаких записей в
   сущность из других горутин, «на минутку», через указатель.
2. **Кросс-региональное воздействие — сообщением владельцу** (action-to-owner), не прямым
   доступом. Валидация — на применении у владельца.
3. **Внутри региона мьютексов нет.** Допустимая синхронизация: мейлбокс, atomic-свап снапшота,
   глобальная иммутабельная статика (geodata/датапак).
4. **Двойного владельца сущности не бывает ни на тик.** Хэндофф — по ADR-0003: у сущности личный
   ящик с вечным адресом; читатель ящика — ровно один подтверждённый владелец (или ноль в окне
   переезда); передача = чемодан {состояние (единственный указатель), курсор, недообработанная
   пачка, transfer-журнал, слуги} через черновик → install-ack → флип owner; черновик пассивен
   (не читает ящик, не эмитит эффектов, не персистит, не публикуется). Эпохи/seq/
   перенаправления в транспорте отсутствуют как класс.
5. **Передача ресурсов (предметы/деньги) — только reserve→commit/abort.** Fire-and-forget для
   предметов запрещён (дюп).
6. **Геодата и датапак — read-only после загрузки**, off-heap/mmap.
7. **Из ADR-0002, уточнено ADR-0003 (D1):** исполнитель тика региона — его горутина; прикладной
   воркер-пул для состояния мира запрещён (пул допустим только для стейтлес-работы); `dt` =
   (количество тиков с прошлого шага) × период метронома — по счётчику тиков, а не по настенным
   часам (настенные часы — только в шлюзе входа); хардкод «100 мс» запрещён.
8. **Из ADR-0003 — транспорт (И1–И12):** адрес сущности вечен, ID не переиспользуются, смерть =
   маркер; письмо — ровно один push и одно изъятие; порядок = FIFO ящика; отправка — только
   слепым push через транспорт (внутрирегиональные события — тоже письма); слуга не имеет ящика
   (адресация `(ownerID, slot)`); никакого ожидания в конвейере (лок = флаг-состояние + буфер);
   конкуренция за переезд — один победитель.
9. **Из ADR-0003 — детерминизм (D1–D6):** RNG региона сеется от (regionID, tick); обход
   сущностей — по сортированному слайсу id; чтение чужого снапшота в игровой логике — только
   через advisory-API модуля репликации с логированием в порцию (прямой дереференс запрещён);
   снапшоты вне advisory — строго репликация к клиенту; реплей-харнесс — с фазы 3.

## Референсы и лицензии (ADR-0001)

- Код проекта — **GPLv3**.
- **Разрешено** открывать исходники L2J/aCis/Mobius (GPL) и портировать семантику: формулы,
  структуры пакетов, поведение. Значимый порт снабжается источником в комментарии или PR
  (например: `// aCis GeoEngine.canMove`).
- **Переводится семантика, не текст** — код читается, понимается и пишется в идиоматах Go.
- **Запрещено коммитить NCsoft-derived данные**: датапак, geodata, файлы клиента. Исключение —
  байтовые фикстуры пакетов для golden-тестов протокола.

## Структура кода

- `cmd/` — точки входа; `internal/` — доменный и служебный код; `pkg/` — переиспользуемые
  библиотеки.
- Зависимости направлены вниз: базовые пакеты не импортируют мир; `world` — вершина. Карта
  компонентов и матрица зависимостей — [ADR-0005](docs/adr/0005-karta-komponentov.md)
  (проверяется `make checkdeps`, входит в `make check`); новые верхнеуровневые пакеты —
  только правкой ADR-0005. `internal/` — доменное и служебное; `pkg/` — переиспользуемые
  библиотеки по критерию ADR-0005.
- Пустых директорий-заготовок не заводим: пакет рождается вместе с первым кодом и тестом.
- **Перед написанием или правкой кода — перечитать [docs/codestyle.md](docs/codestyle.md)**
  (обязательный гайд: простота превыше умного кода, аргументированные абстракции, guard
  clauses, именование, оборачивание ошибок с контекстом, slog напрямую, TDD, бенчмарки на
  горячих путях; выжимка официальных гайдов Go + принципы владельца).

## Документация

- **Никаких отсылок в документации.** Гайды, тексты ADR и doc-комментарии кода — краткие и
  самодостаточные: без ссылок и указаний на файлы, фазы, параграфы и другие документы, без
  излишней детализации; текст исполняется без чтения чего-либо ещё.
- Навигация (AGENTS.md, план/, каталог ADR) — указатели по своей природе; на неё запрет не
  распространяется. Атрибуция портированного кода источником — обязательна (лицензионная
  позиция), это не отсылка-указание, а происхождение.

## Тесты и ворота

- Логика без теста не мержится. Новые пакеты протокола — с golden-тестами (фаза 1+).
- Горячий путь рождается с бенчмарком (принцип 3 из P0.9); при работе над горячими путями,
  сетью, бенчмарками и тюнингом — обязателен [docs/perf.md](docs/perf.md) (выжимка
  goperf.dev: baseline до оптимизации, аллокации/пулы, netpoller/TCP, GC/версии Go).
- Ворота: `make check` = build + lint (vet, staticcheck, gofmt) + checkdeps + test -race. В CI
  обязательны.
- Локальные нюансы этой машины: `make` и gcc могут отсутствовать → проверять покомпонентно
  (`go vet ./...`, `go build ./...`, `go test ./...`, `go run honnef.co/go/tools/cmd/staticcheck@v0.8.1 ./...`);
  `-race` требует gcc (CGO) — если недоступен, гоняет CI, но это надо сказать в PR.
- staticcheck пиннут версией модуля (v0.8.1): старые релизы не читают export data новых Go.

## PR-чеклист (для агента-автора)

1. Ссылка на релевантный ADR — или явное «ADR не нужен, потому что …».
2. `make check` зелёный локально (или покомпонентно с оговоркой).
3. Слайс тонкий: одна задача из `план/pN.md`, не «заодно ещё».
4. Инварианты выше перечитаны, нарушение — нет.
5. Гайд стиля [docs/codestyle.md](docs/codestyle.md) перечитан и соблюдён (простота,
   абстракции с аргументом, guards, `%w`-оборачивание, slog напрямую).
6. Прогресс зафиксирован: запись в `план/прогресс.md`, статус задачи в `план/pN.md` обновлён.

## Ревью

Второй агент (или человек) проверяет PR против этого файла и релевантных ADR. Статусы задач в
планах переводит исполнившая сессия: ⬜ → 🔄 → 👀 (нужно человеку) → ✅.
