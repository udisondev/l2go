## Детальный план (S0, рев. 2 — после S2/S3/S4)

### Факты кодовой базы (собраны чтением, не по памяти)

- `data.Load(fsys fs.FS) (*Static, *Report, error)`; отчёт несёт `Manifest [32]byte` (SHA-256
  потреблённых входов, le64-фрейминг путей). `Static.Dump() string` — канонический дамп всех
  категорий; комментарий в коде прямо называет его формой сверки эквивалентности артефакта.
- `geo.LoadDir(dir) (*Map, *Report, error)`; гео-отчёт несёт свой `Manifest` (тот же фрейминг);
  `geo.DecodeRegion(rx, ry int, data []byte) (*Region, error)` строит регион из произвольного
  слайса байтов (валидация + индексы за один проход, байты не копируются); `Region.data` —
  исходные байты файла целиком; поля `Map`/`Region` приватны (rx, ry, data без акцессоров);
  владение маппингами — до конца процесса (контракт doc). Отображение файла — непубличная
  `mapFile` с потолком `maxRegionBytes = 1<<30` (потолок файла региона, format.go:23–25, 74).
- Типы записей data имеют непубличные поля (raw-bag `set`, таблицы/overrides/raw скиллов) —
  контракт иммутабельности (вложенные слайсы/мапы только чтение) держится именно на них.
  `readRawNode` (skill.go:537, 551) рекурсивен без потолка глубины.
- `cmd/l2data`: `check <корень>` и `geo <каталог>`, exit 0/1/2, флагов нет.
- Синтетика: `internal/data/testdata/synth/` (items/npcs/skills/spawns/zones, включая
  отключённый файл), `internal/geo/testdata/golden_flat.l2j`, `golden_ml.l2j` (наши байты;
  имена НЕ матчатся под канонический паттерн LoadDir `NN_NN.l2j` — тестовому гео-каталогу
  нужны канонические имена, заводится хелпером).
- Env реальных данных: `L2GO_REAL_DATA` (bench_test.go); env реальной геодаты нет — вводим
  `L2GO_REAL_GEO`. `/dist/` в .gitignore уже есть; `go:embed` в репо не используется;
  зависимостей ноль (go.sum пуст).
- CI: fuzz-смоук 12 целей по 10с (4 protocol + 2 crypto + 4 data + 2 geo); Makefile-списки
  fuzz-целей содержат только часть (нет FuzzLoadZones/FuzzLoadSkills — чужие хвосты P2.5/P2.6,
  в этой задаче НЕ правятся). Бенч-цели в Makefile нет. Guard-механизм репо — прогулка
  рабочего дерева по расширению (guard_test.go, filesByExt/WalkDir).

### Решение 1 — раскладка: контейнер и кодеки по доменам

Новый пакет `internal/artifact` — формат-контейнер и точки входа (`Build`, `Encode`, `Decode`,
`LoadFile`, embed-вариант за тегом). Посекционные кодеки живут у владельцев типов:

- `internal/data`: `EncodeStatic(*Static) []byte` / `DecodeStatic([]byte) (*Static, error)`
  (доступ к приватным полям у владельца, кодек рядом с типами).
- `internal/geo`: (а) сборка `NewMapFromRegions(regions []*Region) (*Map, error)` — проверка
  занятых слотов, публичного мутатора НЕ вводим (нулевое значение Map валидно, New не нужен;
  контракт «не мутируется после первой публикации» сохранён буквом API — сборка целиком до
  публикации); (б) чтение для энкодера `(*Map).EachRegion(func(rx, ry int, raw []byte) bool)`
  — исходные байты и координаты; (в) нейтральное отображение файла `MapFile(path) ([]byte,
  func() error, error)` — БЕЗ потолка размера и без гео-префиксов ошибок; `LoadDir` проверяет
  `maxRegionBytes` до вызова сам (поведение oversized-ошибок не меняется), артефакт guarding
  заголовка делает против `len` маппинга. `LoadDir` сохраняет свои предпроверки (range/dup по
  имени файла) ДО отображения и собирает `Map` через `NewMapFromRegions` — один путь сборки,
  отклоняемый дубликат не читается вовсе.
- Логика build (сравнение с существующим артефактом, атомарная запись, тайминги) — в
  `internal/artifact.Build`; `cmd/l2data` — только wire-up: печать, коды выхода.

Матрица ADR-0005: строка `internal/artifact | data, geo` (новая, правкой решения), ребро
`cmd/l2data → internal/artifact`; checkdeps синхронно, red-proof локальным прогоном.

Отвергнуто: кодеки категорий внутри `internal/artifact` (ломает инкапсуляцию приватных полей);
gob напрямую по типам data (решение 12); собственная копия dual-platform mmap в artifact
(дублирование платформенного кода) и микропакет ради одной функции (лишняя строка матрицы).

### Решение 2 — формат артефакта

Один плоский файл, little-endian, детерминированный:

```
magic "L2A\x01" (4Б)
version u32 = 1 (несовпадение = «артефакт устарел, пересобери l2data build»)
dataManifest [32]Б   geoManifest [32]Б        — манифесты входов из отчётов сборки
dataLen u64, geoLen u64
payloadSHA [32]Б     — SHA-256 заголовка ДО поля SHA + ВСЕГО payload (meta + data + geo):
                     однобитовая порча любого байта файла (включая манифесты) = ошибка загрузки
--- payload ---
meta: счётчики сборки (files/items/npcs/spawns/territories/zones/skills/skillLevels,
      regions) — потребитель: обязательная сверка «декодировано == заявлено» и печать
      `l2data load` (второй источник чисел не заводится — Len-семантику P2.2 удалили)
data-секция: EncodeStatic
geo-секция: индекс регионов {count u32; per region: rx i32, ry i32, off u64, len u64} +
            конкатенация исходных байтов регионов как есть (без перекодирования)
```

Гварды заголовка — только вычитанием, без сложений: `off > geoLen || len > geoLen-off`;
`dataLen+len(header)+…` никогда не вычисляется как сумма; приведение u64→int только после
проверки ≤ maxInt. Целостность: один стриминговый SHA-256 по payload, проверяется до
декодирования. Структурная валидация geo-байтов происходит сама при `DecodeRegion` (один
проход = валидация), как и в пути парсинга. wallclock-полей нет — сборка байт-детерминирована.

Предусловие файла артефакта = предусловие гео (не усекать и не править по месту при живом
отображении — SIGBUS/AV). SHA — анти-порча при хранении/передаче, НЕ защита от активного
писателя в окне между проверкой и использованием страниц. Пересборка build
(CreateTemp+rename поверх существующего) при живом LoadFile-отображении безопасна: процесс
продолжает видеть старые байты — машинный тест (Windows обязательна). Цена verify принята
в бюджет: ~0,4–1,0 с на ~1 ГБ (2–2,5 ГБ/с); более дешёвый crc32-Castagnoli отвергнут —
единый примитив с манифестами, риск-модель владельца-сборщика не требует 10 ГБ/с.

### Решение 3 — детерминизм кодирования

Обход всех map — по отсортированным ключам; строки — u32-длина + байты; слайсы — u32-счётчик;
никаких зависимостей от порядка итерации runtime. Тест: две сборки над одним составом —
байт-в-байт (в процессе и вторым процессом через cmd). Идентификация версии данных для реплея
(D1–D6) — пара манифестов из заголовка.

### Решение 4 — декодирование = валидация, ошибки с местом, не паника

- Ёмкость НЕ выделяется вперёд больше `min(счётчик, остаток_секции / минимальный_размер_
  записи)`; длина строки проверяется против остатка буфера ДО создания string — злой счётчик
  u32max при обрыве даёт ошибку range, не OOM.
- Точное потребление секции — инвариант декодера: непотреблённый хвост = ошибка (прецедент
  CodeTail гео); одному составу соответствует ровно один валидный файл.
- Дубликаты — ошибка dup: ID категорий (items/npcs/territories/skills), занятые слоты
  регионов. Сверка «фактически декодировано == meta» обязательна (ворота против тихих потерь).
- Сырые деревья скиллов: симметричный потолок глубины 64 — вводится И в парсер
  (`readRawNode`: ошибка с местом; сейчас рекурсия без лимита), И равный бюджет в декодере
  (явный стек, не неограниченная рекурсия). Цикл «исходник → артефакт → Load» не размыкается:
  парс-зелёное всегда декодируется.
- Энчант-маршруты скиллов в декодере: route вне 1..8 = ошибка, повтор маршрута = ошибка
  (парс это гарантирует — map-ключ; декодер симметричен).
- Правило ёмкостей поимённо требует «минимальный размер записи ≥ 1» для каждой коллекции
  (у записи хотя бы u32-префикс) — гвард не вырождается на коллекциях опциональных полей.
- Золотая байтовая фиксация формата: маленький синтетический артефакт литералом в `_test.go`
  (трекнутый .l2a запрещён guard'ом — литерал обходит законно; байты наши, не NCsoft-derived):
  `Decode(golden) == ожидание` и `Encode(synth) == golden` побайтово — правка лэйаута кодека
  без правки фикстуры/бампа version роняет тест немедленно.
- Ограничители длины на каждый счётчик/строку (прецедент maxFile), границы против остатка
  на каждом чтении; ошибки вида `{секция, офсет, код}` — коды
  `trunc/range/magic/version/checksum/dup/tail`.
- Таблица злых входов + Fuzz-цель `FuzzArtifactDecode` в CI-смоук (13-я; строки таблицы
  становятся f.Add-семенами; цель бьёт в фазу декода поверх payload — SHA пересчитывается
  после мутации, иначе мутации умирают на чексамме и гварды не получают покрытия): обрыв,
  счётчик u32max, строка u32max, wrap-офсеты u64
  (0xFFFFFFFFFFFFFFFF + len=0x1F), дубли ID/регионов/маршрутов, мусорный хвост, плохая SHA,
  плохая версия, плохая магия, глубина >64, регион-индекс вне 0..31, route=0/9.

### Решение 5 — Load без копирования в кучу

- Внешний файл: `LoadFile(path)` — `geo.MapFile` (экспорт, см. решение 1), владение
  отображением до конца процесса — тот же контракт. Проверка заголовка+SHA → `DecodeStatic`
  (кучи требуют только типизированные структуры — это и есть статика) → гео: для каждого
  региона индекса `DecodeRegion` над слайсом geo-секции (байты остаются поверх mmap) →
  `NewMapFromRegions`. Гео-лукапы — путь P2.3/P2.4 без изменений: 0 аллокаций переносится
  машинным тестом поверх артефактных байтов.
- embed: `internal/artifact/embedded.go` за тегом `//go:build embedded`:
  `//go:embed embedded/artifact.l2a` + `LoadEmbedded()` над глобальным слайсом rodata
  (экспериментально проверено: go:embed матчится и на gitignored-файл; сборка проходит).
  Каталог `internal/artifact/embedded/` — artifact.l2a в .gitignore, рядом README (коммитится):
  инструкция цепочки владельца. Подпакет не заводится — матрица не меняется.

### Решение 6 — команда build и политика пересбора

`l2data build <корень данных> [каталог геодаты] [-o артефакт]` (по умолчанию
`internal/artifact/embedded/artifact.l2a`): `data.Load` → ошибки = красный выход 1,
артефакт не тронут; `geo.LoadDir` (если задан; 0 регионов при заданном каталоге = красный,
как у `geo`) → `artifact.Build` → сравнение с существующим файлом: байт-идентичен —
«актуален», exit 0 без записи; иначе атомарная запись: `os.CreateTemp` в каталоге назначения
(тот же том — атомарность rename; имя непредсказуемо — симлинк-подмена tmp исключена) +
rename поверх существующего (работает и поверх живого mmap, решение 2). Печать: сводка обоих
отчётов (существующие принтеры), размеры секций, манифесты, времена фаз (parse/encode/write).
«Прозрачный пересбор» = цикл build: изменился один XML → манифест в заголовке меняется →
файл переписывается; рантаймный `LoadFile` источников не имеет — несовместимость версии/SHA
только явная ошибка с инструкцией пересборки (отклонение от буквы p2 «miss → пересбор» —
запись O2: пересбор живёт в build, у Load нет данных для сравнения).

### Решение 7 — команда load и числа КТ-3

`l2data load <артефакт>`: mmap → проверка → декодирование, печать meta (счётчики, манифесты,
размеры) и wall-clock фаз (verify/decode-data/decode-geo) — источник чисел КТ-3 для внешнего
файла. Роли разведены с бенчами: cmd = wall-clock фаз владельца; бенч = ns/op, B/op, allocs/op
по фазам (решение 13). embed-числа на полных данных — `BenchmarkLoadEmbeddedReal` за тегом
`embedded` (владелец кладёт полный артефакт в embedded/ и гоняет с тегом), синтетика embed — CI.

### Решение 8 — CI и Makefile

- CI-шаги: (1) `go build -tags embedded ./...` на чистом дереве — ожидаемый фолд, вывод
  грепается на «no matching files» (инверсия кода выхода зелёная и при чужой ошибке
  компиляции — ложно-зелёное окно); (2) сборка синтетического артефакта РЕАЛЬНОЙ командой:
  гео-каталог фабрикуется вне дерева (`cp internal/geo/testdata/golden_*.l2j $RUNNER_TEMP/
  geosynth/NN_NN.l2j`) и `go run ./cmd/l2data build internal/data/testdata/synth <гео-каталог>`
  — по умолчанию пишет в настоящий `internal/artifact/embedded/artifact.l2a` (проверяет и
  дефолт `-o`); (3) `go vet -tags embedded ./internal/artifact/` + `go test -tags embedded
  ./internal/artifact/` (бинарарь теста несёт статику с регионами, загрузка без внешних
  файлов). Порядок шагов 1→2 зафиксирован: шаг 1 строго до записи артефакта.
- Makefile: цель `embedded DATA=<корень> GEO=<каталог>` — ПЕРЕСБОРКА артефакта командой build
  (идемпотентна: байт-идентичен = «актуален», без записи — ручной зазор «забыл пересобрать»
  исчезает) + `go build -tags embedded -o bin/`; при незаданных DATA/GEO — внятная ошибка с
  инструкцией. fuzz-списки пополняются ТОЛЬКО `FuzzArtifactDecode` — выравнивание
  FuzzLoadZones/FuzzLoadSkills (хвосты P2.5/P2.6) отклонено как «заодно ещё» (F16).

### Решение 9 — эквивалентность, guard и тесты

- Эквивалентность «артефакт == парсинг» на синтетике полного состава (с гео): `Dump()` строкой
  + гео-пробы (перебор ячеек регионов обоих Map: байты идентичны, лукапы совпадают).
- Тестовый гео-каталог: хелпер пишет golden-байты под каноническими именами `NN_NN.l2j`
  в t.TempDir → LoadDir — CI-артефакт несёт регионы; гео-часть пути (индекс, DecodeRegion
  поверх payload, embed-гео, 0-аллок-лукапы) исполняется в CI, не вырождена.
- Красная сборка: подложенная битая ссылка в копии синтетики → build красный, файл артефакта
  не изменился (байт-сравнение).
- Манифест-цикл: правка одного XML → артефакт отличается; откат → снова идентичен.
- Злые входы декодера (таблица, решение 4) + fuzz; детерминизм; атомарная запись; rename
  поверх живого отображения (Windows).
- Guard репо: артефакт проверяется по git-ТРЕКНУТЫМ файлам (`git ls-files`), не прогулкой
  дерева: `.l2a` среди трекнутых = ошибка (whitelist пуст — `git add -f` ловится); прогулка
  дерева остаётся для фикстурных расширений (.xml/.l2j). Без git-чекаута (экспорт tarball) —
  ошибка, не скип. Дополнительно: трекнутый файл > 16 МиБ = ошибка (whitelist пуст) — закрывает
  случайный коммит embedded-бинараря.
- cmd-тесты процессом (прецедент main_test): build/load exit-коды и вывод.
- Резидентность: env-гейтуемый `TestArtifactResidentHeap` (GC + HeapAlloc после Load
  артефакта, методика TestRealResidentHeap) — гейт: резидентная статика ≤ 48 МБ либо
  зафиксированная дельта с аргументом; число в baseline.

### Решение 10 — строки и аллокации декодера

Декод-сессия держит словарь строк (прецедент keyDict загрузки): повторяющиеся имена
типов/ключей/значения словарей интернируются при декодировании — резидентная статика из
артефакта не хуже парсинга; фальсифицируется TestArtifactResidentHeap (решение 9). Форматных
string-таблиц не вводим (сложность без измеренной нужды; эволюция — по числам).

### Решение 11 — скоуп кодеков по категориям

Кодируются все категории P2.1–P2.6: items, npcs (с дроплистами/миньонами), territories,
spawns, zones, skills (defs: таблицы, set, overrides, raw-деревья, материализованные уровни).
Отчёт валидации в артефакт не входит (счётчики — meta, решение 2); Dump остаётся формой сверки.

### Решение 12 — выбор кодирования: собственный плоский формат (не gob)

gob не видит непубличные поля — потребовалось бы зеркало с экспортированными внутренностями:
дублирование каждой категории, рассинхрон при правке поля, ломка контракта иммутабельности;
gob вдобавок не гарантирует побайтовый детерминизм (порядок мап не специфицирован) против
решения 3. Выбор вынужден структурно — контрольный gob-бенчмарк убран: он не мог изменить
решение (измерение ради галочки). Отклонение от буквы p2 «выбор — бенчмарком в задаче» —
запись O1.

### Решение 13 — методика бенчмарков и baseline

- Сравнения разводятся, не смешиваются: (а) данные-к-данным — `BenchmarkArtifactDecodeReal`
  против `BenchmarkLoadReal` (641 мс / 437 МБ / 7,04 млн аллок — вход P2.6, та же машина);
  (б) whole-path `BenchmarkLoadFileReal`/`BenchmarkLoadEmbeddedReal` — отдельной таблицей с
  фазовым разрезом verify/decode-data/decode-geo (связка с печатью решения 7).
- Состав таймера фиксируется поимённо: LoadFileReal меряет Decode над однократно отображённым
