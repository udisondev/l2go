# Реестр находок P2.5- Задача: P2.5 Зоны (план/p2.md)
- Ревью-профиль: S2 — инвариантщик, доменщик, прагматик; S8 — + тестировщик
- Бюджеты: план 0/2 · рестарты 0/2 · ревью реализации 0/3
- Вход: явная команда владельца «пускай через харнес» (2026-09-13), после вопроса «2.4
  завершается, о чём у нас 2.5?» — запуск относится к P2.5.

## Детальный план (S0, рев. 2.3 — закрыты F1–F61; дельта 2.3: bowtie/коллинеарность, TaxZone, enabled-пустое, Scan-классы, гейт пустых узлов)

### Факты проработки

- Канон — Mobius Interlude 43ac8878, дочитаны: ZoneManager (parseDocument/load/getZoneByName),
  ZoneType.setParameter, ZoneRespawn.parseLoc, RespawnZone, ConditionZone,
  ZoneCuboid/ZoneNPoly/ZoneCylinder (формы), documentation.txt, MapRegionData
  (restart-регионы — потребитель race-point). aCis-зеркала зон в проекте нет; формы тривиальны,
  выборочная сверка не требуется. Числа ниже пересчитаны XML-парсером (grep-подсчёты
  ненадёжны — урок F3/F4).
- Формат: `zones/*.xml` плоско — 37 XML (897 269 байт) + documentation.txt (920 байт),
  1 файл `list enabled="false"` (tax.xml). Иерархия: `list enabled? → zone{type, shape,
  minZ, maxZ, name?, id?, rad?} → node X Y | stat name val | spawn X Y Z type? |
  race name point`. Других элементов и атрибутов в дистрибутиве нет.
- Состав: **2533 зоны во всех файлах / 2411 в активных** (tax.xml: 122 TaxZone — disabled);
  формы всех/активных: NPoly 2061/1939, Cuboid 461/461, Cylinder 11/11 (все в zone.xml,
  все rad>0, rad 750–1500); **28 типов в активных / 29 всех** (топ активных: ConditionZone
  1080, WaterZone 447, EffectZone 153, RespawnZone 145, PeaceZone 109, NoRestartZone 69…);
  minZ/maxZ присутствуют у всех; **minZ>maxZ: 29 всех / 28 активных** (clanhall_teleport 5,
  custom_no_store 5, no_bookmark 13, water 5, tax 1 — disabled); **minZ==maxZ: 2 активных**
  (bandit_stronghold_restart_territory_1, 24_14_water7); name у всех, **41 имя дублируется**
  (активные); id у 111 активных (2300 без id), **дублей id нет**; **33 stat-ключа в активных /
  34 всех**; spawn-точки: other 246 / chaotic 193 / banish 96 / challenger 14 / entrance 0
  (все 4 entrance дистрибутива закомментированы — grep-подсчёт ловит комментарии, XML-парсер
  нет) / **без type 113**; race-point 46 значений; координаты узлов до ±294912 (разности до
  ~590000). Распределение NPoly по числу узлов (все 2061): **4 узла — 1478 (72%)**, 5–8 —
  ещё ~450, хвост до 59 (максимум). Территории спавнов (3630): **4 узла — 1927 (53%),
  5 — 940, 6 — 483**, 3 узла — 4, хвост до 16.
- Словарь типов канона: **31 класс пакета entity/zone/type** (без NpcSpawnTerritory):
  29 регистрируются ZoneManager.load() + NoPvPZone и TaxZone (грузятся Class.forName,
  в load() отсутствуют). В данных активных — 28 из 31 (отсутствуют FlagPvPZone — в
  словаре load(), в данных нет; TaxZone — целиком в disabled tax.xml; один класс
  пакета type/ вне словаря — NpcSpawnTerritory, перехватывается раньше).
- Канонные семантики (порт с атрибуцией):
  - ZoneCuboid: ровно 2 узла; x/y/z нормализуются Math.min/max; contains =
    java.awt.Rectangle.contains (x∈[x1,x2), y∈[y1,y2) — полуоткрыто) && z1<=z<=z2.
  - ZoneNPoly: ≥3 узлов; z нормализуется; contains = java.awt.Polygon.contains (even-odd
    кроссинг: ребро засчитывается при строгом чередовании (y1>py)!=(y2>py), хит — когда
    точка строго левее точки пересечения ребра с горизонталью точки: px < x_int; целочисленный
    безделительный тест с согласованием знака (y2−y1)) && z-диапазон.
  - ZoneCylinder: ровно 1 узел + rad>0; contains = dx²+dy²<=rad² (граница включена) &&
    z1<=z<=z2 — **без нормализации z** (при minZ>maxZ зона пуста; в данных 0 случаев).
  - Арифметика: все промежуточные разности/квадраты/произведения — **int64** (координаты
    до ±294912: int32 переполняется при |Δ|>46341 — канон считает в double).
  - minZ>maxZ не ошибка: канон нормализует в конструкторах Cuboid/NPoly (порт Math.min/max,
    счётчик широты — прецедент MinOverMax P2.2).
  - Дубликаты: id — канон молча «overrides» (в данных дублей нет); name — не ключ вообще
    (getZoneByName — линейный поиск первой; 41 дубликат в активных).
  - Динамические id: канон генерит от 300000 для зон без id (2300 активных) — рантайм-артефакт,
    детерминированная статика не порождает; не переносим.
  - Unknown stat: канон логирует INFO и игнорирует; unknown type: warning + skip зоны;
    unknown shape: warning + skip зоны; spawn-элемент — только для типов-наследников
    ZoneRespawn (ResidenceTeleportZone, ResidenceZone, CastleZone, ClanHallZone,
    ResidenceHallTeleportZone, SiegableHallZone), race — только RespawnZone; вне их — молча
    игнор.
  - list enabled: отсутствие атрибута — файл грузится; значение ≠"true" (без учёта регистра) —
    файл пропускается молча (Boolean.parseBoolean).
  - race.point резолвится не в зоны, а в restart-регионы `mapregion/*.xml` (MapRegionData,
    _regions), при отсутствии — fallback дефолтного региона (не ошибка); **10 из 46 значений
    не имеют restart-региона в каноне** (kamaroka, crate01–03, cleft и др.); категория
    mapregion в фазе 2 не загружается.
  - Повтор stat-ключа: для affectedRace/affectedClassId канон аккумулирует список, прочие —
    присваивание; в данных повторов 0, affectedRace максимум 1 на зону.
- Вырожденность в реальном наборе: зоны — ноль случаев (нет несоответствия числа узлов,
  нет rad<=0, нет всех-узлов-в-точке у ≥2-узловых форм, нет коллинеарных); территории спавнов
  P2.2 (3630 + 17 banned) — ноль вырожденных, **8 с повтором соседних узлов** (кроссингу
  безвредны), minZ>maxZ и minZ==maxZ — ноль.
- Каркас проекта (P2.1/P2.2): loadFlatCategory (плоские категории), parseListFile,
  readFileCapped + манифест, linkRef-каркас (дроп→предмет, спавн/миньон/ignore→NPC,
  спавн→территория), raw-bag с интернированием ключей, Report-счётчики, Dump, synthetic
  testdata/synth. Territory P2.2 хранит геометрию как данные (Nodes/MinZ/MaxZ/Banned),
  принадлежность точки — поле P2.5.

### Решения

1. **Категория зон — плоская, в существующем каркасе.** `zones/` через loadFlatCategory
   (аналог предметов/NPC); `list enabled="false"` — файл пропущен + счётчик DisabledFiles
   (переиспользуется файловый счётчик каркаса; doc-комментарий расширяется до «файлы спавнов
   и зон»); **отсутствие enabled — файл грузится** (порт канона; отличие от спавнов P2.2,
   где отсутствие — ошибка: канон-асимметрия ZoneManager/SpawnData); **присутствующее
   значение вне {true,false}, включая пустое — ошибка CodeAttr** (молчаливая потеря
   невозможна; канон молча skip'ает по parseBoolean); корень ≠ list — ошибка каркаса.
   Чтение атрибута корня — в собственном файловом цикле категории (по образцу
   parseSpawnFile: Files++ только для разбираемых файлов — симметрия со спавнами, F55;
   parseListFile атрибуты корня не читает). Подкаталогов в дистрибутиве нет; появятся —
   SkippedDirs (без правки кода).
2. **Структура Zone (поля по потребителю; layout под горячий перебор).** Порядок полей —
   геометрия впереди (ShapeKind, MinZ/MaxZ, Rad, BBox, Nodes), затем строки и слайсы
   данных: при переборе `[]Zone` читаются только горячие линии кеша (perf.md §1).
   **ShapeKind byte** (ShapeCuboid/ShapeNPoly/ShapeCylinder/ShapeUnknown) — диспетчеризация
   Contains сравнением байта, без строк; Dump печатает канонические имена форм; исходная
   строка unknown-формы сохраняется в raw-bag под ключом zone.shape (ничего не теряется).
   Name (отсутствие **или name=""** — счётчик MissingZoneName, не ошибка: канон
   null/isEmpty), Type
   (строка; словарь 31 класс канона — см. факты; неизвестный — счётчик zone.type.*, не
   ошибка — решение 7 фазы; сравнение точное — регистронезависимость equalsIgnoreCase
   канона не переносится: значение в ином регистре предсказуемо идёт в счётчик),
   MinZ/MaxZ (как в файле; Contains нормализует), Nodes
   [][2]int32, Rad int32 (0 — нет), **ID int32 (тип ZoneID int32 по прецеденту ItemID/NpcID)
   + HasID** (явный id; неразборчивое или ≤0 значение — ошибка CodeNumber, зона не входит в
   статику; динамические не генерируем — детерминизм), Stats raw-bag (zone.stat.<name> — все,
   без интерпретации; дубли ключей — последний + счётчик DupKeys, как P2.1; списочная
   семантика affectedRace/affectedClassId канона не переносится — потребитель фаз 4+,
   потеря фиксируется реестром F19), SpawnPoints []ZoneSpawn{X,Y,Z int32, **Type** string}
   (Type — атрибут type файла, "" — без), RacePoints []ZoneRacePoint{Race,Point}. Элементы
   spawn/race читаются у всех зон без поведенческого гейта по типу: гейт канона —
   рантайм-поведение, статика состав файла не теряет (прецедент: P2.2 хранит и точку, и
   территорию при обеих).
3. **Ссылок новых нет.** race.point → restart-регион: целевой категории в фазе 2 нет
   (mapregion вне DoD фазы), канон сам fallback'ит; строка-данные без linkRef. Внутренних
   ссылок у зон нет (spawn/race — данные). Реестр ссылок не расширяется.
4. **Дубликаты: id — ошибка, name — нет.** Дубль id — CodeDupID (решение 7 фазы; канон
   «overrides», но в данных дублей нет — полный прогон не роняется). Дубликаты name
   допустимы (41 в активных; имя — не ключ: поиск канона по имени недетерминирован и не
   переносится). Доступ: Static.Zones() []Zone — слайс в порядке загрузки (файл
   лексикографически, позиция), только чтение; map по имени/типу не заводится (ключ
   неуникален, потребитель фазы 3).
5. **Point-in-zone — чистые функции, int64-арифметика, указательные ресиверы.**
   `func (zn *Zone) Contains(x, y, z int32) bool` и `func (t *Territory) Contains(x, y, z
   int32) bool` — порт семантики форм (атрибуция L2J_Mobius ZoneCuboid/ZoneNPoly/
   ZoneCylinder; граничная семантика java.awt); все промежуточные разности/квадраты/
   произведения — int64 (координаты до ±294912 переполняют int32 при |Δ|>46341).
   **Прекомпьют при загрузке для всех форм: BBox (MinX/MaxX/MinY/MaxY) и нормализованные
   ZLo/ZHi** — нормализация уходит с горячего пути, единый код-путей; raw MinZ/MaxZ
   остаются для Dump/счётчиков.
   - Cuboid: bbox-полуоткрыто [min,max) (совпадает с bbox NPoly — один предикат);
     z∈[ZLo,ZHi] включительно.
   - NPoly: **bbox-предфильтр — поведение-сохраняющая оптимизация канона** (AWT
     Polygon.contains открывается getBoundingBox().contains — полуоткрыто; промах O(1)
     вместо O(n) рёбер; граничные ожидания выводятся из AWT-семантики кроссинга, с которой
     предфильтр согласован, — не из bbox). Кроссинг even-odd: ребро засчитывается при
     строгом чередовании (y1>py)!=(y2>py), хит — точка строго левее пересечения ребра с
     горизонталью (px < x_int), целочисленный безделительный тест с согласованием знака
     (y2−y1); z как у Cuboid. **Кроссинг — одна общая функция для Zone и Territory**
     (npolyContains(nodes, bbox, x, y) + z-предикат): единственное место, где две
     структуры могли бы разъехаться граничной семантикой.
   - Cylinder: dx²+dy²<=rad² в int64 (граница включена); z без нормализации —
     **Cylinder использует raw MinZ/MaxZ** (канон; пустая зона при minZ>maxZ — счётчик
     MinZOverMaxZ фиксирует широту независимо от формы).
   - Неизвестная форма: Contains → false.
   - Territory: NPoly-семантика (bbox + кроссинг, общая функция) + нормализация z (канон
     NpcSpawnTerritory → ZoneNPoly); Territory получает прекомпутированный bbox (4 поля
     int32; формат поддерживает shape/rad на territory и banned_territory с дефолтом NPoly
     — 0 вхождений в Interlude есть свойство данных; Contains всегда NPoly, raw-bag
     terr.shape/terr.rad остаётся до потребителя); Banned не участвует (логика случайной
     точки спавна — потребитель фазы 3).
   - **On-edge точки: источник ожиданий — строгая целочисленная int64-семантика**
     (канон считает test2/dy·dx в double; на точках ровно на наклонном ребре JVM может
     дать другой ответ из-за округления — расхождение осознанное, детерминизм важнее).
   - Ресиверы указательные: value копировал бы ~80–170 Б (заголовки слайсов, map) на каждом
     вызове горячего пути; перевод существующих value-методов (Set) на указатели — вне скоупа,
     неоднородность осознанная (F17), пересматривается при появлении следующего метода
     территорий.
6. **Валидация геометрии.** Зоны: Cuboid≠2 / NPoly<3 / Cylinder≠1 узлов — ошибка CodeNumber,
   зона не входит в статику; Cylinder: отсутствие rad — ошибка **CodeAttr**, rad<=0 — ошибка
   CodeNumber; **вырожденность — ошибка**: Cuboid — x1==x2 или y1==y2 (после нормализации;
   линия/точка — вечнопустая зона полуоткрытого предиката), NPoly — **полная коллинеарность
   соседних троек узлов (cross == 0 у всех, покрывает и все-узлы-в-точке)**; шнурок для
   этого не годится: bowtie-полигоны датапака (boss_area_valakas2, 4 узла-«песочные часы»)
   имеют нулевой алгебраический шнурок при ненулевой even-odd площади и функциональны в
   каноне (F45); правило применяется к формам с ≥2 узлами (у Cylinder вырожденность =
   rad<=0, уже ошибка); самопересечения/выпуклость — не проверяются (валидация «смысла»
   вне фазы). Элементы-дети зоны: stat без name/val, spawn без X/Y/Z или с неразборчивой
   координатой, race без name/point, узел с X="abc" — per-элементная ошибка с местом
   (CodeAttr для отсутствия, CodeNumber для неразбора, прецедент readNodes P2.2), разбор
   зоны продолжается. Территории P2.2 и их BannedTerritory (задним числом, при загрузке):
   **пустой набор узлов — ошибка до всех веток (гейт F43: polyBounds не выносит пустого
   слайса, канон проверяет coords.length==0 до формы)**; <3 узлов, коллинеарность —
   ошибка **с местом файл+строка** (доступны в контексте разбора спавнов, как у
   спавн-записей); **guard формата: атрибут terr.shape присутствует и ≠ NPoly — счётчик
   zone.shape.\*-территории (SpawnData канона поддерживает shape/rad на territory и
   banned_territory, дефолт NPoly; 0 вхождений в Interlude — свойство данных, не формата)
   и узловая валидация к такой территории не применяется**; minZ>maxZ — счётчик
   MinZOverMaxZ; повтор соседних узлов — счётчик DupAdjacentNodes (8 случаев). minZ==maxZ —
   допустимо (тонкий слой; 2 случая в зонах). Отсутствие minZ/maxZ у зон — ошибка CodeAttr;
   у территорий — уже структурная ошибка P2.2.
7. **Отчёт и Dump.** Счётчики: Zones, ZoneSpawns, ZoneRacePoints, MinZOverMaxZ,
   **MinEqMaxZ** (тонкий слой; 2 случая), MissingZoneName, DupAdjacentNodes,
   **DupZoneNames (считает имена, не зоны-носители: 41 ≠ 89)**, **ZonesWithID** (широта,
   прецедент NamedBlocks/TerrOwnName); DisabledFiles — переиспользуется; UnknownTypes
   zone.type.*; **unknown shape — зона выше счётчика zone.shape.\***;
   SkippedElements/SkippedDirs/DupKeys — общие. Dump: зоны в порядке загрузки —
   name/type/shape (каноническое имя формы; unknown — исходная строка из raw-bag)/id?/
   minZ/maxZ (исходные)/rad?/узлы/стат-набор (сортирован)/спавн-точки/race-точки; дамп
   территорий не меняется. Эквивалентность артефакта P2.7 охватывает зоны автоматически
   (Dump — единый).
8. **Горячий путь и бенчмарки.** Point-in-zone станет горячим в фазе 3 (проверки при
   движении); по правилу реестра ADR-0005 бенчмарк рождается с первым кодом пути:
   - BenchmarkZoneContains: саббенчмарки NPoly n=4/8/16 (4 узла — 72% дистрибутива),
     Cuboid, Cylinder; попадание и промах; координаты мира ~±100000.
   - BenchmarkZonesScan: перебор синтетического набора ~2000 зон (смесь форм как в
     дистрибутиве, **кластеризованная геометрия** — K кластеров центров вместо
     равномерного разброса, как реальные континенты/города), **классы точек вычисляются от самой зоны в итерации** (z-промах; угол bbox — внутри bbox, обычно мимо полигона, платит кроссинг; центр bbox — обычно попадание; полный промах; представленность классов фальсифицируется TestScanClasses — F47) — одна константная точка мерила бы везение бранч-предиктора;
     назначение — baseline наивного перебора для будущего решения о пространственном
     индексе (perf.md §0: оптимизация без baseline запрещена).
   - BenchmarkTerritoryContains — аналогично по размеру.
   - Требование 0 аллокаций — машинное: AllocsPerRun-гейты на все формы + Territory
     (прецедент internal/protocol, internal/crypto); бенчмарки — для ns/op.
   - DCE-защита — sink-паттерн (прецедент internal/geo/move_bench_test.go).
   Строка реестра «Зоны: point-in-zone | data» — правкой таблицы реестра ADR-0005 in-place
   в этой задаче (осознанное расширение ожидания p2 «правка — только рёбра/подпакеты»:
   само правило ADR «бенчмарк с первым кодом пути» требует строки; фиксируется здесь и в
   журнале). Ревью-профиль P2.5 в p2.md расширяется перформансером (S2-компенсация —
   выполнена отдельным прогоном по решениям 5/8, F8; участие в S8). Пространственный
   индекс (ZoneRegion-сетка канона) — анти-скоуп до потребителя (ADR-0004: зоны — данные).
9. **Синтетика и злые входы.** testdata/synth/zones/zones.xml: все 3 формы, зона с id и без,

### Критерии приёмки (фальсифицируемые)

- Таблица point-in-zone на каждой форме: внутри / снаружи / границы (ребро, вершина,
  z-минимум, z-максимум, x/y-граница Cuboid — полуоткрытость, окружность Cylinder —
  включение) и **злой случай |Δ|>46341 на каждой форме** (int32-переполнение — ожидание
  из int64-арифметики); ожидания выведены из строгой целочисленной int64-семантики
  (on-edge точки: расхождение с JVM-округлением double — осознанное, детерминизм важнее)
  и зафиксированы в тесте.
- Таблица злых входов Р9: каждая — отдельная запись-ошибка с местом (файл+строка), сборка
  красная; unknown type / unknown shape / дубликат name / minZ>maxZ / повтор узлов / повтор
  stat-ключа / файл без enabled — зелёная сборка со счётчиками.
- Реальный дистрибутив канона (плоский состав): загрузка без ошибок; выжимка счётчиков —
   в журнал (КТ-3): **ожидаемые 2411 зон, ZoneSpawns 662, ZoneRacePoints 725,
   MinZOverMaxZ 28, MinEqMaxZ 2, DisabledFiles 1 (tax.xml), DupZoneNames 41 (имена),
   ZonesWithID 111**.
- Golden: Dump синтетики (зоны в порядке загрузки) стабилен.
- Бенчмарки Contains/Scan: 0 аллокаций (AllocsPerRun-гейты); baseline в журнал.
- Ворота зелёные; fuzz-смоук CI расширен; зависимостей ноль.

### Скоуп-границы

- Не входит: индекс зон по регионам (ZoneRegion канона), случайная точка зоны/территории
  (getRandomPoint — фаза 3, зависит от геодаты), поведенческая интерпретация типов
  (peace/water-эффекты — фазы 3+), типизация stat-параметров (raw до потребителей),
  списочная семантика affectedRace/affectedClassId (F19 — фазы 4+), категория
  mapregion/restart-регионы (нет в фазе 2), NpcSpawnTerritory в zones/ (не встречается
  в дистрибутиве; тип не в словаре — счётчик zone.type.*).
