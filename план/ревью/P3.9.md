## Детальный план (S0, ред. 5 — финален: раунд 1 + S5-миноры + рекомендации S6 + пины S6b)

### Факты канона (сверка S0; уточнены раундом 1 — F8)

- **Сервер-авторитарность (r1):** клиент шлёт намерение, сервер двигает по geo-валидированному
  пути и бродкастит свою позицию; predict-client/validate+correct-server; токен-бакет скорости
  per-entity: `budget += maxSpeed·dt` до CAP ~1–2 с хода; смещение списывает; `< −SLACK` → флаг;
  CAP сглаживает лаг-спайки, SLACK — порог джиттера.
- **Поток кадров (референс interlude@34fe4c8, Go,GPL — internal/game/loop_movement.go):**
  MoveToLocation → эхо себе + бродкаст окружающим; ValidatePosition → при `distSq > 90000`
  (порог дрейфа **300 юнитов**) → ValidateLocation **себе**; out-of-bounds отчёты дропаются
  (loop_movement.go:110-114) — прецедент для валидации координат отчёта у нас. Позиция у нас
  авторитетна на сервере — отчёт не принимается (сверка, не мутация). describeState известному
  (ввод при движении) — CharInfo + CharMoveToLocation (реестр P3.8). CharMoveToLocation = 29 Б
  (опкод + objID + dst 3D + cur 3D = 7×D).
- **Heading (L2J MathUtil.calculateHeading, порт с атрибуцией):**
  `h = atan2(dx, dy)·65536/2π; if h < 0 { h += 65536 }` — на старте движения к цели; домен
  [0, 65536). Якорь полной точности 10430.378350470453 = 65536/2π — L2J MathUtil;
  интерлюд-референс (combat_range.go) несёт усечённый литерал 10430.378. Atan2 — не
  correctly-rounded (в отличие от Sqrt): бит-в-бит реплейHeading гарантируется режимом
  «тот же бинарарь / та же мажорная версия Go» (F20; прецедент PCG в Noise); целочисленный
  CORDIC не заводится — код под неиспользуемое свойство.
- **Running ≠ факт движения (F7):** Running канона — режим run/walk, Standing — факт позы;
  фаза 3: Running=true константой (walk-режим — фаза 4), Standing=!Entity.Moving.
- **Числа фазы 3 (атрибуция r1-дизайн; владелец утверждает на ✅ по строке КТ p3.md):**
  runSpeed = persist.HumanFighter.RunSpd = 115 юн/с (шаблон). Единая таблица единиц (милли-юниты,
  мЮ = 10⁻³ юн): скорость = runSpeed·1000 мЮ/с = runSpeed мЮ/мс; инкремент за тик =
  **runSpeed·dtMs** мЮ (115·100 = 11 500 мЮ при 10 Гц); CAP = runSpeed·2000 мЮ (2 с хода);
  SLACK = runSpeed·500 мЮ (0.5 с); дебет бакета = d·1000 мЮ (d в юнитах); порог дрейфа = 300 юн;
  K = 64 MoveToLocation-обработок на шаг (64 line-walk'а ≤ ~54 мкс при 75–837 нс на ValidLocation,
  baseline P2.4). Тюнинг — фаза 4 (боты).
- **Телепорты** — ветка не заводится: комментарий-указание на r1 §«Телепорты» для фазы 4+
  (pendingTeleport-флаг уже есть и гасится здесь только как «вход/спавн»).

### Решения

1. **Вся кинематика — в свёртке (Fold), один владелец.** Порядок внутри шага: письма порций
   (интенты движения) → фаза A (advance всех движущихся) → экспирации → ретраи → Beat. Письмо
   движения, обработанное этим шагом, начинает ехать этим же шагом. **Запись-отклонение (F11):**
   порядок «письма → advance» отклоняется от буквы ADR-0002 §5/r1 (A→B) аргументом латентности
   старта: канонический клиент начинает движение при обработке письма (интерлюд-реф), старт
   следующим тиком добавил бы 100 мс; «сверх-кредит» ≤ 1 тика в первом шаге детерминирован и
   одинаков в прогоне и реплее. Детерминизм: целочисленная арифметика в мЮ (int64), никакого
   wall-clock; dt — только delta тиков; период — из Rules (D1).
2. **Проводка зависимостей в свёртку (F5, F19):** `Rules += PeriodNS int64` (заполняется из
   Config.Period() при Wire; реплей-харнесс подставляет из заголовка лога порций; наносекунды,
   а не миллисекунды — одна точка конверсии и точность некратных Hz, прецедент Period());
   инкремент advance = `runSpeed·delta·PeriodNS/1e6` мЮ (порядок множителей исключает
   переполнение int64). `Fold(..., gm *geo.Map, ...)` — карта аргументом (чистота свёртки,
   паковый глобал запрещён). Тест с нестандартным Hz (период 200 мс) — дистанция advance
   следует периоду, не числу тиков.
3. **Состояние сущности (Entity):**
   - `Moving` — переопределяется как флаг **локомоции** (фаза 3 миграций региона нет как класс;
     интент переезда вернётся отдельным полем чемодана в фазе 4 — запись-отклонение в реестре,
     комментарий в world.go). Комментарии world.go/aoi.go обновляются.
   - `Dest Position` — клампнутая цель (уже есть).
   - Новые поля: `Heading int32` (живой heading, домен [0,65536); при рождении — из Rec.Heading),
     `MoveFrom Position`, `MoveDist int64`, `MoveDone int64` (мЮ пройденного по отрезку
     From→Dest; **дистанция отрезка — 2D** (F27): скорость канона горизонтальна, Z — следствие
     рельефа, прибытие ставит Z цели). Позиция каждый тик пересчитывается от From по пройденной
     доле (без накопления ошибки округления); на прибытии позиция = Dest точно.
   - Гашение отрезка (F28): ЛЮБАЯ остановка (прибытие, CannotMoveAnymore, Logout, экспирация,
     ретаргет) приводит поля к стоячему виду — MoveFrom=Pos, MoveDist=0, MoveDone=0
     (ретаргет затем пишет новый отрезок); бит-в-бит реплей не зависит от молчаливого выбора.
   - `Player.SpeedBudget int64` — токен-бакет (мЮ), при рождении = CAP.
   - Рождение игрока (F16, F22): позиция записи — за trust-границей (персист-файл): rec.X/rec.Y
     (int64-поля записи) проверяются `geo.InWorld` ДО сужения до int32 (значение 2^32+k
     заворачивается кастом в сетку); вне сетки — вход не рождается (DeadLetter, прецедент
     валидации записи на применении foldEnterWorld). Без этого «NaN исключён структурно»
     решения 7 держится на непроверенной посылке authPos ∈ сетке.
   - Скорость — константа шаблона `runSpeed` в world (атриб. persist.HumanFighter); per-entity
     скорость — фаза 4 (баффы/режимы); movementMode (клавиатура/мышь) на скорость не влияет фазе 3.
   - Снимок сохранения — единая точка (F10): и queueSave (fold), и finalSave (region) собирают
     rec.{X,Y,Z,Heading} из Entity одной функцией.
   - Гашение движения (F24): foldLogout/foldExpiries при остановке сбрасывают и поля отрезка
     (MoveFrom=Pos, MoveDist=0, MoveDone=0) — гигиена сериализации, на детерминизм не влияет.
   - Dump: Entity-сериализация дополняется Heading/MoveFrom/MoveDist/MoveDone; Player —
     SpeedBudget (бит-в-бит реплей).
   - Record.Heading в recordOf — из **Entity.Heading** (F9); Rec.Heading остаётся персист-слепком.
4. **Письмо MoveToLocation (фаза B, capped):** foldClientFrame → ветка OpCMoveToLocation.
   Валидация на применении у владельца: длина кадра (MoveToLocationView, иначе DroppedFrames);
   цель и authPos в сетке мира — новый экспорт `geo.InWorld(x, y) bool` (F15: ≡ ¬паник-условию
   geoOf — тот же WorldToGeoX/Y и та же граница, тест эквивалентности на кромках сетки); вне
   сетки → дроп + DroppedFrames. Далее: `gm.ValidLocation(authPos, target)` → Dest (кламп),
   Moving=true, From=authPos, MoveDist/MoveDone=0, Heading=calcHeading(From→Dest). Повторное
   MoveToLocation в движении — ретаргет с авторитетной позиции. Кламп вернул точку ≈ текущей
   (дистанция < 1 ячейки) → StopMove немедленно (без старта) **себе** (F29: наблюдатели о
   движении не знали — интродуцировались стоячей записью; им кадр не нужен). Эхо себе:
   CharMoveToLocation(objID,
   Dest, authPos) в res.Pushes (self-поток из приватного состояния владельцем).
   **Кап K=64 обработок на шаг (F3):** счётчик капа считают только валидные к обработке
   письма (невалидные дропаются валидацией раньше, в K не входят — F23); письма сверх капа —
   **дроп + DroppedFrames** (класс
   «кадр не применяется»; прецедент шлюза — InboxCap). Очередь-отложение НЕ заводится:
   FIFO-инверсия пачки ([MoveToLocation-сверхкапа, CannotMoveAnymore] применялось бы в обратном
   порядке), неограниченный рост State/Dump от 65+ коннектов, YAGNI при приёмке фазы 3 в 2
   клиента. **Запись-отклонение от r1 «переполнение — defer на следующий тик»:** defer задуман
   для лавины NPC-ре-пасов осады (фаза 4); игрок может пере кликнуть (шлюз коалесит ≤1
   письма/конн/шаг — кап достижим только 65+ различными коннектами в одном 100-мс шаге).
   Defer-очередь вернётся фазой 4 по данным ботов.
5. **Фаза A (advance):** для каждого жителя с Moving (обход сортированного ents — трактовка
   «SoA-проход по массиву движущихся» фазы 3: итерация массива населения с фильтром;
   параллельные массивы потребовали бы дубль single-writer состояния — отклонение с аргументом;
   индекс движущихся — эволюция по данным бенча, включая точку «население 12k, движущихся ~100»
   (F14, датчик P3.10)): `MoveDone += runSpeed·dtMs` (мЮ); при MoveDone ≥ MoveDist — прибытие:
   Pos=Dest, Moving=false, StopMove себе (res.Pushes) + наблюдателям через AoI. Бакет: всем
   игрокам `SpeedBudget = min(SpeedBudget + runSpeed·dtMs, CAP)` (те же мЮ-единицы, F2).
6. **AoI-компоновка (composeJoin):** Record дополняется DestX/DestY/DestZ (клампнутая цель;
   compose самодостаточен пейлоадом события — прецедент P3.8). Правила:
   - EventIntroduce движущейся записи → CharInfo + CharMoveToLocation (describeState канона);
     стоячей → CharInfo. Standing=!Moving; Running=true (F7).
   - EventUpdate движущейся → CharMoveToLocation(dst=Dest, cur=поз) — **авторитетный стрим
     одна позиция на кадр** (расхождение с каноном L2J «один кадр на интент» осознанное:
     r1 «сервер бродкастит свою позицию» — сервер-авторитарный поток; полоса 29 Б × 10 Гц × пары;
     CPU/аллокации — бенчем раунда 1 (F12), пересмотр фазой 4 по нагрузке).
   - EventUpdate стоячей (прибытие/коррекция) → StopMove(objID, поз, heading).
   - Себе стрим не идёт (self-пара в join исключена; self-кадры — только из свёртки: эхо старта,
     StopMove, коррекции).
7. **ValidatePosition (~1/с):** валидация зеркально решению 4 (F1): длина кадра
   (ValidatePositionView, иначе DroppedFrames); координаты отчёта в сетке мира (geo.InWorld,
   вне — дроп + DroppedFrames, прецедент интерлюд-реф). После валидации обеих концов
   (отчёт + authPos, последний — гарантией рождения F16) осевые |dx|,|dy| ≤ стороны мира
   ≈ 1.05e6 юн → d² ≤ 2·стороны² ≈ 2.2e12 — int64-запас, Sqrt от неотрицательного, NaN исключён
   структурно (конвертация NaN→int64 платформенно-зависима — реплей D6). Далее: pendingTeleport
   → отчёт рядом с authPos (≤ 300 юн) — флаг снят, бакет = CAP; далеко → snap-back
   (ValidateLocation себе с authPos) + SnapBacks, флаг держим. Обычный: d = |отчёт − authPos|
   (int64, 2D, math.Sqrt от квадрата — IEEE-754 правильно округлён, аргумент < 2^53 → бит-в-бит);
   `SpeedBudget -= d·1000`; при `SpeedBudget < −SLACK` → SpeedFlags++ (slog-алерт) + snap-back.
   Дрейф: d > 300 → snap-back + SnapBacks. Внутри порогов — отчёт не мутирует позицию сервера
   (чистая сверка); heading отчёта не принимается.
8. **CannotMoveAnymore:** валидация та же (длина + InWorld, F1). Сущность в движении →
   авторитетная остановка здесь: Moving=false, Dest=Pos, StopMove себе и наблюдателям;
   d > 300 → snap-back себе. Heading письма принимается безусловно с нормализацией `& 0xFFFF`
   в [0,65536) (F6: порога нет — косметика, кадр уже валидирован; F17: знаконосный Go-`%`
   оставляет отрицательные — только маска). Не в движении → счётчик
   CannotMoveNoops (не дроп: кадр валиден, класс «no-op»).
9. **Метки свёртки:** State += SpeedFlags, SnapBacks, CannotMoveNoops (в Dump). Сверхкапный
   дроп K — в существующий DroppedFrames. Наблюдаемость — slog при флаге спидхака (прецедент
   foldPersistReply) + Dump.
10. **Сборка:** NewRegion получает `gm *geo.Map` (nil → ошибка: мир без гео не живёт);
    artifact.LoadFile в cmd/l2go перестаёт отбрасывать карту. **Деградация без гео (F4):**
    артефакт без гео-регионов — карта пустая, сетка мира не сужается: InWorld проходит,
    ValidLocation даёт NullRegion-семантику канона (всё проходимо, без стен, Z цели принимается)
    — «мир без стен», лог на старте; дропа писем нет. Осознанная семантика вырожденного артефакта.
    ADR-0005: ребро world→geo уже объявлено; новых пакетов нет.

### Не в скоупе (фиксируется явно)

Телепорты (комментарий-указание на r1, фаза 4+); walk-режим и семантика movementMode; NPC-
движение (P3.10 — SoA-noop); Z-антифлай по отчёту (слои покрыты ValidLocation; отдельная
сверка заявленного Z — фаза 4+; на пустой гео Z цели принимается — вырожденный артефакт);
VehicleID; спам-лимит писем (шлюз коалесит); пересечение регионов (одна ячейка фазы 3);
принятие позиции отчёта (сервер авторитетен — r1); defer-очередь сверхкапных MoveToLocation
(фаза 4 по данным ботов — запись-отклонение от r1); гашение клиентского интента при snapback
в движении (StopMove себе — канонный рычаг от цикла коррекций ~1/с; фаза 4, опция зафиксирована).

### Обязательства вниз

- **P3.12 (реплей-гейт), О-1:** скрытые входы реплея вне лога — Rules (окна, адреса) и
  гео-артефакт; при смене артефакта между записью и реплеем дамп разойдётся криптически.
