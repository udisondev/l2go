# Реестр находок P1.3

- Задача: P1.3 «Каталог опкодов и примитивы кодека — internal/protocol» — [план/p1.md](../p1.md)
- Ревью-профиль: S2 — инвариантщик, безопасник, перформансер, доменщик, прагматик; S8 — + тестировщик
- Бюджеты: план 1/2 · рестарты 0/2 · ревью реализации 1/3

## План задачи (S0, рев. 2 — после S2/S3/S4)

**Цель.** `internal/protocol`: полный каталог опкодов Interlude 746 (494 записи по 6 группам:
C→LoginServer 6, LoginServer→C 11, C→GameServer 161, C→GameServer-Ex 46 (0xD0+sub),
GameServer→C 198, GameServer→C-Ex 72 (0xFE+sub)) с машинной проверкой полноты/уникальности/
диапазона; примитивы кодека WriteD/H/F/Q/S + LenS + парные read (семантика интерлюда,
0-аллокационная запись); golden-рамка фикстур; конвенция писателей/представлений — на живом
коде (стабы WriteAttack/AttackView скелета оживают). Источник каталога —
`interlude@34fe4c8657d8b6bf338a5d2e788e194489a44f8f` docs/opcodes.md; канон — сверка с
Mobius master CT_0_Interlude (пин ниже) и pcap-фактурой живого клиента.

**Решения (с аргументами).**

1. **Каталог — данные как единственный источник правды; константы Go — по мере типизации
   пакетов, каждая сверяется с каталогом.** Форма: шесть таблиц-слайсов записей
   `{Name string, Value uint16}` (SNAKE-имя как в источнике; у основных групп Value —
   опкод, у Ex-групп Value — sub при опкоде семейства 0xD0/0xFE — атрибут группы).
   Машинная проверка в тесте (четыре проверки): счёт записей по группам ==
   6/11/161/46/198/72 (итого 494 — полнота против источника); уникальность Value и имён
   внутри группы; имя↔значение взаимно однозначны (обход в обе стороны); Value ≤ 0xFF
   для четырёх основных групп. Lookup-API (имя по направлению/опкоду/sub) в P1.3 НЕ
   вводится — нет потребителя, форма ключа определится диспетчером P1.5 (там родится:
   неэкспортированные мапы + экспортированные функции; экспортированные мапы запрещены —
   мутабельная глобаль против инварианта «иммутабельная статика»). Документация каталога
   (doc у таблиц): sub=0 означает «нет sub» (в обеих Ex-группах значения с 0x01 —
   двусмысленности нет); 0xD0 в основной C→GS таблице — легитимная запись EX_PACKET
   (Ex-семейство адресуется и как основной опкод-признак). **Отклонение от буквы спеки**
   («форма: константы» на весь каталог): 474 неиспользуемые константы — мёртвый код
   (codestyle §11), дублирование 494×2 для машинной связи имя↔константа. Константа
   рождается вместе с первым писателем/представлением пакета (в P1.3 — Attack для
   WriteAttack/AttackView) и сверяется тестом. При коллизии имён между направлениями
   (LOGIN_FAIL, NET_PING, TRADE_DONE есть в обоих направлениях GS) константа
   типизируемого позднее пакета получает суффикс направления. Дух спеки сохранён:
   магических чисел в пакетах нет, каталог полон и машинно проверим.
2. **Ex-семейства — подпространства каталога.** Уникальность в группе: у основных —
   опкод, у Ex — sub. Ex-опкод семейства (0xD0/0xFE) — атрибут группы (константа — при
   типизации первого Ex-пакета). Wire-кодирование sub — конвенция парсеров, фиксируется
   в P1.4 с первым Ex-пакетом; каталог хранит только значение sub.
3. **Примитивы записи — семантика helpers interlude, 0-аллокационная реализация.**
   `WriteD(dst []byte, v int32)`, `WriteH(dst []byte, v int16)`,
   `WriteQ(dst []byte, v int64)`, `WriteF(dst []byte, v float64)` — фиксированный размер
   (4/2/8/8 LE, F — IEEE 754 double по битам; канон подтверждён Mobius master:
   UserInfo/CharSelectionInfo пишут writeDouble), пишут в dst[0:], без возврата;
   `WriteS(dst []byte, s string) int` — UTF-16LE + null-терминатор, возврат n
   (переменная длина). WriteS — прямым обходом строки (руны и суррогатные пары вручную),
   НЕ utf16.Encode([]rune(s)): порт аллоцирует 1-2 раза (24-288 Б) на строку против
   0 аллок прямого обхода (прототип F6: 25.8 против 72.3 нс, длинные 90.7 против
   302.5); utf16-пакет — оракул в тестах и реализация ReadS. Невалидные руны и непарные
   суррогаты — замена на U+FFFD (семантика utf16.Encode). Границы: паника с
   диагностикой при коротком dst — программный контракт вызывающего по прецеденту
   F6/P1.2; **статус: зависит от ратификации F6/P1.2 на S9 — продолжено по
   рекомендации, как в P1.2; откат-шов: guard в ошибку, одна ветка на примитив.**
   Sizing строковых полей: `LenS(s string) int` — размер WriteS в байтах (0 аллок);
   конвенция писателей: буфер для пакета со строками считается через LenS (sizing и
   запись — одним расчётом); достаточная верхняя граница 2*len(s)+2 (юниты UTF-16 ≤
   байты UTF-8). writeUD не переносится: беззнаковая семантика — приведение на
   вызывающем (записано в отклонениях порта). writeZeroD/H, writeSpeeds, EncodeUTF16/
   writeUTF16Bytes — пакетные удобства, не переносятся (YAGNI до P1.4).
4. **Примитивы чтения — ok-семантика, не молчаливые нули референса.**
   `ReadD/H/F/Q(src []byte, off int) (v, ok bool)` — офсет ведёт вызывающий;
   `ReadS(src []byte, off int) (s string, n int, ok bool)` — n = байты включая
   терминатор. Отказ (ok=false, нулевые значения) только: терминатор не найден среди
   полностью уложившихся юнитов до конца буфера (непарный хвостовой байт — не причина
   отказа, если терминатор найден раньше); off вне [0, len(src)-size] — проверка в
   форме вычитания `off < 0 || size > len(src)-off` (не переполняется на off≈MaxInt;
   покрывает и отрицательный офсет). UTF-16: декодирование utf16.Decode (непарные
   суррогаты → U+FFFD — стандартная замена, отдельные утверждения тестов). Float — по
   битам (math.Float64{bits,frombits}), NaN/Inf включаются в таблицу.
5. **Конвенция писателей/представлений — doc пакета + живые образцы; форма определяется
   ролью потребителя, не направлением пакета: кодирование исходящего — писатель, разбор
   входящего — представление, в любом направлении** (клиент P1.5 шлёт C→S писателями и
   принимает S→C представлениями; сервер — зеркально). Писатель:
   `func WriteAttack(dst []byte, ...) int` — пишет с опкодом с dst[0], возвращает длину;
   малые пакеты — стек вызывающего, крупные — bufpool; sizing строковых пакетов — через
   LenS (решение 3). Представление: `type AttackView []byte` + конструктор
   `NewAttackView(b []byte) (AttackView, bool)` — проверка минимальной длины один раз;
   геттеры по офсетам без ok (конструктор гарантирует границы). Строковые геттеры
   представлений возвращают string (1 аллокация материализации — неизбежна; допустимы
   на не-тиковых путях диспетчера/логгера; пер-тик-потребление — по сырым байтам/длине).
   Нулевое значение представления недействительно: доступ к полям — только после
   успешного конструктора (осознанное исключение из codestyle §11, класс F6/P1.2 —
   в doc). Валидация полей (диапазоны/семантика) — на применении у владельца
   (инвариант 2). Doc-комментарии скелета переписываются самодостаточными (отсылки
   «появятся вместе с каталогом» снимаются; атрибуция порота сохраняется — это
   происхождение).
6. **Стабы скелета оживают** (в рамках спеки, не анти-скоуп P1.4): WriteAttack —
   порт `attack.go` интерлюда; формат подтверждён каноном Mobius master Attack.java
   (F9-опровержение): opcode + attackerID D + {targetID D, damage D, flags C} +
   atkXYZ DDD + extraHits H + [хиты ×9Б] + tgtXYZ DDD; одиночный удар — 40 Б;
   константа Attack = 0x05 GS→C из каталога. AttackView — представление: конструктор
   по минимальной длине, геттеры первого удара + геттер ExtraHits; doc: представление
   первого удара, хиты сверх — hex-дамп диспетчера. Аргумент: образцы конвенции
   существуют с фазы 0 — живой образец лучше фальшивого; Attack — носитель
   бенчмарка реестра ADR-0005 «пакет-писатель 40 Б, 0 аллокаций». Новых пакетов мира
   не добавляется.
7. **Golden-рамка фикстур — подпакет `internal/protocol/fixture`** (правка ADR-0005 и
   scripts/checkdeps.sh: строка `internal/protocol/fixture` — без зависимостей; рёбра
   `internal/protocol → internal/protocol/fixture` (golden-тест P1.3/P1.4),
   `internal/l2client → internal/protocol/fixture` (сценарий-сервер P1.5) — синхронно
   в матрице и allowed(); ребро будущего pcap-пакета — при его рождении в P1.6).
   Формат testdata JSON: `{dir, op, sub, name, payload-hex, origin}`; payload = байты
   после опкода, для Ex-семейств — после байтов sub; origin = generated|captured —
   происхождение вектора (generated — собран из внешнего оракула формата/полей;
   captured — живой трафик P1.6). Загрузчик `fixture.Load(name string) ([]Fixture,
   error)` — name: путь внутри testdata (без расширения); ошибки — %w + имя файла.
   Первая фикстура — Attack, origin=generated: байты собираются из формата Mobius
   Attack.java и вектора полей теста интерлюда (100/200/1500/0x20/координаты),
   независимо от нашего писателя — генерация фикстуры собственным писателем для
   golden encode запрещена (круг писатель→фикстура→писатель); замена на captured —
   P1.6.
8. **Метод сверки каталога.** Оракулы: первичный — interlude docs/opcodes.md@34fe4c8
   (перенос); канонический — **Mobius master CT_0_Interlude, зеркало GitLab
   gitlab.com/expcero/L2J_Mobius (project 86287781), зафиксировать текущий коммит sha
   при сверке** — ClientPackets.java/ExClientPackets.java/ServerPackets.java
   (скачивание raw через API); фактура живого клиента — pcap-знания интерлюда
   (KeyPacket 0x00 кастом / 0x2E Standard L2J — обе ветки в живых дампах; клиент шлёт
   ProtocolVersion 0x00); la2go@1eed6cb — дополнительный, с известными расхождениями
   (ProtocolVersion 0x0E, KeyPacket 0x2E — не совпадает с Mobius master и живым
   клиентом). **Правило разрешения расхождений: канон — живой клиент (pcap) + Mobius
   master; при расхождении источник↔канон принимается значение канона, расхождение —
   строкой в реестр (значение, источник, принятое); несовпадения la2go — списком.**
   Контекстность опкода 0x2E GS→C (KeyPacket в состоянии хендшейка против
   CHANGE_MOVE_TYPE в игре) — документируется в реестре, реализация — диспетчер P1.5.
   Сверка выполняется при переносе скриптом (выгрузка трёх enum-файлов Mobius,
   сопоставление имён/значений по группам); результат и пин коммита — в реестр. В CI
   воспроизводима только полнота (счёты) — внешние источники в репо не входят.
9. **Тест-план (TDD, красная фаза — отдельным коммитом, прецедент P1.2):** машинная
   проверка таблиц (четыре проверки решения 1); константы→каталог; раундтрипы
   примитивов write→read: равенство — предусловие валидный UTF-8 без U+0000
   (контрпримеры "\xff", "a\x00b" — свойство с предусловием; канонизация невалидных
   руно-входов в U+FFFD и обрезка на U+0000 — отдельные детерминированные
   утверждения); property-таблица: отрицательные значения, граничные длины, UTF-16 —
   кириллица/суррогатные пары (astral, 4 Б UTF-8 → 2 юнита)/пустая строка; float — по
   битам, включая NaN/Inf/−0; злые входы читателей (обрезанный буфер, off<0,
   off=len(src), off>len(src), off≈MaxInt, нет терминатора → ok=false; непарный хвост
   ПОСЛЕ найденного терминатора → ok=true — регресс F-контракта); паника-контракт
   писателей (recover-тест с диагностикой в сообщении; короткий dst на каждом
   примитиве); LenS: соответствие WriteS на таблице строк (включая не-BMP);
   Attack: golden против фикстуры + счёт 40 Б + позиции полей; AttackView:
   конструктор (короткий/точный/длинный с extraHits), геттеры над golden-байтами,
   ExtraHits; fixture.Load: happy path + таблица ошибок (нет файла, битый JSON,
   битый hex → детерминированная ошибка); Example пакета; fuzz-цели раундтрипа
   D/H/F/Q/S с seed-корпусом и фаззингом офсета (off как отдельный аргумент цели);
   полный фаззинг — P1.7.
10. **Бенч-план:** `BenchmarkWriteAttack` — путь реестра ADR-0005 (40 Б, стек, 0
    аллокаций, проверка AllocsPerRun в тесте); `BenchmarkAttackView` — геттеры
    представления; семейство примитивов `BenchmarkWriteReadD`, `BenchmarkWriteReadS`
    (короткая/длинная строки), `BenchmarkLenS`. b.Loop, ReportAllocs, SetBytes,
    benchtime=100ms фиксируется в шапке; baseline `-count=10` →
    `benchmarks/P1.3-protocol-baseline.txt` с окружением; сверка семейств baseline с
    бенч-планом (правило F25/P1.1); послабления против perf.md §0 — по прецедентам
    F28/P1.1, F9/P1.2 в шапке baseline.
11. **Атрибуция и лицензионная классификация.** Каталог — перенос структурных данных
    интероперабельности (имя+значение опкода) из GPL-референса interlude@34fe4c86
    (комментарий-источник у таблиц); колонки «Категория/Описание/Статус» исходника не
    переносятся; это не NCsoft-derived контент (не датапак/геодата/клиентские файлы) —
    значения опкодов суть интерфейс протокола. Helpers/Attack — порт
    pkg/packet/{server,client} interlude@34fe4c86; отклонения перечислены: ok-чтение
    вместо молчаливых нулей, 0-аллокационный WriteS (не utf16.Encode), паника-контракт
    записи с диагностикой, неперенос writeUD/writeZeroD/H/writeSpeeds/EncodeUTF16,
    конструктор-view. Mobius — внешний оракул сверки, код не портируется.
12. **Скоуп-границы:** пакеты логин-флоу — P1.4; фрейминг потока — P1.5;
    lookup-функции каталога и контекстность 0x2E — P1.5 (диспетчер); wire-кодирование
    Ex-sub — с первым Ex-пакетом (P1.4+); полный fuzz — P1.7; смена формы каталога —
    вне задачи.

## Дополнения S6 (внесены в текст плана, без рестарта)

- **Решение 8+** (протоколчик): каноническая выгрузка — ПЯТЬ enum-файлов Mobius:
  game-side ClientPackets/ExClientPackets/ServerPackets + login-side
  loginserver/network/LoginClientPackets.java, LoginServerPackets.java (без них канон
  покрывает 477/494; обе login-группы сверены — идентичны каталогу). Машинное сравнение
  C→GS-Ex исключает сентинел EX_MAX(0x31, null) — граничный маркер Mobius, не пакет;
  «null-поставщик» — НЕ критерий исключения (REQUEST_SURRENDER_PERSONALLY(0x69, null) —
  реальная запись каталога). Сверка fresh-взглядом: значения каталога против Mobius —
  расхождений ноль, 8 косметических нормализаций имён C→GS (REQUEST_BBS_WRITE против
  REQUEST_B_B_SWRITE и т.п.) — фиксируются списком.
- **Решение 1+** (архитектор): шесть таблиц каталога неэкспортированы (слайс — та же
  мутабельная глобаль, что и мапа F13); экспорт в P1.5 — только lookup-функции.
- **Решение 7+** (архитектор): testdata анкеруется внутри пакета fixture (go:embed или
  runtime.Caller — выбор в S7): потребители исполняются из разных рабочих каталогов,
  наивный относительный путь ломается кросс-пакетно.
