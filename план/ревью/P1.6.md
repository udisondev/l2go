  S8 — + тестировщик, доменщик.

## План задачи (S0, рев. 2 — с правками S4)

### Проблема

Для golden-корпуса и сверки канонов (паддинг CT0/dynamic, поведение живого клиента/сервера) нужен
инструмент сбора и разбора живого трафика. pcap-путь требует Npcap и реассемблирования TCP;
владелец предложил доменный тап — прокси между клиентом и сервером. Согласовано.

### Решение

**1. `internal/tap` — прокси-тап с журналом (режим capture).**

- `Run(ctx, opts)`; opts: пары `Map{Listen, Upstream}` (минимум одна), `Log io.Writer`,
  `Rewrite bool` (логгер не пробрасывается — slog напрямую, F18).
- На каждое входящее соединение: `net.Dial` upstream, две горутины зеркалирования. Копия ноги —
  кадровый цикл: буфер + `protocol.NextFrame` (не io.Copy); для rewrite-ветки login-ноги —
  перезапись ServerList (см. §2), прочие ноги — кадры проходят нетронутыми.
- **Полузакрытие (F3):** EOF одной ноги → `CloseWrite` противоположной; полная close обеих ног и
  запись `connClose` — после завершения обеих горутин копирования (WaitGroup на соединение).
- **Shutdown (F5):** cancel ctx → закрыть listener и все live-ноги, дождаться всех горутин,
  финальные `connClose`, flush журнала.
- Журнал — append-only бинарный формат, записи length-prefixed:
  - header: magic `L2TAP\x01`;
  - `connOpen{connID uint64, openedAt int64, listenLen u32, listen, upstreamLen u32, upstream}`;
  - `data{connID, dir uint8 (1=C→S, 2=S→C), unixNano int64, len uint32, bytes}` — байты,
    **фактически отправленные в ногу** (переписанные, если rewrite сработал);
  - `original{connID, dir, unixNano, len, bytes}` — кадр до rewrite (только rewrite-ветка);
  - `connClose{connID, errLen uint32, err bytes (0=nil)}`.
  - Писатель журнала — единственный, под мьютексом (служебный код вне мира; инвариант 3 о
    регионах не применим — оговорка в doc пакета). **Компромисс (F15):** синхронная запись
  блокирует все соединения при медленном Log — зафиксирован в doc; пропускная способность
  покрывается бенчмарком. **Ошибка записи журнала (F12):** разрыв ног + остановка capture с
  диагностикой; обрыв посередине записи — допустимое состояние, декодер обязан переносить.
- connID — атомарный счётчик; время — `time.Now().UnixNano()` (наблюдаемость, не свёртка).
- **Чувствительность (F17):** doc пакета фиксирует — журнал содержит чат, имена, блоб пароля;
  хранить как секрет, в репо не попадает.

**2. ServerList-rewrite (перенаправление game-ноги в тап).**

Клиент получает в ServerList адрес реального GS и уходит мимо тапа. Решение: в login-ноге
(rewrite-ветка) тап держит крипто-состояние: Init читается через `LoginCrypt.DecryptInit`
(static-фаза: статический BF + обратный XOR-pass, F9), `SetKey` из расшифрованного Init; далее
BF-дешифрация кадров S→C. Кадр ServerList: дешифр → разбор `protocol.ServerListView` →
**ограничение (F8): ровно один сервер в списке** — подмена адреса на слушателя game-Map тапа,
пересборка писателем, ре-паддинг/checksum/энкрипт; несколько серверов или несовпадение формата —
skip (кадр нетронутым) + slog. **Защита (F7):** разбор только guard-семантикой представлений;
битый/усечённый ServerList → skip + slog, без паники (строка таблицы злых входов). Оригинал
пишется записью `original`; `data` несёт переписанные байты; инвариант `original ≠ data ⟺
rewrite сработал` (F16). Флаг `-rewrite` (default true; false — чисто пассивный режим).
Членство в кадрах login-ноги C→S: не разбираются, зеркалируются (кроме направления rewrite).

**3. Декодер журнала (режим decode).**

Код — `internal/tap` (F11); `cmd/l2tap` — только флаги и вызов.

`cmd/l2tap -decode session.tap [-out-log traffic.txt] [-out-fixtures fixtures.json]`.

- Читает журнал, группирует по connID; `data`-записи после `connClose` допускаются (F14);
  `original` в поток не подмешивается (отдельно в логе как примечание).
- **Формат-валидация (F13):** неизвестный тип записи, dir∉{1,2}, len-несогласованность,
  data без connOpen, мусорный magic, обрыв записи посередине → детерминированная ошибка
  (обрыв хвоста — предупреждающий лог + Salvage завершённых соединений, если header валиден).
- Классификация ноги:
  - login: первый S→C кадр — Init в static-фазе (`DecryptInit` → `SetKey`); далее BF обе стороны.
    C→S AuthLogin — RSA-блоб: в лог как `OPAQUE` с hex; **в фикстуры не выгружается (F6)**.
  - game: канон границы шифрования — семантика `internal/l2client/game.go` (F2):
    C→S ProtocolVersion plaintext; S→C CryptInit с XOR-ключом → `NewGameCrypt(wire)`; после
    границы — шифрованные кадры. Расхождение живого сервера с каноном — slog + деградация
    пакета в `OPAQUE` (авто-перебор границ запрещён находкой F2).
- Нарезка кадров — `protocol.NextFrame` по потоку каждой стороны (строгий порядок data).
- Лог — формат строк `l2client/traffic.go` (сами хелперы не импортируются; **паритет ловится
  побайтовым сравнением в интеграционном тесте**, F10). Типизированные: login/handshake из
  protocol; прочие — каталог + hex.
- Фикстуры: формат `protocol/fixture`, origin=`live`, **AuthLogin исключён** (F6); селекция
  пакетов для репо — вручную владельцем (ADR-0001).
- Канон паддинга: декодер фиксирует фактический паддинг живых login-кадров (static/dynamic
  по успешности дешифровки) — предупреждение при расхождении с каноном CT0; закрытие хвоста P1.1.

**4. `cmd/l2tap` — тонкий wire-up.**

Флаги: `-map listen=upstream` (повторяемый), `-out session.tap`, `-rewrite` (default true),
`-decode session.tap`, `-out-log`, `-out-fixtures`, `-v`. Учётные данные тапу не нужны.

**5. Матрица ADR-0005 + checkdeps.**

Новая строка `internal/tap` | deps: `internal/protocol`, `internal/protocol/fixture`,
`internal/crypto`, stdlib. Интеграционный тест — **в `internal/l2client`** (импортирует tap;
направление вниз допустимо, F1), l2client — вершина фазы 1. `cmd/l2tap` — точка входа.
Правка ADR-0005 — в этой задаче.

**6. Тесты.**

- Формат журнала: раундтрип всех типов записей; злой журнал: обрыв записи, мусорный magic,
  неизвестный тип, dir=7, len-несогласованность, data без connOpen → детерминированные
  ошибки; хвостовой обрыв → salvage + предупреждение.
- Тап (в internal/l2client, F1): интеграция — scenario-сервер как upstream, l2client через тап;
  флоу до game-хендшейка; лог декодера == логу прямой сессии **побайтово** (F10).
- Half-close (F3): клиент FIN → дочитывает ответ сервера, журнал полон.
- Shutdown (F5): cancel ctx при живом соединении → connClose записан, журнал читается.
- Rewrite: ServerList двумя сегментами (F4) → подмена сработала; multi-server (F8) → skip+slog;
  битый ServerList (F7) → skip без паники; инвариант original≠data (F16).
- Декодер: синтетика scenario-сервера → журнал → фикстуры == байты, прошедшие тап (раундтрип);
  AuthLogin отсутствует в выгрузке (F6).
- Бенчмарк записи журнала (F15) → benchmarks/P1.6-tap-baseline.txt.

**7. Критерии приёмки (фальсифицируемые).**

- Раундтрип инструмента на синтетике: фикстуры == байты через тап (AuthLogin исключён —
  отдельным пунктом проверки).
- Интеграционный тест «клиент → тап → сценарий-сервер»: флоу до game-хендшейка, лог декодера
  побайтово == лог прямой сессии.
- Half-close и shutdown-тесты зелёные; таблица злых журналов/входов — без паник.
- Ворота зелёные (gofmt/vet/build/test/staticcheck/checkdeps; -race — CI).
- Живой прогон против 37.228.91.208:7777 — ручная КТ владельца (лог + фикстуры + вердикт по
  паддингу; инструкция — в выжимке S9, включая предупреждение о чувствительности журнала).

**8. Анти-скоуп.**

pcap-парсер; отправка/модификация пакетов кроме ServerList-rewrite; автоматический вход;
типизация новых пакетов мира; выкладка живых журналов/логов в репо; ephemeral-листенеры на
элементы multi-server списка.

**9. Риски.**

- Живой ServerList/Init формат расходится с писателями P1.4 → graceful skip + slog (game-нога
  теряется, capture продолжается) — узнать на живом прогоне.
- Граница game-шифрования живого сервера отличается от канона l2client → OPAQUE-деградация,
  пересмотр канона отдельной задачей с дампом-свидетельством.
- ЗМега-лаунчер перезаписывает адрес клиента при старте — прогон через правку hosts/l2.ini
  владельцем (инструкция в S9).
