# Реестр находок P3.10

- Задача: NPC-население из спавнов статики — internal/world (план/p3.md §P3.10)
- Ревью-профиль: S2 — инвариантщик, доменщик, перформансер, прагматик; S8 — + тестировщик
- Бюджеты: план 1/2 · рестарты 0/2 · ревью реализации 0/3

## Финальный план (S4, раунд 1)

Механика: контрольное письмо разворачивания → Births свёртки → Spawn актором (буква
P3.2: «производители EnterWorld/NPC фаз 3.7/3.10»; «контрольные письма P3.7/P3.10
сведутся к их вызову»). Реплей воспроизводит разворот из письма в логе порций (реплейные
логи — с LogPayloads=true: payload письма разворота и EnterWorld обязателен для повтора
свёртки — обязательство вниз P3.12) + та же статика артефакта.

1. **transport: KindDeployNPCs.** Новый Kind после KindConnBind: контрольное письмо
   региона (Regional()=true, Class=Reliable), payload — transport.NPCDeployMsg
   (JSON-кодек, прецедент EnterWorldMsg): `{CenterX, CenterY, Radius int32}` — режим
   среза один: центр+радиус. Тест полноты реестра Kind — обновить.
2. **world: Region.DeployNPCs(static, cfg).** До старта Run (после — ошибка, повторный —
   ошибка): сохраняет статику региона; encode-валидация payload до отправки; отправка —
   только слепым push через транспорт (И12): `reg.Send(Envelope{To: Addr{Entity: ctrlID},
   FromID: ctrlID, Kind: KindDeployNPCs, Payload: NPCDeployMsg})`. Отправитель и адресат —
   ctrl-ящик региона; валидация на применении: FromID == rules.From, однократность
   (st.NPCDeployed — повторное письмо dead-letter), Radius ≤ 0 → dead-letter; dead-letter
   разворота — slog.Error (диагностика «нулевых NPC» живого прогона), не только счётчик.
3. **world: окружение свёртки.** Группировка статических условий шага: тип
   `Env{Rules Rules; GM *geo.Map; Static *data.Static}` (заполняется в Wire + аргумент
   DeployNPCs), Fold-сигнатура: `Fold(tick, delta, rng, st, ents, portions, adv, env)` —
   8 аргументов (было 9, +static сделал бы 10). Static=nil толерантен: KindDeployNPCs →
   dead-letter. Ребро world→data — уже в матрице ADR-0005.
4. **world: разворачивание deploySpawns (чистая, в foldLetter).**
   - RNG разворота — собственный `rand.NewPCG(regionID, tick)` (D2 — буква спеки
     «RNG от (regionID, стартовый tick)»; изоляция от смещения точек потребления
     остальных стримов свёртки, P3.2/F2).
   - Фильтр среза (один режим): точечный спавн — 2D-дистанция точки до центра ≤ Radius
     (датапак-Z не фильтрует); территориальный — bbox территории ∩ квадрат радиуса
     (консервативно шире круга; следствие — часть NPC вне enter-радиуса, безвредно).
   - На запись: Npc-шаблон lookup (нет — skip-счётчик; fake-players без определения
     исключаются этим же путём — канон SpawnData.checkTemplate); статикой неспавнимые
     типы — skip-счётчик (SiegeGuard, RaidBoss — менеджерные спавны канона,
     SpawnTable.checkTemplate).
   - Count × позиция: Territory=="" → точка как есть, кроме Monster-поддерева: Z-коррекция
     гео NearestZ при |Δz| < 300 (канон Spawn.initializeNpc — монстры на устаревшем
     датапак-Z висят/тонут на живом прогоне); Heading −1 → бросок, иначе &0xFFFF;
     территориальный → Territory lookup (нет — skip), бросок x/y равномерно в bbox до
     попадания в полигон (лимит 64 попыток → skip; канон после 1000 возвращает точку
     вне полигона — наше усиление), banned-полигоны — 3D-проверка по вычисленному гео-Z;
     Z = GM.NearestZ({x, y, midZ}) с клампом в [MinZ, MaxZ] (сид midZ — канон
     ZoneNPoly.getRandomPoint; двусторонний кламп — усиление канона, у него только
     верхний); Heading — бросок rng (канон: Rnd.get(61794) при отсутствии heading,
     территория принудительно −1). periodOfDay (ночные/дневные) — спавним всегда:
     день/ночь-цикла нет, отклонение осознанное.
   - Birth{Ent: Entity{Pos, Heading, HP: 1, Npc: &NpcSkin{...}}}. NpcSkin — поля
     потребителя NpcInfo: TemplateID int32, Name, Title string, Attackable bool,
     CollisionRadius/Height float64, RunSpd, WalkSpd, SwimRunSpd, SwimWalkSpd, PAtkSpd,
     MAtkSpd int32, MoveMult, AtkSpdMult float64. Заполнение из data.Npc: скорости —
     raw-bag `stats.speed.run.ground`/`stats.speed.walk.ground` с floor-дефолтами канона
     run 120 / walk 50 (CreatureTemplate; floor вместо канон-санитизации ≤0 → 0.1 → кадр
     с нулём — отклонение, мотивированное нулевыми скоростями в кадре), Swim = Run/Walk
     (fallback канона), PAtkSpd — `stats.attack.attackSpeed` дефолт 300, MAtkSpd 333,
     MoveMult 1.0, AtkSpdMult 1.1 (дефолт простоя канона CreatureStat); Attackable —
     Type ∈ {Monster, RaidBoss, GrandBoss, Chest, FestivalMonster, RiftInvader,
     EventMonster, FeedableBeast, TamedBeast} (порт L2J_Mobius: setAutoAttackable(true)
     Monster-поддерева; Guard/FriendlyMob/Defender без флага — мирному наблюдателю false).
   - State: NPCDeployed, NPCSkipped (без шаблона/территории/лимит попыток) — счётчики в
     Dump; appendEntity — NpcID NPC-сущностей (машина по дампу обязана отличать NPC);
     slog разворота (deployed/point/territorial/skipped) — актор после applyEffects.
5. **replica: NPC-поля Record.** Без префиксов, примитивы без data-типов (матрица
   зависимостей replica←data не открывать): TemplateID int32, Title string, Attackable
   bool, CollisionRadius/Height float64, RunSpd/WalkSpd/SwimRunSpd/SwimWalkSpd/PAtkSpd/
   MAtkSpd int32, MoveMult/AtkSpdMult float64 (нули у игроков — как Race у NPC).
   recordOf: NPC-ветка заполняет из ent.Npc. Dirty-манифест ADR-0004 не меняется
   (гистерезис — фаза 4, см. F2).
6. **world: NpcInfo-ввод.** composeJoin EventIntroduce для RecordKindNPC: кадр NpcInfo из
   Record (ObjID=ObjectIDBase+Entity, DisplayID=TemplateID, Attackable, позиция/heading,
   все скорости/множители, коллизии, Name/Title, Running=false — канон: NPC не бежит при
   спавне) — WriteNpcInfo; ветка npcIntroduceSkipped умирает (метрика — счётчик вводов).
   Счётчик сущностей региона и NpcInfo при входе — в журнал живого прогона (КТ).
7. **cmd/l2go: wire-up.** static из artifact.LoadFile (сейчас отбрасывается); флаги
   -npc-center "x,y" (дефолт — persist.HumanFighter.Start* стартовая точка новичка,
   единый источник) и -npc-radius (дефолт 20000 ≥ enter 3500; КТ-1: владелец утверждает
   географию по гео-покрытию — конфиг без кода); порядок NewRegion → Wire → DeployNPCs →
   Run.
8. **Датчики/бенчи (обязательства вниз из P3.9; датчик, не ворота).**
   - BenchmarkRegionNPCStep 12k NPC + 100 наблюдателей — с под-бенчами фаз прямым вызовом
     харнесса (aoiStep/фаза A отдельно, прецедент прямого r.step() в bench_test.go):
     obs×N-скан join 12k×100 ≈ 1.2M итераций/шаг впервые измеряется (точка P3.9 шла с
     нулём наблюдателей); фазовые доли — из под-бенчей, в baseline + журнал.
   - Бенч «ввод×наблюдатели»: M наблюдателей рождаются в толпе k NPC, лестница плотности,
     кадры NpcInfo в метрике, ReportAllocs (пик входа в толпу — мотивировка радиуса,
     решение 8).
   - Сверка PublishBlob/FullPass/SteadyDirty против baseline P3.9 (рост Record на NPC-поля).
   - Первый шаг разворота (12k Births: Spawn- вставки, лог порций) — разовая цена,
     датируется в харнессе (StopTimer-обходы), в журнал.
9. **e2e.** Синтетика: спавны рядом со стартовой точкой (точечный + территориальный +
   count + banned + fake-id-без-определения), полигоны фикстуры — целиком внутри или
   целиком вне enter-радиуса (сид живого разворота зависит от тика первого шага —
   пересекающие границу полигоны делают точный count-ассерт флакающим); вход клиента →
   свойственный ассерт «каждый пришедший NpcInfo — в радиусе» по NpcInfoView, полнота
   набора — ассертом свёртки (сид фиксирован); логаут/вход — набор идентичен по id;
   l2client — ожидатель NpcInfo (NpcInfoView готов). Критерий детерминизма «два
   прогона → идентичные позиции» исполняется на уровне свёртки бит-в-бит (дампы двух
   вызовов, фикс. tick+static+письмо; прецедент TestFoldDeterministicBitExact); живая
   сверка — реплей P3.12.

Отклонения от спеки/обязательств (аргументация):

- Гистерезис записи Heading/Z (F91-минор «обязательство вниз при ботах») — ВЫЧЕРКНУТ из
  P3.10 в фазу 4: в задаче мёртв (NPC стоят, игроки меняют X/Y — dirty встаёт до всякого
  порога), а наивная реализация несла два дефекта (сравнение с prev вместо last-sent
  якоря; подавление Z-дельт останавливает пересмотр членства — Z входит в 3D-предикат
  enter/exit). Семантика dirty-манифеста ADR-0004 не тронута.
- Режим «имя зоны» (слэш-альтернатива спеки) — не реализуется: зоны датапака ⊆ круг,
  имя-не-ключ (дубликаты), потребитель один (КТ-1) и выражается центром+радиусом;
  гео-фрагмент владельца может не включать стартовую точку — центр обязан быть
  конфигурируем (в спеке центр фиксирован стартовой точкой). Добавление Zone-фильтра —
  фаза 4 по потребности, шов один (предикат среза).

S0-обязательство «точное число точечных спавнов в полном датапаке»: живой артефакт
владельца на этой машине отсутствует (в репо быть не может — NCsoft-данные); оценка
«порядка 12 тыс.» — решение 8 фазы 3 (обход P2.2). Точное число фиксируется живым
прогоном владельца (slog разворота несёт total/point/territorial/deployed/skipped) —
вопрос в выжимку S9.

## Тест-план (S6b)

Уровни по docs/testing.md §3; «e2e» = полный живой контур in-process (cmd/l2go), «компонентный»
