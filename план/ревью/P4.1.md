# Реестр находок P4.1

- Задача: Сетка ячеек AoI — подъём вырожденной конфигурации фазы 3 (internal/replica,
  internal/world). Досрочный слот фазы 4 по распоряжению владельца (2026-09-18, после
  нагрузочного датчика: квадрат join-скана — граница ~5000 движущихся); полный план фазы 4
  (грид регионов, хэндоффы, бой) — отдельно, задача от него не зависит.
- Ревью-профиль: S2 — инвариантщик, перформансер, доменщик (3 роли по слову владельца);
  S8 — + тестировщик.
- Бюджеты: план 0/2 · рестарты 0/2 · ревью реализации 0/3

## Финальный план (S0, выносится на ревью)

Механика — буква ADR-0004 осей 2–3: сетка глобальна и выровнена глобально (не по границам
регионов), ячейка ≥ радиуса обзора, подписка наблюдателя — константный стенсил 3×3, блоб —
SoA-сегменты по ячейкам, слоты стабильные плотные с детектом реюза по вечному id. Сегодня
сетки нет: одна ячейка на регион (aoiCell=0), join-скан — каждый наблюдатель × все слоты =
O(N²); нагрузочный датчик 2026-09-18: 20000 игроков → 1.4 с/шаг при бюджете 100 мс
(benchmarks/P3.10-player-load-baseline.txt).

1. **replica: геометрия сетки (Grid-инжект).** `Grid{MinX, MinY, CellShift}` — значение
   с методом `CellOf(x, y int32) CellID` (арифметика в int64: вычитание min и сдвиг без
   int32-переполнения; компактный uint32 gx<<16|gy, диапазон домена 0..127 на ось;
   поведение вне домена — детерминированный кламп координат до вычитания, описан
   поведением, не аналогией с geoOf). Grid конструируется в world (`replica.NewGrid`) из
   экспортированных geo-констант домена (geo правится: экспорт WorldMinX/WorldMinY —
   единый источник, дублей констант нет) и передаётся в NewPublisher/NewJoin — реплика
   гео не импортирует (матрица ADR-0005 чиста). Норма размера (вердикт доменщика):
   **cellSize ≥ Exit** (не ≥ Enter: гистерезисное кольцо (3500,4200] обязано целиком
   лежать в окне 3×3; канон L2J 4096 < 4200 — осознанно не копируем, квирк); дефолт
   8192 = 2¹³ ≥ 4200. Фабрик-инвариант cellSize ≥ cfg.Exit (ошибка конструирования при
   нарушении — защита от тюнинга фазы 6 в осцилляцию).
   - Свойство-инвариант «окно 3×3 покрывает членство»: цель вне окна наблюдателя ⟹
     дистанция ≥ cellSize+1 > Exit 4200 > Enter 3500 (любая геометрия позиций в своих
     клетках, включая диагональные — вердикт доменщика). Следствия: ввод невозможен вне
     окна; член, покинувший окно, гарантированно за Exit → Remove легитимен; гистерезис
     enter/exit по дистанции работает только внутри окна. Property-тест на границах
     ячеек, включая позиции у ±(2³¹−1).
2. **replica.Blob: сегменты по ячейкам (плотная укладка).** `segs []segment` —
   сортированный слайс по CellID (пустых ячеек нет); segment = {cell; slotOff, slotLen
   (срез в общий слайс слотов блоба)}; общий `slots []int` (глобальные слоты по
   возрастанию внутри сегмента) + `records []Record` параллельно общему слайсу —
   3–4 аллокации на блоб-тик при любом числе ячеек (без пула — фаза 6). Слоты остаются
   **глобальным единым пространством издателя** (Publisher.slots как сегодня):
   view/Apply/детект реюза не меняются. Манифесты member/born/changed — глобальные
   битмапы по слотам (как сегодня); gone-битмап после изъятия gone-веток (п.4) не
   читается потребителем — ОСТАВЛЯЕТСЯ осознанно (диагностика целостности поколений и
   существующие тесты пакета; изъятие — отдельной гигиенической правкой, не этой
   задачей). `seatBySlot []seat` (слот → {cell CellID; ent
   EntityID} жильца поколения; для свободного слота cell = сентинел **cellInvalid** — не
   нулевая клетка, ноль валиден; ent = 0) — O(1) array-indexed доступ единой чистки
   (п.4в; детект деспавна и реюза — F2/F11). Порядок сегментов и слотов детерминирован
   (сортировка) — реплей/дампы стабильны.
3. **replica.Publisher.Build.** Распределение записей по ячейкам позиций; слот выдаётся как
   сегодня (младший свободный), запись попадает в сегмент своей ячейки; prev-сравнение
   полных пейлоадов — по-прежнему по слотам глобально (changed-бит от смены ячейки
   возникает сам: запись изменила Cell). Смена ячейки сущностью = перегруппировка списков
   сегментов, слот жив; маркеры переезда/hold-last НЕ порождаются (переезд между ячейками
   внутри региона — не хэндофф; два случая ухода ADR-0004 ось 4 не затронуты).
4. **replica.Join: окно вместо мира; единая чистка хвоста.** Шаг наблюдателя: (а) окно =
   3×3 ячейки вокруг ячейки наблюдателя (window(obsCell); разрешение ячеек — бинарный
   поиск по сортированному segs, ~9×log(#ячеек) на наблюдателя); (б) fullPass
   новорождённого/changed-наблюдателя и dirty-цикл — по слотам сегментов окна: вводы
   (Enter/born), удержание (beyondExit/!Visible), апдейты (changed — фикс F47);
   **gone-ветка dirty-цикла изымается** (её случаи забирает (в)); (в) — единственный
   источник Remove по **слотовым** признакам (вне окна / сентинел / чужой жилец);
   дистанционный выход за Exit и невидимость (!Visible) живого члена окна остаются
   в (б) — гистерезисный случай «обе клетки в окне» (F12);
   (в) **единая чистка per-члена — единственный источник EventRemove**: для каждого
   члена view — seat слота вне окна ИЛИ cellInvalid (деспавн) ИЛИ seat.ent ≠ id из view
   (реюз слота новым жильцом) → ровно один EventRemove по вечному id из view. Хвост
   fullPass (join.go:280 сегодня — сравнение жильца) и gone-ветка dirty — заменены
   чисткой (в), не дублируются: двойной Remove за шаг исключён структурно (F6/F11);
   чистка (в) исполняется на ВСЕХ путях шага — события и примирение reconcile — иначе
   view-хвост после паник-окна не чистится. Детект членства — событийный по dirty-потоку
   в пределах окна: стоимость на наблюдателя O(слотов 9 ячеек + |view|),
   детерминированно от толпы вне окна.
5. **replica.Snapshot/Read.** Advisory Read(cell, id) — по сегменту ячейки (линейный поиск
   внутри сегмента вместо всего населения). Сигнатуры не меняются.
6. **world.** NewRegion конструирует Grid (replica.NewGrid(geo.WorldMinX, geo.WorldMinY,
   дефолт cellShift 13 — единая точка константы для фабрик-инварианта F3) и передаёт в
   NewPublisher/NewJoin; Grid хранится регионом для recordOf: Cell = grid.CellOf(x, y)
   (const aoiCell умирает); aoiStep/composeJoin/JoinConfig — без изменений.
7. **Числа.** cellSize 8192 ≥ Exit 4200 (канон PlayerKnownList: watch 3500/forget 4200 —
   OQ-3 закрыт P3.8); точный размер — фаза 6 по метрикам (ADR-0004 ось 2), 8192 —
   инженерный дефолт (степень двойки, 2× радиуса — окно 3×3 покрывает гистерезис с
   запасом).
8. **Датчики/бенчи.**
   - Нагрузочная лестница BenchmarkRegionPlayerLoad (до/после — та же методика):
     критерий-цель: 10000 кластеры50 ≤ 60 мс/шаг (сейчас 361 мс); 20000 — зафиксировать
     факт. Разложение прогноза (пересчёт ревью-перформансера по до-числам: кадр ≈ 60 нс,
     слот-итерация ≈ 3.4 нс, Build ≈ 0.56 мс/10k): кадры 29/59 мс (доминанта; слэб-пул —
     фаза 6) + скан окна fullPass при all-dirty 10–26 мс + чистка хвоста 1.5/3 мс +
     Build с сегментами 0.65/1.3 мс ⇒ 10000 ≈ 42 мс (38–50) — критерий с запасом; 20000
     ≈ 85 мс (78–95) — на грани бюджета, резерв 5–20% (записать как есть; толпа-1000 в
     одной ячейке не улучшается и не должна — фундаментальный N² кадров, стена
     ~1000–1700 в точке по ADR-0004 «Проверка»).
   - Фальсификатор «независимость от толпы вне окна» (тест-обязательство ADR-0004 фазы 4):
     население вне окна наблюдателя растёт на порядки — стоимость **изолированного
     Join.Step на наблюдателя** стабильна с точностью до log(#ячеек) (бинарный поиск
     segs); полный шаг не годится датчиком (Build линеен по всему населению).
   - До-базлайн join/PublishBlob перегнать на этой машине (P3.8-файл снят на windows —
     чужая машина, perf.md §0); сверка до/после на одном железе. Ожидание по Build
     (плотная укладка п.2): +3–4 аллокации на блоб-тик при любом числе ячеек; бюджет
     Idle-шага 15 → правка осознанная, с новой раскладкой в комментарии (OQ-3 закрыт
     числами).
9. **Тесты.**
   - Юнит-свойства: CellOf (границы клеток, края мира, детерминизм); сегментация блоба
     (записи по ячейкам, слоты глобальные, порядок сортирован); смена ячейки целью
     (перегруппировка, changed-бит, без маркеров).
   - Join-свойства: пара через границу ячеек (ввод по Enter, апдейт стрима, выход за Exit);
     выход цели из окна → ровно один Remove; реюз слота нового жильца: вне окна И в окне
     при covered-наблюдателе (двинувшийся наблюдатель + деспавн члена + рождение на его
     слоте — ровно один Remove старого по вечному id + Introduce нового, F11); возврат
     в окно → повторный ввод (после Enter); деспавн члена внутри окна → ровно один
     Remove (cellInvalid, F2); после паник-окна — примирение доезжает чистку (в); наблюдатель пересекает границу ячейки — окно едет, известность
     не мерцает (член новой кромки вводится, ушедшей — Remove; смена окна — дальняя
     кромка ≥8193, члены ≤4200 не задеты); гистерезис-дуга на краю Enter — нулевой чурн
     (перенос P3.8 на сетку); covered-наблюдатель в окне (твин F47).
   - Property set-equality на сетке (тест-обязательство ADR-0004, обобщение вырожденного
     «по населению региона»): случайные расстановки/перемещения/деспавны в нескольких
     ячейках — view каждого наблюдателя == эталонная функция членства (дистанции
     Enter/Exit, гистерезис) после каждого шага; ловит рассинхрон чистки и вводов.
   - Вырожденная конфигурация: все записи в одной ячейке — все существующие тесты join/
     region без правок (закон оси 6); прогон полного пакета — регрессий нет.
   - e2e: движущаяся пара через границу ячеек — CharMoveToLocation продолжает доставляться
     (живой контур, синтетика: расставить спавны/маршрут через границу 8192).
10. **Скоуп-границы (не входит).** LOD-тиры, per-client outbound budget, дельта-пейлоады,
    пулы/encode-once (фаза 6); хэндоффы регионов, затравки, маркеры переезда, слуги,
    предметы лёгкого класса, инстанс-пространства (прочая фаза 4); изменение JoinConfig
    (радиусы канона не трогаем).

Открытые вопросы — закрыты ревью раунда 1 (вердикты в «Раундах»):

- OQ-1 закрыт: норма cellSize ≥ **Exit** (гистерезисное кольцо целиком в окне 3×3; канон
  L2J 4096 < 4200 — квирк, не копируем); 8192 = 2¹³; фабрик-инвариант связки (F3).
- OQ-2 закрыт: gx<<16|gy (диапазон домена 0..127 на ось — запас до cellSize 2048 фазы 6);
  вычисление в int64, кламп вне домена (F9/F10).
- OQ-3 закрыт числами: плотная укладка сегментов — 3–4 аллокации на блоб-тик при любом
  числе ячеек (F7); бюджет Idle-шага — осознанная правка с раскладкой.
- OQ-4 закрыт: чистка O(|view|) ≤ O(слотов 9 ячеек) по свойству п.1 (каждый член — в
  окне); в толпе ~1–2 мс на 1000 — в разбросе (вердикт перфомансера).
