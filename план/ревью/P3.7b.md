# Реестр P3.7b — bufpool в энкод-стадии (мини-задача по распоряжению владельца)

- Контекст: обязательство P1.2 («энкод-стадия фазы 3 — первый живой потребитель
  bufpool; датчик владения (Gets−Overflows)−Puts») не исполнено при реализации
  P3.6 (per-client возврат без пула, отклонение не записано — пропуск).
- Режим: план → 3 независимых ревьюера → реализация → ворота (распоряжение
  владельца от 2026-09-16).
- Профиль: код encode/conn; аргументация каждого решения обязательна.

## План (аргументы и отвергнутые альтернативы)

### D1. Пул — на границах, per-client spare остаётся горячим циклом

- push: слэб из spare (первый cap ≥ wireLen, как сегодня); МИСС →
  `pool.Get(wireLen)` (бакетная ёмкость; wireLen > 4096 — overflow-ветка
  Get, прямая аллокация, датчик Overflows).
- Отдача: Recycle финального батча, Put очереди/spare при смерти клиента,
  trim spare (D3).
- **Аргумент против пер-кадрового Get/Put**: контракт bufpool требует
  `clear()` всей ёмкости бакета при каждом reuse-Get — для 4К-бакета это
  ~0.5–1 мкс memset + трафик памяти НА КАЖДЫЙ КАДР стационара. Текущий
  0-аллокационный цикл (слэб живёт в spare и перезаписывается только в
  [:wireLen]) не платит этого вовсе. Пул на границах платит clear только там,
  где иначе была бы свежая аллокация (чурн/бёрст) — т.е. бесплатно относительно
  статус-кво.
- Отвергнуто: полный отказ от spare (пер-кадровые Get/Put) — регресс горячего
  пути; «оставить как есть + отклонение» — распоряжение владельца «подключай».

### D2. Владелец пула — Stage (нулевое значение bufpool.Pool)

- `Stage.pool bufpool.Pool` — поле, не глобал; NewStage без изменений
  сигнатуры. Одна стадия на процесс (сегодня); изоляция Stats в тестах
  (каждый NewStage — свой пул → дельты датчика детерминированы).
- Отвергнуто: глобальный пул (скрытая зависимость, тесты недетерминированы);
  пул в cmd с инъекцией (мок ради мока — скоуп не тянет).

### D3. Trim возврата spare: бюджет spareKeepBytes = 8 КиБ

- Take, возвращая prev в spare, держит слэбы, пока сумма cap ≤ spareKeepBytes;
  излишек — `pool.Put` (кросс-клиентское переиспользование; иначе бёрст 256 КиБ
  у медленного читателя паркуется у клиента навсегда).
- 8 КиБ покрывает слиток входа (~1.5–2 КиБ) с запасом; константа encode
  (флагов не разводим — тюнинг по профилю фазы 4).
- Отвергнуто: без trim (парковка памяти на тихом клиенте после бёрста);
  trim по количеству слэбов (смешанные бакеты дают непредсказуемый байтовый
  след).

### D4. Put только слэбов с бакетной ёмкостью — контракт соблюдён

- Источник слэбов теперь только pool.Get → cap ∈ {128..4096} либо overflow
  (cap == wireLen, небакетная — Put отбросит молча, посчитано Overflows у
  Get). make() из takeSpare удаляется вовсе — единственный источник Get.
- Слайфы из Get хранятся/передаются целиком-владением: reslice [:n] не
  урезает cap (Put принимает по cap) — буква контракта («проекция с урезанной
  ёмкостью — нарушение») не нарушается: cap сохраняется.

### D5. Замыкание владения финального батча: шов conn.Outbound + Recycle(prev)
<!-- тело ниже в частях отменено правками R3/R4 (прямой Put без spare;
defer-стек writeLoop/обёртки; StageOutbounds не трогается) — верифицировано
автором находки;留着 как история -->

- Проблема: write-горутина на close-выходе держит последний батч в локале
  `prev` — Unregister его не видит → датчик (Gets−Overflows)−Puts навсегда
  терял бы ~батч на каждый дисконнект (датчик владения — вся суть P1.2).
- Решение: метод `Recycle(prev [][]byte)` в потребителе шва conn.Outbound;
  writeLoop: `defer func() { out.Recycle(prev); out.Unregister(id) }()`
  (захват prev замыканием — финальное значение). Recycle: nil-safe,
  идемпотентный по владению (после вызова prev мёртв), пишет в spare-trim/
  пул записи клиента; после Unregister — просто в пул стейджа.
- Обратная сторона: +1 метод интерфейса → правка обёртки gateway.StageOutbounds
  и тестовых фейков conn (механическая). Отвергнуто: смириться с дефицитом
  датчика (обесценивает задачу); передавать батч через Unregister(id, prev)
  (меняет семантику существующего метода, все вызовы).

### D6. Recycle при ошибке записи — легален

- Write-ошибка: prev = недописанный батч; байты мусорны, но владение цело —
  Recycle в defer корректен для обоих выходов writeLoop (close и error).

### D7. Криптоблок и переиспользование — утечек нет

- Тело шифруется инплейс; после записи слэб несёт шифротекст СВОЕГО клиента.
- Кросс-клиентская передача безопасна: push перезаписывает [:wireLen] целиком
  (заголовок+копия), хвост ёмкости никогда не читается; pool.Get обязан
  clear() весь cap при reuse (контракт) — двойная защита.

### D8. Лок-дисциплина
<!-- «Put в Unregister — под s.mu» отменено R1: дрен под c.mu после
снятия из карты -->

- Get в push — под c.mu; Put в Take — под c.mu; Put в Unregister — под
  s.mu. sync.Pool неблокирующ (буква контракта стейджа «никогда не
  блокировать»); цены Put/Get ~десятки нс, вне горячего цикла (D1).

### D9. Датчик в Stats стейджа

- StageStats += PoolStats bufpool.PoolStats (снимок трёх Load — неатомарная
  тройка, оговорка контракта bufpool переносится). Инвариант для тестов и
  эксплуатации: (Gets−Overflows)−Puts == 0 после полного тирдауна всех
  клиентов.

### D10. Документация

- Пакетный doc encode: «возврат слэбов обменом при Take» → + «границы
  (мисс spare / смерть клиента / trim) — общий бакетный пул»; комментарий
  Unregister («слэбы уходят сборщику») переписан; матрица ADR-0005 без правок
  (ребро encode→pkg/bufpool существует с P0.9).

### Порядок реализации (TDD)

1. Красные: TestStagePoolOwnershipBalance (N клиентов × кадры ×
   take/close/recycle → (Gets−Overflows)−Puts == 0); TestStageSpareTrim;
   TestStageUnregisterPutsQueue; TestConnRecycleFinalBatch (фейк-аутбаунд
   считает Recycle); TestStageCrossClientReuse (слэб умершего клиента
   обслуживает нового — Gets не растёт при живом бакете).
2. encode: pool-поле, takeSpare → Get-фолбэк, trim, Recycle, Unregister-Put,
   Stats.
3. conn: Outbound.Recycle + writeLoop defer; StageOutbounds-обёртка; фейки.
4. Ворота покомпонентно + существующие 0-аллок-гейты обязаны остаться
   зелёными (spare-хит не платит ни аллокаций, ни атомиков).
5. Бенчи encode P3.6 — контрольный прогон (стационар не меняется).

### Критерии приёмки

- (Gets−Overflows)−Puts == 0 после тирдауна (владение замкнуто).
- 0-аллок-тесты стационара зелёные (TestGatewayDrainAllocBudget и
  encode-бюджеты P3.6).
- Бенчи encode в пределах шума baseline P3.6.
- Ворота зелёные; race чист.
- Запись в журнал; реестр P3.7 дополняется ссылкой (закрытие обязательства
  P1.2 в фазе 3).

## Ревью 3 агентов → правки (ред. 2)

Вердикты: конкурентщик — ядро D1–D4/D6/D7/D10 состоятельно, 1 мажор (гонка
Push×Unregister) + 4 минора; перформансер — D1 вывод верен, арифметика
опровергнута измерением (F1), мажор F3 (трим-чёрн не покрыт бенчами);
прагматик — план состоятелен, 0 мажоров, 6 миноров. Правки внесены:

- **R1 (закрытие мажора, конк#1): dead-флаг + дрен под c.mu.** Семантика
  abort однозначна: dead ⇒ ПОЛНЫЙ откат push — без pool.Get и без append
  («откат до Get» переоткрыл бы окно); возврат три-стейтом, dead-аборт
  НЕ считается capDrop (метрика переполнения не врёт). Unregister:
  delete из карты под s.mu → c.mu → c.dead=true → Put очереди и spare →
  unlock. push: под c.mu первым делом сверяет dead — мёртвой записи слэб
  НЕ берётся (откат без pool.Get) → TOCTOU-окно закрыто, датчик не течёт;
  дрен под c.mu исключает data race (буквальный D8 отменён).
- **R2 (конк#2, паника-раскрутка Take): переупорядочение + defer-unlock.**
  Take: криптоблок ПО очереди выполняется до возврата prev в spare и до
  переиспользования носителя prev (два прохода по очереди — цена прохода по
  указателям ничтожна); разблокировка — defer. Паника в крипте → c.mu
  отпущен, prev нетронут (владение у вызывающего) → unwind: Recycle(prev)
  → прямой pool.Put (без локов) → Unregister дренит очередь/spare (prev
  там нет — двойного Put нет) → процесс падает чисто (let-it-crash).
- **R3 (конк#5 + перф-F2): Recycle — прямой Put, без spare/trim.** Recycle
  зовётся только из defer writeLoop (клиент умирает — Unregister следом):
  слэбы финального батча идут прямо в пул стейджа, локов нет, nil-safe,
  контракт «однократность на вызывающем; после вызова prev мёртв» (не
  «идемпотентный» — Н6). client получает указатель пула при Register.
- **R4 (конк#4/Н4): механика D5 по факту кода.** Recycle — defer ВНУТРИ
  writeLoop; Unregister остаётся в defer обёртки write-горутины; порядок
  гарантирован стеком defer'ов на обоих выходах (close и ошибка записи).
  StageOutbounds НЕ трогается (реализует Outbounds, не Outbound): правятся
  conn.Outbound (+1 метод), *client (encode), fakeOutbound (conn_test).
- **R5 (перф-F1/Н1): арифметика D1 исправлена.** Полный цикл Get+clear+Put:
  128Б — 10.5 нс, 4096Б — 37.9 нс (параллельно ×~1.9); доминирует
  фиксированная часть sync.Pool+атомиков, НЕ memset (моя «0.5–1 мкс» была
  ценой свежей make(4096)≈438 нс — того, что пул избегает). Вывод D1
  выживает: пер-кадровый пул = +10–38 нс на кадр (+45–90% мелкого кадра
  40Plain ≈22 нс, +4% у 1.4КБ) + атомики общего пула на стационаре.
- **R6 (перф-F2): бегущий счётчик c.spareCap** — обновляется при
  добавлении/удалении, пересуммирования на каждый Take нет.
- **R7 (перф-F4): матчинг best-fit** — наименьший достаточный cap (≤64
  записи, дёшево) вместо first-fit: мелкий кадр не ест 4096-бакет.
- **R8 (перф-F3/Н5): трим-чёрн-режим записан и измерен.** Клиент со
  стационарным следом > 8 КиБ платит pool-раундтрип на каждый батч
  (Get+clear+Put ~10–38 нс/слэб, параллельно ×2) — осознанный трейд
  «память ↔ цикл»: без трима бёрст паркует до byteCap (256 КиБ × 20к
  коннектов ≈ до 5 ГиБ). Бенч через границу добавлен (254Б × 70 кадров,
  след ≈ 17.9 КиБ).
- **R9 (Н2/конк#3): оракулы тестов переформулированы** — баланс
  (Gets−Overflows)−Puts==0, AllocsPerRun==0 на reuse-цикле, рост Puts;
  «Gets не растёт» убрано (противоречит контракту: Gets считает каждую
  выдачу).
- **R10 (Н3): тест-план дополнен** — кадр >4096Б в баланс-тесте
  (Overflows-ветвь и молчаливый отброс Put испытаны, член −Overflows
  живой); error-выход writeLoop — внутренний тест conn (writeLoop напрямую
  с падающим net.Conn-стабом + fakeOutbound считает Recycle→Unregister
  порядок); слоистость: conn проверяет контракт шва (фейк), encode —
  реальный Recycle.
- **R11 (перф-F5): критерии приёмки операционализированы** — benchstat
  против benchmarks/P3.6-encode-baseline.txt, -count=10, пороги perf.md;
  0-аллок-гейт — TestStageAllocBudgets (encode); заявка про
  TestGatewayDrainAllocBudget снята (не касается encode).

## Реализация (S-финал)

Encode: Stage.pool (нулевое значение), client.pool/spareCap/dead; takeSpare —
best-fit + Get-фолбэк; Take — defer-unlock, криптоблок до возврата prev,
трим бюджета 8 КиБ (излишек Put); Recycle — прямой Put без локов; Unregister —
дрен очереди/spare под c.mu с dead-флагом; push — три-стейт (dead-аборт не
считается capDrop); StageStats += PoolStats. Conn: Outbound.Recycle,
writeLoop defer Recycle (оба выхода). fakeOutbound — счётчик. Матрица:
gateway/world + pkg/bufpool (транзитивно через encode).

Тесты: баланс владения (вкл. overflow-кадр >4096), трим, best-fit (волны,
Gets==4), кросс-клиент 0 AllocsPerRun, Recycle-замыкание, фальсифицируемость
(утечка видна), гонка Push×Unregister (dead-аборт), шов conn (close- и
error-выходы). Бенч: PushTakeOverBudget (трим-чёрн, ~10 мкс/волна 70 кадров).
Стационар бит-в-бит baseline P3.6 (40Plain 23.6–24.0 vs 23.3–26.3; 256Crypt
123.7–126.4 vs 123.7–126.7; 0 аллок). Ворота: 22 ok, race чист, staticcheck/
checkdeps чисты.
