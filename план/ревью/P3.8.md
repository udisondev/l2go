### Факты канона (сверка S0; L2J Interlude — зеркало L2JServer_C6_Interlude, GPL)

- **Радиусы (OQ-3):** PlayerKnownList: watch/forget по тирам размера knownlist:
  ≤25 → 3500/4200 («пустое поле»), ≤35 → 2900/3600, ≤70 → 2300/2910, >70 → 1700/2310
  («осада, TOI, город»); канонный комментарий: forget ≥ watch, иначе
  «watch-forget-watch-forget» (осцилляция). Адаптация по размеру knownlist — механизм
  деградации под толпу (аналог бюджета оси 5) — фаза 6; фаза 3 фиксирует пару тира
  «пустое поле»: enter=3500, exit=4200.
- **Дистанционность (OQ-8):** WorldObjectKnownList.addKnownObject — чистая проверка
  `Util.checkIfInRange(watch, active, object, true)` (3D, включая Z); гео-LOS в
  knownlist-потоке отсутствует → исключение LOS из предиката репликации подтверждено
  каноном; LOS живёт в advisory-событиях (аггро/скиллы) — фазы 4+.
- **Вводы/удаления:** addKnownObject — игроку игрок → CharInfo, NPC → NpcInfo
  (саммоны/петы/предметы — фазы 4–5); removeKnownObject → DeleteObject — сервер
  шлёт безусловно, не отслеживая знание клиента: повторный ввод и удаление
  неизвестного клиенту id толерантны формату (ввод — обновление, удаление
  отсутствующего — no-op) — качество формата, опора ресинка/доктора. Повторный
  ввод после ухода — пакет ввода шлётся заново (OQ-5 — качество формата, не
  предпосылка корректности с v1.4). Продвижение состояния движения известного —
  describeStateToPlayer (CharMoveToLocation) — P3.9.
- **Абсолютность апдейтов (OQ-7):** известностные пакеты канона несут полные
  координаты/состояние (CharInfo/CharMoveToLocation/describeStateToPlayer —
  абсолютные значения, инкрементальных knownlist-пакетов нет); блокирующая
  проверка реестра полного потока — фаза 4 (сви-детектор «K∩M без ре-спавна»).
- **Событийность:** канон — периодический скан видимой области (updateKnownObjects =
  findCloseObjects + forgetObjects); событийный детект (спавн/деспавн/dirty) — решение
  ADR-0004 ось 2, семантика членства та же — запись-расхождение формы.
- **Задержка вводов:** канон шлёт вводы асинхронно с нарастающей задержкой 100 мс
  +Rnd (сглаживание сетевых шипов) — фаза 3 без задержек (троттлинг — фаза 6),
  запись-отклонение.
- OQ-1 (труп пета), OQ-2 (детект-инвиз), OQ-6 (мгновенность DeleteObject при
  телепорте) — потребители/механизмы в фазе 3 отсутствуют структурно (слуг, инвиза,
  телепортов нет); референс-сверка — фазы 4+ при появлении механизма.

### Решения (ред. 2)

1. **Пакет replica: блоб/издатель/join/advisory, без горутин** (ADR-0005: библиотека
   внутри региона). Поверхности (эталон — решение 6):
   - `Record` — полный пейлоад AoI-записи (значение): Entity (вечный ID), Cell
     (CellID — вырожденная сетка: одна ячейка), X/Y/Z int32, Heading, Moving, Kind
     (RecordKindPlayer/RecordKindNPC), Flags (входы предиката; фаза 3 — синтетический
     флаг шва), поля потребителя CharInfo (Name, Race, Female, BaseClass, ClassID,
     HairStyle/HairColor/Face). NpcInfo-поля — P3.10 дополнит.
   - `Blob` — иммутабельный per-owner блоб: несёт Generation (номер поколения) и
     BaseGen (поколение-база dirty-манифеста; норма BaseGen = Generation−1 —
     манифест есть дифф prev→next); сегмент ячейки
     (Records []Record, слот = индекс; дырки — нулевые записи + битмап Member),
     Dirty-манифест (Born/Changed/Gone — битмапы слотов), MembershipHeader
     (генерация, Moving []EntityID — маркеры переезда: тип присутствует, фаза 3
     всегда пуст). Форма сегмента — массив значений Record + отдельные битмапы
     (последовательный скан; колоночный SoA — фаза 6 по измерениям, запись-отклонение
     О-7). Блоб строится на свежих аллокациях: Build копирует значения записей во
     внутренние массивы — входной слайс мира переиспользуется без алиасинга
     опубликованного поколения. Поля Blob неотэкспортированы (решение 6).
   - `Publisher` — строитель у владельца: стабильные плотные слоты (слот присваивается
     при первом входе записи, освобождается при уходе, реюз — младший свободный;
     детект реюза — вечный id в слоте), map EntityID→слот + free-list (издательская
     сторона: per-record, не per-pair — контракт оси 3 не нарушает). API:
     `Build(recs []Record) *Blob` — построение поколения + dirty сравнением с
     предыдущим (полные пейлоады: честный dirty без событийной бухгалтерии — ловит
     и смену Flags; события позиций P3.9 могут уточнить по бенчу); внутреннее
     состояние издателя (слот-карта, free-list, prev) мутируется ТОЛЬКО при успешном
     завершении Build (построение во временные структуры, мутации издателя нет
     вовсе); `Commit(b *Blob)` — атомарная публикация с запинненным порядком:
     СНАЧАЛА продвижение prev (базы будущего манифеста), ПОТОМ свап опубликованного
     (паника внутри Commit оставляет согласованную пару view/prev; опубликованное
     может отстать на поколение — безвредно, читатели теряют одно поколение);
     вызывается регионом в фазе publish — дисциплина «свап после шага»;
     `Read(cell CellID, id transport.EntityID) (Snapshot, bool)` и
     `Committed() *Blob` — читают закоммиченное поколение (advisory-точечное чтение —
     линейный поиск по сегменту; потребители фазы 3 нет, чтения per-candidate редки —
     aux-индекс по измерениям, база — бенч F4).
   - `Join` — view set наблюдателей у владельца. **Контракт оси 3 переносится в
     Join: доступ на пару (наблюдатель, цель) — только O(1) array-indexed по слотам
     сегмента; хеш-lookup на пару запрещён.** View set наблюдателя — плотный
     слайс/битмап по слотам сегмента + вечный id на слот (детект реюза слота тот же,
     что у издателя); собственная позиция наблюдателя — из его записи в том же
     сегменте. API: `NewJoin(cfg JoinConfig)`, `Step(obs []Observer, blob *Blob)
     []Event` (Observer{Entity, ConnID}; Event{Obs Observer, Target Record, Kind} —
     ConnID только в Obs), `Apply()` — применение стадированных диффов к view set.
     **Step НЕ мутирует view set — стадирует диффы** (первым действием сбрасывает
     стадинг; паника внутри Step ⇒ частичный стадинг мёртв — никто его не читает до
     возврата); возвращает слайс событий для компоновки. **Примирение поколений
     (механический детект, не флаг):** Join хранит appliedGen — поколение блоба, к
     которому применён view; начальные значения: appliedGen₀ = BaseGen(пустого
     prev) = 0 (первый шаг — вырожденное примирение = первичное заполнение,
     безвредно). **appliedGen продвигается ПЕРВОЙ операцией Apply** (до применения
     стадинга): бинарное покрытие окон фазы — паника до начала Apply ⇒ базы равны,
     view нетронут, событийный пере-вывод; паника после начала Apply (включая
     частичную) ⇒ базы разошлись ⇒ примирение — полный эмит покрывает любую
     степень применённости стадинга. В начале Step сверяет
     next.BaseGen с appliedGen: расхождение ⇒ ОДИН полный примирительный проход с
     ПОЛНЫМ эмитом: Introduce ВСЕМ next∩радиус (повторные безвредны по канону —
     лечит и «мутация применена, кадр не слит/не доставлен», и флип-флопы с
     нетто-нулевой дельтой к prev), Remove всем view\next (закрывает «рождение+уход
     в окне»), дроп view умерших наблюдателей; O(M×N) разово после паники,
     стационарно бесплатно (одно сравнение поколений); совпадение баз — обычный
     событийный путь. Тестовый шов `Join.ForcePanicInApply` — ЭКСПОРТИРОВАННОЕ поле
     (паника на первой итерации применения стадинга; выключено по умолчанию,
     прецедент Region.forcePanic; входит в API-эталон решения 6 с пометкой
     «тестовый шов» — компонентный world-тест ставит его напрямую).
     **Apply вызывается регионом ДО
     merge кадров** (порядок фазы
     AoI — решение 2): паника в фазе AoI ⇒ r.joinPushes шага дропаются — кадры
     неподтверждённого стадинга не доставляются, события пере-выведутся
     манифестом/примирением. Инварианты окна: «мутация применена ⇒ кадр слит»
     (merge после Apply) и «кадр доставлен ⇒ стадинг применён» (дроп joinPushes до
     merge) — обе стороны сходятся примирением/пере-выводом.
     Протокольных знаний нет (матрица: replica ← transport).
   - `Visible(obs, tgt Flags) bool` — **одна функция предиката пары для обоих
     потребителей** (репликация внутри Join; advisory-потребители фазы 4 обязаны
     прогонять пары через неё). Слим-вход по Flags — ровно то, что дают
     Snapshot-аксессоры и Record.Flags: advisory-потребитель физически может
     вызвать ту же функцию без фабрикации полей; радиус в предикат не входит
     (членство), координаты — не нужны (LOS отсутствует, OQ-8). Расширение входов
     (LOS/детект фазы 4+) — эволюция сигнатуры с обоими потребителями разом.
2. **Регион: фаза AoI в шаге.** `r.outbox = append(r.outbox, res.Out...)` — сразу
   после Fold, ДО applyEffects (письма свёртки шага переживают любую панику
   последующих фаз в outbox). Новая фаза между phaseLog и phaseB, порядок операций:
   (а) сбор next-блоба `r.nextBlob = publisher.Build(recs)` — Build строит во
   временные структуры и НЕ мутирует издателя вовсе (слот-карта/free-list/prev
   продвигаются только в Commit); (б) `r.events = join.Step(obs, nextBlob)` —
   события (стадинг диффов внутри Join; слайс — для компоновки); (в) компоновка
   `r.joinPushes = composeJoin(events)` — чистая функция событий, полный проход;
   (г) `join.Apply()` — применение стадинга к view set (ПЕРВОЙ операцией продвигает
   appliedGen — бинарное покрытие паник-окон, решение 1); (д) merge:
   `pendingPushes = append(pendingPushes, r.joinPushes...)` — слив ТОЛЬКО
   применённого стадинга. Паника в любой точке
   (а)–(г) ⇒ r.joinPushes шага дропаются (кадры неподтверждённого стадинга не
   доставляются — курсор их не видит; слитки/fold-кадры доставляются как раньше);
   Commit не случился ⇒ манифест следующего шага диффуется от незакоммиченного
   prev ⇒ полный ⇒ события пере-выведены с неприменённого view — без потерь,
   дубли безвредны по канону. Доставка фазы B идёт по курсору `r.pushCursor` —
   индекс первого недоставленного кадра pendingPushes (инкремент после каждого
   pusher.Push); **resetDrain — долговечный хвост**: недоставленное
   pendingPushes[pushCursor:] переносится в голову следующего шага (курсор в 0;
   per-client FIFO сохранён) — потеря кадров структурно невозможна, сброс слайса
   без переноса запрещён. phasePublish: `publisher.Commit(nextBlob)` — публикация
   свапом + продвижение prev издателя (заготовка snapshot удаляется; тест
   публикации region_test переносится на блоб; примечание: вставка phaseAoI
   сдвигает числовые коды поздних фаз в LogPanic-маркерах — золотых лог-фикстур и
   реплей-харнесса нет, формат маркеров паник не стабилизирован; phAoI-счётчик и
   RegionStats.PhaseAoI — по прецеденту phDrain…phAck). Порядок: решение об уходе
   (Fold/applyEffects) предшествует компоновке AoI — ушедший не наблюдатель и не
   цель; проводной порядок кадров на клиента: слиток → join-кадры → письма B
   (per-client FIFO Stage сохраняет порядок; Stage.Push мёртвому/неизвестному —
   молча). Наблюдатели (obs) — скан residents с фильтром живых игроков
   (Player ≠ nil, не Leaving/EnterLeaving; состояние известно региону) в
   переиспользуемый obs-буфер.
3. **Событийный join + гистерезис.** Join.Step обрабатывает: dirty-манифест блоба ×
   наблюдатели (Born→проверка enter-радиуса и предиката; Changed→переоценка пары:
   выход за exit / позиционный Update / ввод не-члена; Gone→Remove без маркера);
   рождение наблюдателя — полный проход сегмента (первичное заполнение view set,
   O(население) один раз); смерть/уход наблюдателя (Gone его слота) — дроп его view
   set; Changed самого наблюдателя (движение) — полный проход его пар с диффом view
   set. Гистерезис: вход при
   d²≤enter², выход при d²>exit², между — удержание; дистанция 3D по канону,
   int64-арифметика с отсечкой дальних: |dx|,|dy|,|dz|>exit до возведения в квадрат
   (три сравнения — и переполнение исключено, и дальние дешевле). Предикат —
   Visible(obs, tgt) (решение 1; obs-флаги — из записи наблюдателя в сегменте —
   Observer{Entity, ConnID} флагов не несёт); смена флага записи = Changed →
   переоценка: →false = Remove, →true = Introduce; переоценка члена без изменения
   членства (кольцо enter<d<exit, повторный вывод полного манифеста после паники)
   эмитит НОЛЬ событий — опора «ровно один ввод/удаление» и стабильности
   трафик-лога. Конвенция манифеста при реюзе слота в одном поколении (деспавн X +
   рождение Y): Gone-бит = «id слота в prev ≠ 0 и ≠ id в next», Born-бит = «id в
   next ≠ 0 и ≠ prev» — на одном слоте оба бита; view-детект по вечному id
   различает: Remove(X) эмитится детектом реюза, Introduce(Y) — по Born. Self-пары
   пропускаются. Радиусы — JoinConfig{Enter,
   Exit} из CanonJoinConfig() (3500/4200, атрибуция L2J PlayerKnownList, тир «пустое
   поле»); тесты инъектируют свои. Регион конструирует Join жёстко с
   CanonJoinConfig() — конфигурационной поверхности радиусы фазы 3 не получают
   (тюнинг — фаза 6); компонентные тесты — на канонных числах, юниты — на
   инъецированных. Обходы детерминированы (наблюдатели по Entity,
   слоты по индексу) — для тестируемости, не реплея.
4. **Компоновка кадров (мир, world/aoi.go).** Introduce+игрок → CharInfo (CharInfoData:
   поля Record + шаблонные константы HumanFighter — как UserInfo P3.7; MaxCp/CurCp=0 —
   запись-отклонение О-6); Introduce+NPC → счётчик+журнал (наполняет P3.10); Remove →
   DeleteObject (objID = encode.ObjectIDBase+Entity); Update → no-op-заглушка с
   комментарием P3.9. Пуши — pendingPushes (Crypt=true). Self-поток — вне join
   (слиток P3.7). CharInfo-плейсхолдеры скоростей/коллизий — константы шаблона
   HumanFighter (persist), как UserInfo P3.7; точные значения байтов фиксирует
   golden-тест по прецеденту P3.5. Scratch-буферы (recs []Record, obs []Observer —
   поля региона; events []Event — слайс-вид стадинга Join, мир между шагами не
   хранит) переиспользуются между шагами (0 аллок стационарно, прецедент
   drain-буферов); осознанная правка машинного аллок-бюджета Idle-шага (блоб на тик
   = Blob+Records+битмапы — точное число пиннится в тесте) — с аргументом в
   комментарии.
5. **Advisory (D4-шов).** Точечное чтение — Publisher.Read (решение 1). Snapshot —
   непрозрачное значение: поля неэкспортированы, аксессоры возвращают копии
   примитивов (Entity/Pos/Kind/Flags; Pos() — тройка (x, y, z int32); Epoch сида —
   дублирует Generation заголовка, сносится: реальная эпоха записи появляется с
   переездами фазы 4 — тогда и вернётся аксессор). Логирование: мир оборачивает
   источник в logAdviser{src, sink *[]AdvisoryIn} — каждое чтение дописывает
   AdvisoryIn{Cell, Entity} в adviseBuf шага → LogStep (N чтений = N записей).
   **world.AdvisoryIn = replica.AdvisoryInput (алиас типа)** — обязательство P3.2
   сведено; битовое представление (uvarint Cell+Entity) и portionVersion (2) не
   меняются. Обёртка — поле региона; контракт окна: механика шва бьёт ТОЛЬКО
   верхнюю границу — чтение после LogStep = паника шва (advisory есть вход свёртки:
   чтение после LogStep попало бы не в свою порцию); «только из свёртки» до
   LogStep — дисциплина потребителя (чтение из applyEffects механически попадёт в
   порцию шага — расхождение live/реплей исключается потребителем фазы 4, не
   швом). Значение чтения в порции —
   обязательство фазы 4 (первый реальный потребитель); шов реплея (live/записи) —
   интерфейс, заглушка реплея — P3.12.
6. **Приватность view set (машинно).** Join-состояние — поле региона (actor-owned), в
   Fold не передаётся, в Dump не входит, формат лога не меняется — бит-в-бит реплей
   P3.7-сценариев не трогается. Типы view — неэкспортированы в replica; поля Blob
   (Generation/Records/манифест) — тоже неотэкспортированы: внешний читатель
   (мир/фаза 4) идёт через Committed()/Read/события — механическое исполнение
   D4-запрета прямого дереференса снапшота, сильнее конвенции (внутренние
   потребители — Join и пакетные тесты — читают поля напрямую). Пакетный тест
   API-поверхности: go/doc-разбор пакета replica, эталон экспортированных имён
   (полный перечень, включая конструкторы и методы): типы CellID, Record, RecordKind
   (RecordKindPlayer, RecordKindNPC), Blob, Publisher, Join, JoinConfig, Observer,
   Event, EventKind (EventIntroduce, EventRemove, EventUpdate), Snapshot,
   MembershipHeader, GroundItem, Advisory, AdvisoryInput, Flags; функции
   CanonJoinConfig, Visible; методы NewPublisher, Publisher.Build, Publisher.Commit,
   Publisher.Read, Publisher.Committed, NewJoin, Join.Step, Join.Apply; тестовый шов
   Join.ForcePanicInApply (поле, пометка «тестовый шов»);
   аксессоры Snapshot (Entity / Pos — тройка int32 / Kind / Flags), Record/Event-поля
   как значения. Утечка view-типа или новые экспорты = красный тест.
7. **Паника фазы AoI — структурная гарантия: стадирование + Apply-после-приклейки +
   полный манифест + примирение поколений + долговечный хвост.** Доктор событий,
   Events(), joinAttached, Resync и швы forcePanicLate/forcePanicAfter СНОСЯТСЯ
   (механика ред. 4 заменена — S6-мажор F43: однократная попытка доставки в
   recovered оставляла окна вечных фантомов при транзиентной панике доктора/хвоста).
   Три механизма: (а) **порядок фаз** (решение 2): join-кадры сливаются в
   pendingPushes ТОЛЬКО после Apply (merge — последняя операция AoI; Apply до
   merge: «мутация применена ⇒ кадр слит»; паника до merge ⇒ joinPushes дропнуты —
   «кадр доставлен ⇒ стадинг применён»), Commit — только в phasePublish
   после B; паника в любой точке до Commit ⇒ prev издателя не продвинут ⇒ манифест
   следующего шага ПОЛНЫЙ (дифф от незакоммиченного) ⇒ Step пере-выводит события от
   неприменённого (или частично применённого — паника внутри Apply) view: уже
   применённые диффы эмитят ноль событий, неприменённые выводятся заново; дубли
   канон-толерантны. (а′) **примирение поколений** (F60/F61, контроль ред. 5/6):
   view, применённый к НЕзакоммиченному блобу (паника между Apply и Commit;
   частичная Apply; паника между Apply и merge), а база
   манифеста следующего шага — закоммиченная ⇒ члены с нетто-нулевой дельтой к prev
   (рождение+уход в окне, флаг-флип-флоп) не покрыты манифестом — детект
   next.BaseGen ≠ appliedGen в Step (решение 1) запускает один полный
   примирительный проход с полным эмитом (Introduce всем next∩радиус, Remove всем
   view\next); условие механическое (сравнение поколений),
   стационарно не срабатывает. (б) **долговечный хвост курсора** (решение
   2): resetDrain переносит недоставленное pendingPushes[pushCursor:] в голову
   следующего шага. recovered() доставляет хвост немедленно (оптимизация
   латентности, под собственным recover с деградацией «метрика» — при неудаче
   остаток жив по курсору и уедет следующим шагом; порядок внутри recovered:
   маркер LogPanic → доставка хвоста → freeze-решение — freeze-ветка не возвращается
   раньше доставки). Тест-швы: injectPanic(phaseAoI) — события пере-выведены
   следующим шагом, без потерь/фантомов; injectPanic(phaseB) при ненулевых
   join-кадрах + панирующий тест-пушер failAfterPushes=N — хвост доставлен
   (немедленно или переносом), возобновление с курсора >0 без дублей головы;
   forcePanicPostApply — окно между Apply и merge (join-кадры дропнуты, примирение
   пере-вводит); сценарии F60/F61 — «рождение+уход через окно phaseB», «флип-флоп
   через окно phaseB», «рождение+уход через post-Apply-окно», «флип-флоп через
   post-Apply-окно», «паника внутри Apply (частичный стадинг)».
8. **Бенчи (журнал, не ворота).** (а) BenchmarkJoinFullPass — M наблюдателей × N
   записей полный проход (d²-отсечка + предикат + дифф view + эмит событий);
   компоновка проволочных кадров (CharInfo) вне метрики — оговорка в комментарии:
   якорь ADR-0004 7–11 нс/пара — ПОЛНАЯ константа (скан+компоновка+выборка);
   core-часть без компоновки сопоставима с ~половиной якоря (~3–6 нс/пара), полная
   константа фазы 3 видна в BenchmarkRegionTick (фаза AoI входит в шаг); это же
   худший случай О-4; (б) BenchmarkJoinSteadyDirty — k dirty × M наблюдателей
   (стационарная цена события); (в) BenchmarkPublishBlob — лестница 100/1000/10000
   (симметрия тиковой; комментарий состава цены: N лукапов слотов + N сравнений
   полей + N×sizeof(Record) копирование); (г) BenchmarkAdvisoryRead — линейный
   baseline, две точки N=100/10000 (наклон виден только при ≥2 точках; база
   будущего aux-индекса). Все ReportAllocs; числа — в прогресс (первое измерение =
   baseline; оптимизация — не скоуп).
9. **e2e (cmd/l2go).** Два клиента (харнесс enterWorld ×2): взаимные CharInfo после
   второго входа; логаут второго → DeleteObject у первого (трафик-лог l2client).
   Регресс: одиночный клиент P3.7 — view set пуст, join-кадров нет, существующие e2e
   бит-в-бит не меняются.

### Скоуп-границы (анти-скоуп)

Без LOD/бюджета/тиров (фаза 6); без сетки 3×3 (одна ячейка, CellID присутствует
типом); без слуг и предметов лёгкого класса в блобе (фазы 4–5; типы сида остаются);
без NPC-компоновки (P3.10: Kind есть, компоновка — счётчик); без позиционных
апдейтов (P3.9: событие Update есть, кадры — нет); без aux-индекса точечных
advisory-чтений (baseline-бенч — теперь); пул блобов — фаза 6 (аллокация на тик);
адаптивные тиры радиусов — фаза 6. Маркер фазы 6: память view set растёт O(M×N)
слотов (плотный id-массив на наблюдателя ≈ 8 Б/слот против канонного knownlist ≤70
записей) — цена контракта оси 3 без хеша в вырожденной одной ячейке; при M×N,
ломающем память (P3.10+), усечение (id только для in-view слотов / поколение слота
от издателя) — фаза 6 по измерениям.

### Корнер-чеклист (покрытие)

Границы: 0/1/максимум (подтесты SetEquality), ±1 дистанции (Boundaries), int32-края
(Int32Edges); Generation-переполнение — не применимо (584 года при 10 Гц).
Интерливинги: параллельные Step/Publish — не применимо (single-writer, И1;
свидетель — -race-кейсы); окно [Apply, merge) — PostApply-строки матрицы;
повторное событие — knownSet-множество; поздний ответ — нет запрос-ответа в AoI;
мёртвому адресату — ObserversOnlyLiving. Тайминги: dt фазе AoI не нужен
(членство — функция позиций); waitFor-поллинг без синов. Деградации: одиночные
паники всех окон (матрица + Reemits), паника пушера (два режима), серия → freeze.
Злые входы: координаты (Int32Edges), огромное Name (ComposeJoin + golden P3.5),
флип-флопи (FlagsFlip + матрица), реюз слота (SlotReuse). Чурн: спавн+деспавн
одном шаге, повторный вход аккаунта, TERM. Пики byteCap: P3.10 (F15). Идемпотентность:
повторный Step (StagesWithoutMutating), повторное примирение (стационарный ассерт
Reconciliation).

### Анти-план

Проволочная толерантность дублей (golden P3.5, качество формата); гео-LOS (OQ-8);
сетка 3×3/тиры/задержки/троттлинг (О-1/2/3, фаза 6); NpcInfo-компоновка (P3.10);
позиционные кадры Update (P3.9); byteCap-шторм (P3.10); числа бенчей как ворота;
повторный Commit/чужой блоб (не контракт); реплей исходящего (недетерминирован по
построению).

### Требуемые швы (обязательство вниз для S7)

1. Region.forcePanic + код phaseAoI (константа, не магическое число — коды сдвигаются).
2. Region.forcePanicPostApply — тест-поле: паника между Apply и merge.
3. Join.ForcePanicInApply — экспортированный тест-шов (в эталоне с пометкой).
4. failAfterPushes-пушер (двойник FramePusher): режимы «однократная паника после N» /
   «до конца шага» + счётчик доставок (оракул отсутствия дублей); семантика
   сброса на попытку пиннится в реализации.
5. knownSet-хелпер: pushCollector + декод опкода → множество objID−Base на клиента.
6. Кастомные JoinConfig в юнитах (NewJoin); компонентные — канонные.
7. logAdviser: флаг окна поднимается после LogStep, сбрасывается первым действием
   следующего шага (урок F40).

### Находки планировщика на спеку (закрыты в ред. 8 правками эталона/решений)

Н1 ForcePanicInApply — экспортирован, в эталоне с пометкой (закрыто); Н2 источник
JoinConfig региона — CanonJoinConfig жёстко (закрыто); Н3 снос snapshot-заготовки —
оракул публикации через Committed()/Read (TestRegionBlobCommitOnlyInPublishPhase);
Н4 семантика failAfterPushes — пин в шве №4; Н5 константы фаз в тестах; Н6 сброс
флага advisory-окна первым действием шага (шов №7).
