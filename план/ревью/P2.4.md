## Детальный план (S0, рев. 2.2 — закрыты F1–F30)

### Факты проработки

- Канон — Mobius Interlude 43ac8878, дочитаны GeoEngine (getValidLocation, canSeeTarget,
  getLosGeoZ, hasNeighbourLayerNear, checkNearestNsweAntiCornerCut, getNearestZ/
  getNextLowerZ/getNextHigherZ/getNearestNSWE), GridLineIterator2D/3D, GeoUtils.computeNswe,
  MultilayerBlock, NullRegion, GeoEngineConfig. Константы канона: HEIGHT_INCREASE_LIMIT 40
  (резкий подъём), MAX_SEE_OVER_HEIGHT 48, ELEVATED_SEE_OVER_DISTANCE 2, лимит слоёв правила
  1000 (только multilayer, передан из P2.3), PATH_CONTINUITY_TOLERANCE 16.
- **Итераторы канона — Брезенхам** (8-связная линия, диагональные шаги); r1 предписывает
  supercover (посетить каждую задетую ячейку). Канон компенсирует диагонали ветками
  анти-среза: движение — checkNearestNsweAntiCornerCut на каждом шаге (для ортогонального
  nswe вырождается в проверку NSWE prev; для диагонального — оба ортогональных бита prev +
  оба переходных флага соседей угла); LOS — явные четырёхусловные ветки на NE/NW/SE/SW.
- **Corner-тождество (основа решения 3):** канонный композит диагонального перехода A→C
  (SE, B=(x+1,y), D=(x,y+1) — угловые ячейки) = {A.S, A.E, B.S, D.E}. Supercover-путь через
  ОБЕ угловые ячейки (A→B→C и A→D→C) проверяет ровно эти четыре перехода канонными
  ортогональными предикатами — структурное тождество без диагонального кода. Все четыре
  предиката вычисляются при prevZ события (включая виртуальный prevZ); z-обновление один
  раз — у диагональной ячейки C, по канонной семантике шага.
- Канонная семантика getValidLocation (наш ValidLocation): обход линии от гео-ячейки from к
  гео-ячейке to; на каждом шаге: rawZ = getNearestZ(cur, prevZ) (с правилом 1000); если
  rawZ − prevZ > 40 — одноячеечный разрыв: если у какого-то из 4 NSWE-соседей cur есть слой
  в пределах 16 от prevZ — непрерывно (curZ = prevZ, виртуальный слой), иначе стена → кламп
  в центр предыдущей ячейки (getWorldX/Y + prevZ). **Соседи — 4 NSWE-орта cur, включая
  предыдущую ячейку при ортональном шаге** (у канона исключение prev возникает только на
  диагональных шагах Брезенхама); NSWE предыдущей ячейки в направлении cur (при гео у
  предыдущей) — анти-срез. Финал: дошли — если у конечной ячейки гео есть и prevZ ≠
  nearestToZ → вернуть ИСХОДНУЮ точку (x, y, nearestFromZ); иначе — (tx, ty, nearestToZ).
  Двери/заборы — вне задачи (потребитель фазы 3+).
- Канонная семантика canSeeTarget: nearestZ обеих точек; быстрый путь той же ячейки; обмен
  концов так, чтобы источник был выше; 3D-обход канона (Брезенхам, доминантная ось, z ±1;
  z-only-итерации пропускаются до смены XY); первая точка пропускается; при гео у ячейки:
  losGeoZ = (переход prev→cur открыт ? getNearestZ(cur, prevZ) : getNextHigherZ(cur,
  prevZ)); maxHeight = (точка < 2 ? nearestFromZ + 48 : zЛуча + 48); на диагональном шаге —
  дополнительная ветка: обе касательные ячейки угла — losGeoZ каждой ≤ maxHeight и ≤
  getNearestZ(ячейка, zЛуча); перекрытие, если losGeoZ > maxHeight (строго).
- Зоны без гео: NullRegion канона — getNearestZ возвращает входной z, NSWE-проверки
  пропускаются; движение в гео-пустоту разрешено, финальный кламп возвращает цель.
- Конфиг-ветки: isCompletelyBlocked за гейтом PATHFINDING (default 0, выключен) — не
  портируется; AVOID_OBSTRUCTED_PATH_NODES по умолчанию ВКЛЮЧЁН, но живёт в canMoveToTarget,
  который не портируется, — не портируется.
- **Вне сетки мира** канон падает (REGIONS.get за границами массива) — контракт «в мире»
  возложен на вызывающего; наш P2.3 RegionAt возвращает nil и для «в сетке без файла», и
  для вне-сетке — эти домены разводятся контрактом решения 2.

### Решения

1. **Пакет internal/geo, файлы**: move.go (Loc, NearestZ, ValidLocation, CanSee + внутренние
   nearestZLimited/checkNSWE/losGeoZ) и iter.go (supercover-степперы 2D и 3D). Новых рёбер
   матрицы нет; правка ADR-0005 не нужна (строка «Геодата: canMove/пасфайнд | geo» есть).
   Дельта имён: NearestZ — доменная обёртка (сетка/пустота/правило 1000); nearestZLimited —
   запрос по гео-ячейке после проверки региона, без nil-ветки (вызывается только для ячеек
   с гео); Cell.Nearest — без правила 1000. Перекрёстные разграничения — в doc.
2. **API** (мировые координаты; потребитель — движение фазы 3):
   - `type Loc struct{ X, Y, Z int }` — тройка мировых координат.
   - `func (m *Map) NearestZ(at Loc) int` — порт getHeight/getNearestZ: ближайший слой с
     правилом 1000 (только multilayer); без гео — сам z (NullRegion).
   - `func (m *Map) ValidLocation(from, to Loc) (Loc, bool)` — порт getValidLocation:
     дальняя достижимая точка и признак **прибытия** — ok ⇒ res.XY == to.XY (финальная
     проверка слоя цели прошла; кейс +41 — ok=false, res — исходная точка; обратная
     импликация не утверждается: same-cell different-layer возвращает исходную точку с
     ok=false при res.XY == to.XY — табличный кейс); кламп — центр последней валидной
     ячейки при блоке; «исходная точка» = (from.X, from.Y, nearestFromZ); bool устраняет
     хрупкое побайтовое сравнение у потребителя.
   - `func (m *Map) CanSee(from, to Loc) bool` — порт canSeeTarget без дверей/заборов.
   - **Домен-контракт** (все три функции): обе точки в сетке мира — гарантия вызывающего
     (фаза 3 валидирует недоверенные координаты клиента до вызова; прецедент канона —
     исключение вне сетки); нарушение — паника с диагностикой (прецедент CellAt;
     ратифицированное правило: паника — программный контракт, недоверенный вход — ошибка
     на шлюзе). Внутри сетки nil-регион = гео-пустота (NullRegion-семантика) в любом
     месте трассы, включая концы. Соседние запросы у кромки сетки: вне-сеточный сосед =
     «нет гео» (hasGeoPos-guard канона); checkNSWE на касательной ячейке-пустоте = true
     (NullRegion.checkNearestNswe). Длина обхода ограничена сеткой (~131 тыс. шагов
     максимум) — вечный цикл невозможен.
3. **Итераторы supercover — степпер-структуры** (значение + состояние + метод Next; без
   замыканий, iter.Seq и интерфейсов — 0 аллокаций по построению): 2D — Amanatides–Woo,
   переход по пересечённой границы (tMaxX/tMaxY в целочисленной перекрёстной форме,
   сравнение без float-равенства; на corner-событии продвигаются ОБЕ оси tMax — защита от
   вечного цикла); 3D — то же по XY, z = fromZ + Δz·num/den по integer-t перекрёстной
   формы степпера (точная геометрическая интерполяция, не индекс эмиссии — corner эмитит
   три точки на один advance). **Corner-событие** (точное равенство пересечений X- и
   Y-границ, целочисленно через перекрёстное умножение int64): эмитятся ОБЕ угловые
   ячейки и диагональная; движение проверяет четыре канонных ортогональных перехода
   {A.E, A.S, B.S, D.E} — тождество канонному композиту (факт-блок); **высотная ветка
   применяется к каждому эмиту независимо по канонной ортогональной семантике: соседи B
   включают A (B спасается prev — виртуальный z), соседи C НЕ включают A (A диагонален C —
   канонная семантика диагонального шага); NSWE-провал любого из четырёх переходов —
   кламп центр A; высотная стена у C — кламп центр B/D с текущим prevZ**; в LOS на
   corner-событии применяется портированная диагональная ветка канона (обе касательные
   ячейки: losGeoZ ≤ maxHeight и ≤ getNearestZ(ячейка, zЛуча); «переход prev→cur открыт»
   для диагональной C = все четыре перехода пучка). Диагональных переходов в степпере
   нет. Плата supercover — до 3× эмитов на точной 45° против Брезенхама (обе угловые +
   диагональная на шаг; работа сопоставима — те же четыре предиката) — осознанная цена
   анти-среза (фиксируется baseline диагональной формой).
4. **Семантика порогов — канон**: 40 (подъём), 48 (обзор), 2 (первые точки — от высоты
   источника), 16 (непрерывность через соседа), 1000 (правило getNearestZ, только
   multilayer), кламп/финал — точно по GeoEngine.getValidLocation/canSeeTarget, с
   атрибуцией в doc-комментариях. **Зарегистрированные отклонения от канона** (реестр —
   эта задача): (а) fall-лимит спуска r1 в каноне отсутствует — порт канона; (б) Брезенхам
   → supercover: на чисто ортогональных сегментах семантика идентична канону (включая
   промежуточные высотные клампы при виртуальных цепочках — двойной разрыв даёт стену);
   расхождение — только там, где канон шагает диагонально: кламп на ячейку глубже
   (виртуальный z), итог «дойти/не дойти» совпадает через финальную проверку слоя цели;
   геометрии с открытыми NSWE на перепаде >40 при диагональном подходе расходятся
   (экзотика; реальная геодата кодирует перепады закрытыми NSWE); (в) z луча в LOS —
   целочисленная интерполяция по integer-t степпера вместо ступенчатого 3D-Брезенхама
   (отклонение ≤ 1 ед. z на точку — только усечение; z-only-итерации канон пропускает —
   эффективная дискретизация сопоставима); (г) околодиагональные лучи (не через точный
   угол): наш обход проверяет ровно физически пересечённые рёбра (геометрически точно,
   эксплойта нет — замкнутые рёбра покрывают все пересечения пути), канон на
   диагональных шагах Брезенхама проверяет композит из 4 рёбер включая касательную
   ячейку вне пути — строгое доминирование ни в одну сторону (канон строже по рёбрам,
   наш обход — по высотной проверке промежуточных ячеек); табличный кейс — луч с
   наклоном ≠1 мимо L-угла; (д) швы регионов: канон резолвит касательные ячейки угла
   через регион prev с зеркальным заворачиванием за швом (баг канона); наш обход
   резолвит каждую ячейку через собственный регион — расхождение на полосе швов
   записано, шовный тест добавлен.
5. **NSWE-проверка** — по ближайшему слою БЕЗ правила 1000 (канон: getNearestNSWE не
   применяет правило; правило живёт только в высотных запросах): checkNSWE(cell, z, dir) =
   Nearest(z).NSWE&dir == dir. Высоты — через nearestZLimited с правилом. Подтверждено
   каноном (MultilayerBlock.getNearestNSWE → getNearestLayer без правила).
6. **Тесты (TDD, красная фаза коммитом)**:
   - Синтетические геометрии (билдер P2.3): плоский регион (broad-phase); стена NSWE
     поперёк (кламп до стены); **односторонний стаб у угла** (закрыт только один
     ортогональный флаг prev; диагональный луч 45° — блок; критерий p2.4 об L-угле
     дополняет симметричный случай); **переходный флаг угловой ячейки** (закрыт B.S или
     D.E — флаг угла в сторону C; блок — фальсифицирует «не ту пару» переходов);
     L-угол; мост двухслойный с перепадом <1000 (ближайший слой: под мостом не наверх,
     по мосту не вниз); **мост с перепадом >1000: ≥3 однослойные-верхние ячейки настила
     над пустотой** (у средней все 4 соседа вне 16 — сосед-ветка не спасает) **+
     прямой ассерт NearestZ(ячейка настила, z ходьбы) == z** (фальсифицирует и правило
     1000, и fallback getNextLowerZ — входной z); **цель-пьедестал +40** (ok=true, слой
     совпал) и **+41** (ok=false, исходная точка — граница порога финальной проверкой);
     **плато по диагональному подходу** (кламп на ячейку глубже на виртуальном слое —
     документируем отклонение (б)); гео-пустота: цель без гео (успех, res == to) и
     **середина луча через nil-регион**; одноячеечный разрыв слоя (сосед в 16 —
     непрерывно; **без соседа — стена**: конструкция — prev без слоя в 16 от prevZ, вход
     из nil-региона или виртуальная цепочка, фиксируется комментарием теста); LOS: стена
     перекрывает, ровная плоскость видна, рост рельефа **+48 виден / +49 скрыт**
     (граница), «с высоты источника» (первые 2 точки), corner-луч с касательной стеной
     (диагональная ветка).
   - Ожидания детерминированы таблицей: кламп-точка (центр ячейки — GeoToWorldX/Y),
     ok-признак, слой; блок именует фактор в комментарии теста (NSWE какой ячейки /
     финальная проверка / правило 1000).
   - Property-инварианты: ok ⇒ res.XY == to.XY; ok и у ячейки цели нет гео ⇒ res == to;
     !ok ⇒ res — исходная точка или центр ячейки трассы (виртуальные z допустимы — канон
     таков); res.XY — в пределах точечного bbox(from, to), расширенного на одну
     гео-ячейку по каждой оси XY (кламп-центр может выступать до 8 ед. от луча; z из
     инварианта исключён); CanSee(from, from) == true.
   - Фазз-цель (FuzzValidLocation, 10-я в CI): миры строятся детерминированно один раз
     (sync.Once: фиксированный набор синтетических миров + миров из seeds — только
     декодируемые сиды; фазз-параметр сида отображается в этот набор по модулю — мутация
     сида не порождает декода), вход — пары Loc в сетке; инварианты — как выше +
     отсутствие паники. Таблица злых координат вне фазза: вне сетки, ±край int32/int64 —
     паника-контракт (проверка через recover).
   - Угловые кейсы (стаб, переходный флаг, LOS corner, L-угол) прогоняются во все четыре
     квадранта — зеркальные отражения геометрии и луча дают тот же исход (фальсификация
     перепутанных битов N/S/E/W и знаков шагов).
   - Дополнительно: same-cell different-layer (ML, ok=false, исходная точка);
     LOS-луч через nil-регион (инкремент счётчика точек — по всем XY-точкам, включая
     безгео: перенос losGeoZ через пустоту по канону); пьедестал +40/+41 — flat-блок
     (квант высот 8), цель на кромке блока.
   - 0-аллок таблица на ValidLocation/CanSee/NearestZ (AllocsPerRun); Example пакета
     (ExampleValidLocation на стене).
7. **Бенчмарки** (реестр ADR-0005 «canMove/пасфайнд»): ValidLocation {плоско 3 ячейки,
   стена 20 ячеек, мост ML, **диагональ 45° 20 ячеек**, **гео-пустота 20 ячеек**}; CanSee
   {открыто 20 ячеек, **перекрыто на 10-й из 20**, **ML/закрытый-NSWE 20 ячеек**,
   **диагональ 45° 20 ячеек**}; NearestZ {flat, ML}; ReportAllocs; baseline -count=10 →
   benchmarks/P2.4-geo-move-baseline.txt с шапкой (прецедент P2.3), числа в журнал.
8. **Атрибуция**: порты getValidLocation, canSeeTarget (+диагональные ветки), getLosGeoZ,
   hasNeighbourLayerNear, getNearestNSWE (checkNSWE), getNextHigherZ, константы — видом
   «Mobius GeoEngine.<метод>» (файл+функция, без номеров строк в коде); ревизия канона —
   одна строка в шапке файла теста; итераторы — алгоритм Amanatides–Woo и supercover-
   свойства самодостаточно, без указания на внутренние документы.

### Критерии приёмки (фальсифицируемые)

- Таблица геометрий зелёная с точными клампами и ok-признаками; односторонний стаб у угла
  блокирует диагональ (критерий p2.4); мост >1000/<1000 — правильные слои (правило 1000 и
  fallback фальсифицированы); границы +40/+41 и +48/+49 покрыты.
- Property-инварианты зелёные; фазз-цель в CI (10-я), сид-прогон чист, миры построены один
  раз (число exec'ов в журнале).
- 0 аллок на горячих путях; baseline с шапкой содержит все формы, включая диагональ и
  пустоту; числа в журнале.
- Таблица злых координат: вне сетки — паника-контракт (recover-проверка); в сетке пустота —
  семантика NullRegion.
- Ворота зелёные покомпонентно; external require — ноль; новых рёбер матрицы нет.
- Канон-трассировка: каждое пороговое решение ссылается на метод GeoEngine (файл+функция)
  в комментарии теста; отклонения (а)–(в) решения 4 — в реестре задачи.

## Отклонения реализации от плана (S8, ADR-0006)

- **O5 (F33)**: кламп высотной стены у диагональной ячейки corner-пучка — центр
  основания пучка A, а не «центр B/D» из Р26. Канон-эквивалент: диагональный шаг
  Брезенхама возвращает центр предыдущей ячейки (=A); B/D — непройденные касания,
  кламп туда ставил бы сущность вне пройденного пути; единое правило «центр prev»
  проще. Тест фиксирует.
- **O6 (решение 6)**: фазз без «миров из seeds» — 8 синтетических миров покрывают
  классы геометрий (плоскость, стены, мосты, настил, плато, ML-флаги, пустота);
  инварианты не о данных, сиды дублировали бы классы.
- **O7 (решения 1/3)**: единый stepper (2D-потребитель передаёт zFrom=dz=0) вместо
  отдельных «степперов 2D и 3D» — одно состояние, меньше дублирования.
- **O8 (F31)**: corner-пучок на конце луча редуцируется к одиночному шагу в цель:
  заходящие за конец касания не эмитируются (итератор канона останавливается на
  конечной ячейке).
- **O9 (F42)**: бенч-форма «пустота» — nil-хвост 13 ячеек луча (цель в пустоте);
