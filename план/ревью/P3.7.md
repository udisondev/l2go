### Факты канона (сверка S0 + правки доменщика F10/F12/F15/F16)

Безусловный состав EnterWorld-слитка канона (без клана/фракции/GM, живой персонаж),
порядок: UserInfo → SendMacroList (пустой, SendMacroList.sendUpdate шлёт ≥1 пакет) →
ItemList(showWindow=0) → ShortcutInit → HennaInfo (тело 6×B(0)+D(3)+D(0)) → QuestList →
EtcStatusUpdate (7×D(0)) → ExStorageMaxCount (константы канона: инвентарь/склад/…) →
FriendList → SystemMessage(WELCOME_TO_THE_WORLD_OF_LINEAGE_II) → SystemMessage(период
Seven Signs; свежий сервер — recruiting-ветка) → SkillCoolTime → SkillList (канон:
player.sendSkillList() асинхронно ~300 мс после слитка) → ValidateLocation →
ActionFailed. Плюс ClientSetTime один раз: тело D(игровые минуты суток) + D(6)
(IG_DAYS_PER_DAY); gameTime = (тики10Гц % 144000)/100 (GameTimeTaskManager);
отправитель ClientSetTime в запиненном каноне не найден — «периодический» из других
форков, фаза 3 шлёт один раз в слитке. Итого 16 кадров. При нулевом игроке канон шлёт
LeaveWorld + разрыв (ветка фазы 3 недостижима: шлюз гарантирует char≠nil). Logout:
store → delete → close(LeaveWorld) — финальный кадр клиенту перед закрытием; отказ
canLogout — ActionFailed (фаза 3: отказа нет). ObjectID-база 268435456 = FirstObjectId
канона (IdManagerConfig).

### Решения (ред. 2)

1. **Свёртка входа/выхода — в Fold.** Контрольные письма KindEnterWorld/KindLinkDead
   (приоритетная порция ctrl-ящика; KindPersistReply — обычное письмо ctrl-ящика,
   применяется общим списком того же шага; Regional() не меняется) и клиентские кадры
   KindClientFrame (порции сущностных ящиков) обрабатывает Fold: рождения/удаления —
   только через Births/Retires, исходящие письма — StepResult.Out. Состояние в
   world.State: Conns map[connID]EntityID, Accounts map[account]EntityID, Leaving
   (сортированный слайс по (deadlineTick, EntityID)), SaveQ map[key]save (ключ —
   account, внутри записи слот; Corr письма сохранения = EntityID — вечен и уникален,
   вторичный индекс connID→account не нужен; EnterWorld аккаунта обязан очищать SaveQ
   аккаунта — ретраи старого снимка не переживают перезаход). Fold получает параметры
   поведения значением (GraceTicks, SaveRetryTicks — из конфига региона, не глобалы). Любой обход карт — только по
   сортированным ключам (D3: итерация по map в игровой логике запрещена без
   оговорок); Dump сериализует карты в отсортированном порядке (бит-в-бит).
2. **Player-блок сущности.** `type Player struct { Rec persist.CharRecord; ConnID
   uint64; PendingTeleport bool }` (включение записи, не дублирование полей; ребро
   world→persist в матрице). Entity.Player *Player (nil у не-игроков).
   Сериализация — симметричная пара appendPlayer/parsePlayer (используется из
   appendEntity/parseEntity и из Dump: одно место формата); int64-поля записи
   (CreatedUnix, LastSeenUnix, Exp) — AppendVarint (uvarint отрицательного
   разваливается). Версия формата лога порций 1 → 2 (читатель строго проверяет
   версию — guard новый, сейчас parseFile её не проверяет; старые цепочки
   отличает честно).
3. **Пушер стационарных кадров — регион** (F42-буква): мир пушит кадры напрямую в
   encode.Stage по ребру world→encode (узкий интерфейс у потребителя:
   `type FramePusher interface { Push(id uint64, frame []byte, crypt bool) }` —
   encode.Stage ему удовлетворяет структурно). Fold чистой функцией КОМПОНУЕТ кадры
   (encode.ComposeEnterWorld; аллокации байтов — не I/O), возвращает
   StepResult.Pushes []FramePush{Client, Frame, Crypt} (пуши — в порядке применения
   порций, без сбора через map). Слиток компонует АКТОР сразу после applyEffects тем
   же чистым хелпером encode.ComposeEnterWorld (ObjectID требует EntityID из Spawn —
   Fold физически не может; без лишнего тика и без флага), дописывая в Pushes до
   фазы B; актор исполняет пуши в фазе B СТРОГО РАНЬШЕ писем Out шага (happens-before
   «LeaveWorld в стейдж → KindConnClose шлюзу» — close-after-flush выдаёт кадр до
   разрыва) — единственный писатель исходящего потока региона; стейдж потокобезопасен
   по построению P3.6. Новый Kind не вводится. Ребро эксклюзивности двух пушеров
   (шлюз-пресессия/регион-стационар) — письмо EnterWorld: последний пресессионный
   push шлюза строго до sendRegion, первый пуш региона строго после применения
   письма; после бинда шлюз кадры не пушит (F42).
   Presession-кадры (до EnterWorld) остаются за шлюзом. Крипт-марка стационарных
   кадров — всегда crypt.
4. **Композиция кадров — обёрткой encode** `ComposeEnterWorld(data EnterWorldData)
   []FramePush`-слайс: 16 кадров слитка writers'ами protocol; ObjectID клиента =
   268435456 + EntityID (FirstObjectId канона; закрывает КТ-риск маленьких ID).
   Новые писатели protocol (11; SystemMessage существует с P3.5 — chat.go, id 34
   welcome уже в фикстурах): SendMacroList(пустой), HennaInfo, QuestList,
   EtcStatusUpdate, ExStorageMaxCount, FriendList, SkillCoolTime, ValidateLocation,
   ClientSetTime, LeaveWorld, RestartResponse (+константа id Seven Signs). Одна
   группа testdata «enterworld» на все кадры слитка — один loader. Константы формулы gameTime выводятся из периода метронома
   (тики IG-суток = секунды_суток × Гц; хардкод «100 мс» запрещён — инвариант 7;
   тест нестандартного периода сверяет и формулу). Атрибуция Mobius CT_0_Interlude
   @43ac8878 — в doc-комментариях
   писателей и констант (критерий приёмки). Фикстуры — ручной hex (методика P3.5).
5. **Персист: OpSaveChar вместо OpSaveSnapshot** (потребителей старой нет): upsert по
   слоту в chars/<account>.json, Request.Char persist.CharRecord. Актор применяет
   полный комплект валидации handleSnapshot: NormalizeLogin, validateCharRecord,
   владение именем (nameOwner), дубликаты имён/слотов, лимит, CreatedUnix из старой
   записи/LastSeenUnix ставит актор. Whitelist FromID-отправителей (шлюз, регион) —
   поле конфига актора, wire-up в cmd. Злые входы (чужой слот/имя/аккаунт/диапазоны) —
   ok=false, файл не тронут (критерий приёмки).
6. **Логаут** (Logout-кадр в ящике сущности → Fold): остановка движения (Moving=false,
   Dest=Pos), письмо KindPersistRequest{OpSaveChar, Corr=EntityID} (решение 1) + запись SaveQ
   (ретраи: нет ответа SaveRetryTicks=10 тиков (1 с при 10 Гц) → повтор; ok=false по
   валидации — стоп ретраев + Error + счётчик «не сохраняем»; ok=false по IO — повтор
   каденса; персонаж не теряется, пока жив процесс — остаточный риск: смерть процесса
   до успешного сохранения), Retire сущности, пуш LeaveWorld (стейдж, crypt), письмо
   KindConnClose{conn} шлюзу, развязка Conns; Accounts развязывается УСЛОВНО —
   только если Accounts[account] == удаляемая сущность (перезаход того же шага уже
   перезаписал бинд — безусловный delete стёр бы бинд новой сессии; прецедент guard
   шлюза). Ответ персиста не блокирует
   выход.
7. **LinkDead → grace-окно в тиках** (GraceTicks=50 ≈ 5 с при 10 Гц, конфиг
   world.Config): Leaving-запись с дедлайном тика; кадры Leaving-сущности не
   применяются (счётчик дропов в State); истечение → путь логаута БЕЗ LeaveWorld и
   БЕЗ KindConnClose (сокет мёртв). Повторное KindEnterWorld аккаунта при живой
   сущности (grace или обычная) — немедленный Retire старой БЕЗ её персиста, очистка
   SaveQ аккаунта, рождение новой, перезапись бинда; развязка Conns/Leaving старой
   записи — явная, зеркально логауту).
   Активность региона: residents > 0 ИЛИ SaveQ непуст (S6: иначе последний
   logout/LinkDead-экспирация усыпляет регион — IO-ретраи SaveQ мертвы навсегда;
   пустые шаги логируются, детерминизм не страдает).
8. **KindConnBind — производитель регион**: при рождении игрока актор (после
   applyEffects — ID присваивает Spawn, письмо не может ехать из Fold) дописывает в
   исходящие шага KindConnBind{conn, EntityID} (включая перезапись при перезаходе);
   шлюз по бинду начинает слепой push стационарных кадров в ящик игрока. LinkDead
   шлюз шлёт по фазе коннекта (gc.phase ≥ phWorld), не по entity — смерть коннекта в
   RTT бинда не теряет сущность; регион резолвит сущность по Conns.
9. **Фикс conn.go:364 + соседняя гонка**: начальный handshake-дедлайн вооружать под
   dlMu только при mode==ModeHandshake И stopping==false (закрытие до первого arm —
   иначе wg.Wait Close буксует до HandshakeTimeout); перезавод после кадра
   перепроверяет stopping под dlMu; Close() ставит дедлайн-в-прошлое под тем же
   per-state dlMu (полное закрытие окна «arm перезаписывает past»). Регресс-тесты:
   стационарный молчун (HandshakeTimeout=150мс, stationary сразу после Open, молчание
   250мс — жив); кадр в момент Close — дедлайн не воскресает; Close до первого кадра —
   readLoop не вооружает будущий дедлайн.
10. **Метрики дропов** (фальсифицируемые): транспорт — классовые счётчики финальных
    дропов уже есть в Mailbox (finalFAF/finalReliable); после Retire письма смотрят в
    синглтон deadBox — Registry получает доступор этих агрегатов (без per-entity
    атрибуции; тест ассертит дельту агрегата). State — счётчик дропов кадров
    Leaving/неизвестных сущностей. Критерий «кадр после
    деспавна» проверяет транспортный счётчик; «кадр в grace» — State-счётчик + Dump
    (позиция не меняется).
11. **RequestRestart** — белый список стационара: ответ RestartResponse(false) +
    ActionFailed (канон-паттерн отказов; живой клиент не виснет; КТ-3).
12. **cmd/l2go — wire-up**: флаги -addr :7777, -hz 10, -persist var/persist, -artifact
    (обязателен), -link + -tls (mTLS-стык), -portions var/portions, -max-conns 20000;
    таймауты — константами дефолтов (флагов не плодим); guard CompletionsCap ≥
    MaxConns (машинная сверка, критерий приёмки; буква спеки §P3.6 — «не меньше»);
    slog напрямую; artifact.LoadFile —
    статика только артефактом (e2e стартует на синтетическом артефакте из testdata в
    каталоге без XML); порядок старта: метроном → persist-актор (doorbell из подписки
    метронома) → регион (FramePusher=стейдж) → encode-стейдж → conn.Server → шлюз
    (doorbell подписки) → loginlink.Dial/Run + WaitRegistered → открытие :7777.
    byteCap стейджа — guard ≥ батч слитка с запасом (иначе push живого логина
    получает false→closing). Graceful shutdown (SIGTERM): закрыть слушатель →
    отменить шлюз/conn → отменить регион: его Run-defer (горутина региона —
    single-writer) шлёт финальные OpSaveChar всех живых И дренит SaveQ (зависшая в
    ретрае запись — снимок в ней уже есть; S6) → done региона → отменить персист
    (его shutdownDrain в бюджете DrainTimeout дорабатывает письма; ответы мёртвому
    региону — безвредные мёртвые письма в его ящике) → выход. Ожидание ответов
    сохранителем не вводится. Харнесс — package main cmd/l2go (main.go
    рефакторится в run(args)+сборка контура по прецеденту l2login — «тот же контур»
    буквально, без дублей wire-up); синтетический артефакт строится в TestMain
    (data.Load(testdata/synth)+artifact.Build во TempDir — .l2a в git не входит);
    «TERM» тестируется через ctx-отмену (signal.NotifyContext — тривиальная
    обвязка); реальная login-нога in-process (login.New + loginlink сервер/клиент,
    mTLS-материал во временном каталоге) на 127.0.0.1:0.
13. **l2client**: типизированный лог UserInfo в стационарной фазе (поля name/x/y/z —
    e2e-ассерты). Round-trip позиции фальсифицируется нетривиально: между сессиями
    e2e редактирует chars/<account>.json на смещённую позицию и ассертит её в
    UserInfo/CharSelected перезахода (путь восстановления), а путь сохранения —
    сверкой файла после логаута (S6: без этого критерий сравнивает стартовую позицию
    с собой же). Окно «CharList обогнал финальный персист» (кросс-отправительный
    порядок) — осознанное: e2e-харнесс ждёт подтверждения сохранения (поллинг
    атомарного rename файла) перед реконнектом (остаточный риск записан).
14. **Бенчмарков новых нет**: путь входа холодный; Pushes PhaseBCap не потребляют
    (капнуты только Out-письма: на логин — 1 ConnBind, на логаут — 2+SaveChar;
    реальные ограничители — DrainBudget 4096 и byteCap стейджа); массовый исходящий
    бродкаст — P3.9.

### Порядок реализации (S7, TDD)

1. Красная фаза (каркас, не весь объём): e2e-харнесс (package main cmd/l2go на
   127.0.0.1:0) + по одному красному ассерту на зону приёмки (слиток/логаут/grace/
   TERM) — падают по поведению, не по компиляции семи пакетов; юнит-красные живут в
   своих шагах TDD (тест → реализация → зелёный), панорама кейсов — тест-план S6b.
2. protocol: 12 писателей + фикстуры ручным hex (+SystemMessage по id).
3. encode: ComposeEnterWorld + EnterWorldData + objectID-база.
4. persist: OpSaveChar upsert + валидация + whitelist отправителей.
5. world: Player/State-структуры + Fold-обработка + Pushes + Dump/лог v2.
6. conn: фиксы дедлайнов + регрессы.
7. gateway: бинд/LinkDead по фазе/ConnClose-путь (без стационарных пушей).
8. l2client: типизированный UserInfo-лог.
9. cmd/l2go: wire-up + shutdown + e2e зелёные.

### Критерии приёмки (фальсифицируемые)

- E2E: логин → создание → вход; слиток (16 опкодов в канонном порядке) в трафик-логе,
  позиция/имя — по полям.
- Логаут: LeaveWorld доставлен (последний кадр до закрытия), коннект закрыт, файл
  персонажа обновлён (позиция раунд-трип), повторный вход — на сохранённой позиции.
- LinkDead без Logout: деспавн+сохранение после grace; перезаход в grace — ровно одна
  сущность аккаунта, файл отражает вторую сессию (ретраи старого снимка отменены);
  goroutine-leak тест проводов.
- Кадр после деспавна — транспортный счётчик enqueue-дропов; кадр в grace — State-
  счётчик + Dump (позиция неизменна); не паника.
- RequestRestart → RestartResponse+ActionFailed, коннект жив.
- cmd/l2go стартует на синтетическом артефакте (каталог без XML); Hz доходит до
  метронома (тест нестандартного периода); TERM → персист-файлы консистентны
  (финальные сохранения живых); CompletionsCap ≥ MaxConns машинно.
- Атрибуция Mobius CT_0_Interlude @43ac8878 в doc-комментариях новых писателей и
  констант (обсуждающий список — дифом).
- Ворота зелёные; Dump бит-в-бит на повторном прогоне свёртки тех же писем; порядок
  Pushes/Out детерминирован.
