# Реестр находок P2.3

- Задача: P2.3 Геодата: формат, парсер, mmap-представление (план/p2.md)
- Ревью-профиль: S2 — инвариантщик, безопасник, перформансер, прагматик; S8 — + доменщик,

## Детальный план (S0, рев. 2 — правки S3/S4)

### Факты проработки

- Канон — Mobius Interlude master 43ac8878 (тот же коммит, что в P1–P2), пакет
  `org.l2jmobius.gameserver.geoengine` читается на месте в `_refs/mobius-interlude`:
  GeoEngine.java (загрузка, координаты), geodata/{Cell,IBlock,IRegion}.java,
  blocks/{FlatBlock,ComplexBlock,MultilayerBlock}.java, regions/{Region,NullRegion}.java.
- Сверка со вторым оракулом aCis (зеркало sonizs123/Acis, GeoStructure.java): раскладка
  L2J-файлов идентична — типы блока 0/1/2, блок 8×8, регион 256×256 блоков, NSWE E/W/S/N =
  1/2/4/8, ячейка 16 юнитов. aCis дополнительно читает .l2d/l2off-варианты (0xD0/0x40/0xD1/0xD2)
  — подтверждение предупреждения r1; для нас l2off — анти-скоуп. Лимит слоёв у aCis в
  GeoStructure отсутствует; у Mobius — явный 1..125 («Geo file corrupted») — принимаем лимит
  канона Mobius.
- Канонный getNearestZ (MultilayerBlock.java:241–254) — не «ближайший слой»: при
  `nearestZ − worldZ > 1000` подменяется getNextLowerZ (анти-«телепорт на этаж/мост»). Это
  композиция над примитивами представления; порт целиком — потребитель P2.4, здесь фиксируем
  правило в контракте, чтобы оно не потерялось между задачами.
- Геодаты на дисках владельца нет (проверено: C:\games — только клиенты L2-Interlude/L2-TCT/
  L2-Trial и артефакты тапа; D: — ini/логи). КТ-3 (ручной прогон на реальном пакете) ждёт
  источник от владельца; конвейер и CI — на синтетике (буква плана фазы: «CI — только
  синтетика»). Рекомендация владельцу: любой публичный пакет L2J-геодаты Interlude (файлы
  `NN_NN.l2j`), подложенный в каталог вне репо.

### Формат (канон Mobius Interlude; все константы — из исходника, порт с атрибуцией)

- Файл на регион: `%d_%d.l2j` (regionX_regionY, без ведущих нулей). geoX-пространство покрывает
  тайлы 0..31 (WORLD_MIN_X = −655360, WORLD_MIN_Y = −589824); имя файла = индексу региона
  (regionX = geoX/2048). Канонный Interlude живёт в тайлах 16..26 × 10..25 (World.TILE_*).
- Регион = 256×256 блоков = 2048×2048 ячейки; блок = 8×8 ячеек; ячейка = 16 юнитов.
  Преобразования: geoX = (worldX − WORLD_MIN_X)/16; мир: geoX·16 + WORLD_MIN_X + 8 (центр
  ячейки).
- Блоки в файле последовательно (индекс = blockX·256 + blockY, X-мажор; blockX = (geoX/8) mod
  256 внутри региона). Тип — 1 байт:
  - flat (0): 2 байта int16 LE — высота всего блока. Итого 3 Б. NSWE flat-блока в байтах
    отсутствует — семантика канона: все направления открыты (NSWE_ALL, FlatBlock.java:56–62).
  - complex (1): 64 × int16 LE. Ячейка: NSWE = v & 0x0F; высота = int16(v & 0xFFF0) >> 1
    (знаковая, ≈ ±16384). Итого 129 Б.
  - multilayer (2): 64 ячейки, каждая: 1 байт nLayers (валидно 1..125) + nLayers × int16 LE
    слоёв (формат ячейки complex). Размер переменный; максимум блока 16065 Б.
- Ячейка в блоке: cellX·8 + cellY (X-мажор, локальные 0..7).
- Семантика ближайшего слоя (порт MultilayerBlock.getNearestLayer): точное совпадение Z —
  немедленный возврат; иначе минимум |dz|; при равенстве — первый слой по порядку.
- Высоты знаковые: домен высоты ячейки/слоя ≈ [−16384, 16383] (после >>1); высота flat-блока —
  полный int16. Мир Z: WORLD_Z_MIN/MAX = ±16000.
- Регион без гео (NullRegion канона): HasGeo=false, семантика «нет данных» — у нас
  *Region = nil.

### Решения

1. **Пакет `internal/geo` без зависимостей** (строка матрицы уже есть). Раскладка: doc.go
   (контракт, время жизни маппингов), format.go (константы формата, NSWE-тип, BlockType,
   координатные преобразования), region.go (Map/Region/Cell), decode.go (DecodeRegion +
   StructError), load.go (LoadDir + Report/Entry + манифест), mmap_windows.go / mmap_unix.go.
   Новых рёбер матрицы нет; cmd/l2data → internal/geo — cmd вне матрицы (как cmd/l2data →
   data).
2. **Декодер над []byte не знает источника.** `DecodeRegion(rx, ry int, data []byte)
   (*Region, error)` — валидация и построение индексов за один проход. Источники байтов:
   mmap внешнего файла, embedded-байты P2.7, синтетика тестов. Ошибка структуры —
   `*StructError{Code, Block, Offset, Message}` (Message формируется в decode у места
   ошибки; File появляется уровнем выше); LoadDir копирует квартет в Entry и добавляет File.
3. **Транспорт файла — `mapFile(path) (data []byte, unmap func() error, err error)`**
   (строчная: внешний потребитель появится в P2.7 — тогда и экспорт; LoadDir и тесты —
   внутри пакета).
   Windows (платформа владельца, обязательная проверка): kernel32 через syscall.NewLazyDLL —
   CreateFileMappingW(PAGE_READONLY, размер из GetFileSizeEx/stat) + MapViewOfFile(FILE_MAP_READ,
   тот же размер); после MapViewOfFile хэндл файла и секции закрываются (view живёт до
   UnmapViewOfFile — документированное поведение Windows), unmap = UnmapViewOfFile. Unix:
   syscall.Mmap(fd, PROT_READ, MAP_PRIVATE, stat-размер), fd закрывается после mmap, unmap =
   munmap. Маппится ровно stat-размер — потолок и все проверки DecodeRegion работают по
   len(data) (не по повторному stat). Пустой файл — пустой слайс без маппинга, unmap при
   этом — безопасный no-op (нулевые файлы в Windows не маппятся; decode всё равно даст
   trunc). Контракты времени жизни: MapFile —
   «вызывающий потребляет байты до unmap; предусловие — файл не модифицируется и не усекается
   при живом маппинге» (нарушение — SIGBUS/ACCESS_VIOLATION вне контроля Go); LoadDir владеет
   маппингами регионов всё время жизни процесса — unmap не вызывается вовсе. Данные —
   операторские (read-only каталог), контроль share-режима открытия не вводится — патологический
   случай закрыт предусловием.
4. **Индексы O(1), иммутабельные после загрузки** (инварианты 3/6): один слайс записей
   `blocks []blockIdx` (65536 × {off uint32 — смещение блока в data; ml uint32 — старт блока в
   mlCells, sentinel ^uint32(0) для flat/complex}) + для multilayer-блоков плоский
   `mlCells []uint16` (64 внутриблочных смещения ячеек на блок; внутриблочные ≤ 16064 —
   uint16 хватает; off — uint32 до потолка файла ~1 GiB). Байты региона в кучу не копируются.
   **Цена индексов (осознанная, фиксируется в отчёте HeapIndexBytes):** 512 КиБ на регион
   (blocks) + 128 Б на multilayer-блок (mlCells); на канонном пакете 176 регионов ≈ 88 МБ +
   70–140 МБ (при доле multilayer 5–10%) ≈ **160–230 МБ live-кучи** поверх off-heap данных
   (указатели отсутствуют — GC не сканирует содержимое). Порог эволюции: HeapIndexBytes >
   ~300 МБ на полном пакете (замер КТ-3) — off-heap sidecar-индексы обязательны в P2.7.
   Альтернатива (проход канона по ячейкам на каждый лукап, O(≤64), кучи только 512 КиБ/регион)
   отвергнута: план требует O(1), потребитель — A* фазы 4; решение пересматривается числами
   КТ-3.
5. **API представления (потребитель — P2.4; всё 0-аллок):**
   - `Map`: `RegionAt(geoX, geoY) *Region` (nil = нет гео; координаты вне [0, 65536) — nil,
     без паники). HasGeo не вводится (≡ RegionAt != nil).
   - `Region`: `CellAt(geoX, geoY) Cell` — geoX/geoY глобальные гео-координаты; ячейка вне
     данного региона — паника программного контракта с диагностикой (ратифицировано F6/P1.2;
     запрет mod-заворота канона Region.java:83). Region.X()/Y() не вводятся (rx/ry знает
     владелец Map).
   - `Cell`: `BlockType()` (broad-phase flat — P2.4), `Nearest(z) (z, NSWE)`,
     `LowerZ(z) int`, `HigherZ(z) int` — порты getNearestLayer/getNextLowerZ/getNextHigherZ
     канона (fallback worldZ; flat/complex — деградация в единственный слой; flat-блок:
     NSWE = NSWE_ALL — порт FlatBlock). Перебор слоёв (Layers/Layer) не экспортируется —
     названный потребитель (связный слой) появится в P2.4, тогда и родится. Канонический
     getNearestZ = Nearest с правилом «nearestZ − z > 1000 → LowerZ» — правило ТОЛЬКО
     multilayer (FlatBlock.java:65–68, ComplexBlock.java:121–124 возвращают высоту
     безусловно); композиция — P2.4, правило зафиксировано в doc-контракте geo (константа
     1000 с атрибуцией). Region хранит собственные rx/ry в некспортированных полях —
     контракт CellAt реализуем без экспортированных X()/Y().
6. **Валидация = единственный проход decode; разрушенная структура — ошибка, регион не
   устанавливается; ошибки всех файлов собираются в отчёт** (как P2.1). Коды: `trunc` (выход
   за конец данных; место — блок+офсет), `block_type` (байт ∉ {0,1,2}), `layers` (0 или >125),
   `tail` (байты после 65536-го блока), `dup` (второй файл с теми же координатами региона —
   включая случаи ведущих нулей `016_010` и регистра расширения), `range` (координаты из имени
   вне [0,32)), `size` (> MaxRegionBytes = 1 GiB; максимум легального файла
   65536·16065 = 1 052 835 840), `io` (чтение/mmap). Потолок проверяется выделенной функцией
   размера (тестируемо без выделения 1 GiB). «Sanity NSWE»: значения формата по построению
   ≤ 0x0F (маска при чтении); отдельной валидации нет — NSWE=0 (запертая ячейка) легитимен.
7. **Отчёт гео — тот же формат, свои типы** (пакеты не связаны ребром): `Entry{File, Code,
   Block, Offset, Message}`; `Report` со счётчиками Regions, BlocksFlat/Complex/Multilayer,
   LayersTotal, MaxLayersPerCell, DupLayerZ (два слоя одной ячейки с равной Z — широта,
   канон не запрещает), ExtraTiles (файл вне тайлов канона 16..26 × 10..25), SkippedDirs,
   IgnoredFiles (имена корня вне паттерна — видимость состава каталога), BytesMapped,
   HeapIndexBytes, Files; `Errors []Entry`; `Manifest [32]byte` — SHA-256 по сортированному
   составу, фрейминг P2.1 один в один (le64(len(name)) ‖ name ‖ contentHash); состав —
   файлы, установленные как регионы (по одному на координаты; dup-проигравшие и битые не
   входят). Манифест
   опережает букву P2.3 — оставлен осознанно: идентичность пакета для КТ-3, вход P2.7 и реплея
   D1–D6; цена хэширования GB-объёмов измеряется бенчем (BenchmarkManifest) и выжимкой КТ-3,
   P2.7 заменяет её хэшем артефакта. `HasErrors()`.
8. **`LoadDir(dir string) (*Map, *Report, error)`** — прямой `os.ReadDir(dir)` (fs.FS не
   вводится: интерфейс не отдаёт ни путь, ни дескриптор под mmap — его появление вынудило бы
   копию в кучу или тайп-асперт к *os.File; embedded-байты P2.7 — другой источник по решению
   2). Имена `^\d+_\d+\.l2j$` регистронезависимо по расширению, числа без нормализации —
   дубль координат ловится кодом dup независимо от записи имени; подпапки — счётчик
   SkippedDirs, прочие имена — счётчик IgnoredFiles. Порядок обработки — сортированный
   (детерминизм манифеста и отчёта). error — только фатальное (каталог не читается); всё
   остальное — в отчёт.
9. **cmd/l2data: подкоманда `geo <каталог>`** — geo.LoadDir → печать счётчиков и ошибок,
   exit 0/1; при Regions=0 — заметная строка «регионы не загружены — проверьте каталог и
   формат (нужен L2J .l2j)» и exit 1 (защита от тихой путаницы форматов — канон для пустого
   набора тоже снижает функциональность явно, GeoEngine.java:127–132). Тонкий wire-up;
   `check` не меняется.
10. **Синтетика — наши байты** (исключение ADR-0001: байтовые фикстуры тестов): билдер
    encodeRegion в тестах, детерминированный; golden-файлы .l2j в internal/geo/testdata
    (2 файла: flat-тяжёлый и multilayer-тяжёлый) — пин байтового формата и сиды фаззера.
    Гвард «данные не в репо» (internal/data/guard_test.go) расширяется: .l2j в списке
    расширений дистрибутива, whitelist — точечно два golden-файла (как P2.1, не каталог);
    red-proof: файл с дистрибутивным именем NN_NN.l2j внутри testdata — красный.
11. **Тесты (TDD, красная фаза отдельным коммитом):**
    - Golden round-trip: билдер → DecodeRegion → зонды Nearest/LowerZ/HigherZ/BlockType
      против известных высот и NSWE: все 3 типа блока (flat: NSWE_ALL!), 1–3 слоя и граница
      125, знаковые высоты, все 16 NSWE (complex), границы (блок 0/65535, ячейка 0/63,
      регион 0/31).
    - Таблица злых входов: каждый код — отдельный кейс (обрезки всех типов на разных
      смещениях, тип 3/255, nLayers 0/126, хвост 1 байт, пустой файл, имя вне диапазона,
      дубликат региона (включая ведущие нули и регистр), размер сверх потолка — через функцию
      размера); ошибки с местом (блок/офсет), не паника.
    - Координаты: world↔geo против значений канона (−655360→0, +8 центр, regionX = geoX/2048,
      граница 2047/2048), вне мира — RegionAt nil.
    - Nearest/Lower/Higher семантика: точное Z, ближайший, первый при равенстве, fallback
      worldZ, слои с равной Z → DupLayerZ (порты канона).
    - CellAt вне региона — паника контракта с диагностикой (тест соседней координатой).
    - Манифест: два прогона — одинаков; изменение байта — другой.
    - 0-аллок: AllocsPerRun==0 таблично на весь публичный API представления (RegionAt, CellAt,
      BlockType, Nearest, LowerZ, HigherZ — flat/complex/multilayer).
    - Off-heap: multilayer-тяжёлый синтетический файл (~10–12 МБ) через MapFile → heap-рост
      ≤ 1.3 × HeapIndexBytes из отчёта (доказательство «в куче — только известные индексы,
      байты вне кучи»; порог от данных — отказ, состав файла меняет пропорцию).
    - MapFile: temp-файл с golden байтами → байты равны → DecodeRegion → unmap; пустой файл —
      пустой слайс; Windows (локально) и unix (CI).
    - Fuzz FuzzDecodeRegion: не паника; при успехе — выборочные (не полный свип — throughput)
      лукапы блоков не паникуют и держат инварианты портов: LowerZ(z) ≤ z ≤ HigherZ(z) и
      Nearest-высота ∈ высотам слоёв ячейки. В CI-смоуке (целей станет 9), сиды — golden и
      обрезки.
    - Example для пакета (codestyle §10, прецедент P2.1): DecodeRegion + CellAt.Nearest на
      миниатюрном регионе с выводом.
12. **Бенчмарки (реестр ADR-0005, строка «Геодата: canMove/пасфайнд | geo» уже есть — правка
    ADR не нужна):** RegionAt (в мире и вне мира — точка входа A* фазы 4), CellAt{Flat,
    Complex,Multilayer}, BlockType{Flat,Complex,Multilayer}, Nearest (2–3 слоя), LowerZ,
    HigherZ (зеркально), DecodeRegion (время, B/op, allocs, SetBytes = МБ/с — цена индексов),
    Manifest (SetBytes = ГБ/с — цена хэша). ReportAllocs на всех бенчах. baseline -count≥10 →
    benchmarks/P2.3-geo-baseline.txt; числа — в журнал.
13. **Атрибуция:** порты GeoEngine (константы, раскладка, getNearestLayer,
    getNextLowerZ/HigherZ, координаты, NSWE_ALL flat, правило 1000) — источником в
    doc-комментариях (`// Mobius GeoEngine …`), как P2.1/P2.2.

### Критерии приёмки (фальсифицируемые)

- Golden round-trip зелёный; таблица злых входов — каждый код ловится с местом, не паника.
- Fuzz-цель в CI-смоуке; сид-прогон зелёный.
- AllocsPerRun==0 на всём публичном API представления; бенчи в baseline-файле; числа в журнале.
- Off-heap тест зелёный (heap-рост ≤ 1.3 × HeapIndexBytes); MapFile проверен на Windows
  локально и unix в CI.
- Гвард ловит .l2j вне whitelist и файл с дистрибутивным именем внутри testdata (red-proof с
  откатом).
- `l2data geo` на синтетике: exit 0 и счётчики; на подложенном злом файле — exit 1 с местом;
  Regions=0 — exit 1 с заметной строкой.
- Ворота зелёные покомпонентно (gofmt/vet/build/test/staticcheck/checkdeps; -race — CI, gcc
  нет); external require — ноль.
- КТ-3 (вне конвейера, за владельцем): реальный пакет — выжимка прогона в журнал (включая
  HeapIndexBytes и время манифеста — входы для порога sidecar P2.7).
