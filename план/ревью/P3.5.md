# Реестр находок P3.5

- Задача: P3.5 «Пакеты мира скелета — internal/protocol» (план/p3.md)
- Ревью-профиль: S2 — инвариантщик, безопасник, доменщик, перформансер, прагматик; S8 — + тестировщик

## S0-проработка (правлена по F1–F25 раунда-1; объект ревью S2)

Опорные факты кода: хендшейк и фаза выбора персонажа уже типизированы в P1.4
(Write/View: ProtocolVersion, AuthLogin, Logout, CharacterSelect, KeyPacket, GSLoginFail,
CharSelectionInfo, CharSelected; Attack в P1.4-бое) — P3.5 их не трогает. Конвенции:
писатель `func(dst []byte, …) int` с константой опкода при пакете, представление
`type XView []byte` + конструктор-валидатор + геттеры по офсетам; **по прецеденту P1.4 каждый
пакет получает обе стороны** — писателя (отправляет сервер или l2client) и представление
(разбирает сервер или тест-оракул/l2client); фикстуры `fixture/testdata/<группа>.json`
(hex payload после опкода, origin=generated); `TestConstantsMatchCatalog` — машинная связь
констант; fuzz-цели в Makefile fuzz-smoke + ci.yml. Референс канона: L2J Mobius CT_0_Interlude
@43ac8878 (gitlab.com/expcero/L2J_Mobius), пути
`java/org/l2jmobius/gameserver/network/{clientpackets,serverpackets}/*.java`; доп. сверка —
udisondev/interlude@34fe4c8. Исходники выкачаны в /tmp/mobius_gs (вне репо).

### Состав (по потребителям P3.6–P3.11)

Размеры: C→GS-таблица — payload после опкода; GS→C — итоговый размер кадра с опкодом.

**Каждый пакет: писатель + представление.** Представления больших пакетов (CharInfo/UserInfo/
NpcInfo) — конструктор + геттеры по потребителю оракула (objId, имя, позиция, класс), не все
~70 полей; писатели C→GS нужны l2client (прецедент WriteAuthLogin/WriteCharacterSelect из P1.4)
и закрываются в P3.5 (P3.6 расширяет l2client, но не protocol).

  стек-копия, без алиасинга; аргумент в doc-комментарии).

### Решения S0 после раунда-1 (F1–F25)

1. CharacterDelete: канонный флоу требует ответа → view + WriteCharDeleteFail (отказ
   REASON_DELETION_FAILED=1); CharDeleteOk не пишем.
2. Пустые списки — писатели без параметров (WriteEmpty*); ItemList — showWindow=0 по канону входа.
3. CreatureSay/SystemMessage — по одному минимальному режиму; расширение — с потребителем.
4. EnterWorldView — только проверка длины, без геттеров (hwinfo/tracert не потребляются).
5. Полная таблица ChatType — по прецеденту полных таблиц канона (login.go Reason*); «ошибки
   создания» спеки = причины CharCreateFail 0x00–0x06 (SystemMessage-Id для них не существует) —
   соответствие записано (F18).
6. Дубль чисел шаблона в фикстурах — осознанный (P3.3), атрибуция HumanFighter.xml.
7. Say2View.Target() остаётся: часть переменно-структурного формата (хвост whisper),
   потребляется тест-оракулом; runtime-потребитель — фаза 5+ (F22).
8. ActionFailed типизируется (1 байт, канонические потребители уже в фазе 3) (F9).
9. Пакеты слитка входа (кроме ActionFailed) — P3.7-S0 по букве её спеки (F9).
