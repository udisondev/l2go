## Порядок запуска

Из корня репозитория (cmd/ и var/ создаются сами, var/ в gitignore):

1. mTLS-материал стыка (однократно):
   `go run ./cmd/l2login cert -out var/tls`
2. Собрать артефакт статики (парсинг+валидация; выход 1 = красные данные):
   `go run ./cmd/l2data build <корень датапака> <каталог геодаты> -o var/static.l2a`
   (артефакт ~1 ГБ с реальной геодатой; без геодаты сервер не поднимется —
   регион проверяет гео-секцию? — нет: гео нужна P3.9 для клампа, но вход
   работает и на данных без гео; всё же для КТ-3 полный состав правильнее.)
3. Запустить LoginServer (держать процесс открытым):
   `go run ./cmd/l2login -tls var/tls`
   (LS слушает :2106, стык gRPC :9011)
4. Запустить игровой сервер (вторым процессом):
   `go run ./cmd/l2go -artifact var/static.l2a -link 127.0.0.1:9011 -tls var/tls`
   Лог «контур поднят» и отсутствие ошибок регистрации = GS в ServerList.
5. В l2.ini клиента прописать адрес машины с LS (если клиент на той же
   машине — 127.0.0.1).
6. Прогон: логин (аккаунт создастся автоматически при первом входе —
   авто-создание включено по умолчанию) → создание персонажа → выбор →
   «войти в мир» → осмотреться → логаут → повторный вход.

## Что смотреть (чек-лист для владельца)

- После выбора персонажа клиент не виснет и не вылетает (слиток принят).
- Персонаж стоит на стартовой позиции, видно имя/уровень/HP/MP.
- UserInfo-имя совпадает с созданным.
- Логаут: возврат к выбору сервера (LeaveWorld), не «разрыв соединения».
- Повторный вход: та же позиция (round-trip персиста).
- В логах l2go нет ERROR-строк.

## Если клиент виснет/вылетает

Запустить тап между клиентом и сервером (P1.6: cmd/l2tap) и прислать журнал
декодера — по нему видно, на каком кадре клиент споткнулся. Три suspects
уже записаны (О-С1..3); буфер на дофикс зарезервирован в реестре P3.7.
