# план/ — планы и прогресс исполнения

Здесь планируются фазы из [r2.md](../research/r2.md) и фиксируется прогресс. Теория живёт в
`research/` (r0–r2), решения — в `docs/adr/`, этот каталог — исполнение.

## Структура

- `pN.md` — план фазы N. Пишется **до** стара фазы; правки по ходу — явные, с записью в
  прогресс, а не молча.
- `прогресс.md` — журнал: что сделано, что решено, что заблокировано.

## Конвенции

**Статусы задач:** ⬜ не начата · 🔄 в работе · 👀 на ревью человека · ✅ принято · ⛏ заблокирована.

**Definition of Done задачи:** все критерии приёмки выполнены + пройдены человеческие контрольные
точки, указанные в задаче. Статус ✅ ставится только после этого.

**Формат задачи** (единообразный по всем планам): Спецификация → Критерии приёмки
(фальсифицируемые, где возможно — машинно проверяемые) → Зависимости → Ссылки на research/ADR.
Текст задачи = spec-first слайс для агента: передаётся агенту как есть, без пересказа.

**Ревью-профиль** (с ADR-0006): строка в задаче задаёт состав панелей ревью конвейера; без
явной строки — профиль по умолчанию по типу задачи. Находки конвейера живут в реестре
`ревью/<ID>.md` рядом с планами фаз.

**Правило ворот:** если работа не проверяется `make check` или тестом — она не сделана. Новая
критерия проверяемости, найденная по ходу, добавляется в план задачи, а не живёт в чате.

**Связь слоёв:** research/ отвечает «почему так», план/ — «что и в каком порядке делаем»,
docs/adr/ — «что решили и какой ценой». При конфликте победитель — самый свежий accepted-ADR;
r0–r2 читаются как его предыстория.
