# p1 — План фазы 1: Протокол и headless-клиент

Исполнение [r2.md](../research/r2.md) §Фаза 1. Входы из референсов владельца — [r4.md](../research/r4.md)
(клоны в `_refs/` вне репозитория). Карта пакетов и реестр горячих путей —
[ADR-0005](../docs/adr/0005-karta-komponentov.md); каждая задача проходит ревью-конвейер
[ADR-0006](../docs/adr/0006-revyu-konveyer-zadach.md) (реестр находок — `ревью/<ID>.md`).
Конвенции ведения планов: [README.md](README.md).

**Цель фазы:** бинарный слой протокола Interlude 746 доказан машиной — криптодвижок, кодек и
каталог опкодов покрыты golden-тестами против байтовых фикстур и fuzz-раундтрипом (смоук в CI);
headless-клиент проходит логин-флоу против сценария из реальных байтов и декодирует трафик в
читаемый лог. Клиент — главный актив проекта: актив проверки фаз 3–4 (сервер, боты,
дифф-тесты). Конвейер ADR-0006 откалиброван метриками первых задач.

**Оценка:** 5–8 агентных сессий + человеческие контрольные точки (источник фикстур, калибровка
конвейера, приёмки ✅).

## Выход фазы (Definition of Done)

- [ ] `internal/crypto`: движок шифра протокола (Blowfish, XOR статический/динамический,
      checksum, паддинг, RSA-блок логина) с golden-векторами и бенчмарками криптоблока.
- [ ] `pkg/bufpool`: бакетный пул байтовых буферов с бенчмарками Get/Put, без доменных
      зависимостей.
- [ ] `internal/protocol`: каталог опкодов 746 по направлениям (полнота и уникальность машинно
      проверяемы, сверка с референсами зафиксирована), примитивы записи/чтения, конвенция
      писателей/представлений на живом коде.
- [ ] Пакеты логин-флоу и хендшейка типизированы: golden encode/decode на каждый пакет.
- [ ] `internal/l2client` + `cmd/l2client`: подключение → логин-флоу → декод трафика в
      читаемый лог; интеграционный тест на in-process сценарий-сервере из фикстур.
- [ ] Fuzz-цели (раундтрип, малформенные входы) с corpus в testdata; fuzz-смоук в CI активен
      (заглушка снята).
- [ ] Все порты из референсов помечены источником; NCsoft-derived данные в репо — только
      байтовые фикстуры golden-тестов.
- [ ] Метрики конвейера первых задач (P1.1–P1.3) записаны в журнал; калибровка бюджетов
      зафиксирована (правка — если числа потребуют).

## Задачи

Формат: каждая задача — готовый spec-first слайс для агента (текст раздела = спецификация;
проработка и уточнение — стадии S0–S4 конвейера). Критерии приёмки фальсифицируемы.
Статусы: ⬜ не начата, 🔄 в работе, 👀 на ревью человека, ✅ принято, ⛏ заблокирована.

### P1.1 Криптодвижок протокола — ✅

**Спецификация.** Порт криптоблока из референсов (`_refs/interlude/pkg/crypto`,
`_refs/la2go`), семантика сверяется с Mobius/aCis; атрибуция каждого порта в комментарии
источником. Состав:

- Blowfish с таблицами L2J; статический XOR-ключ 8 байт; динамический ключ (после
  хендшейка); checksum кадра; паддинг до 8 байт.
- RSA-скрамбл-блоб логина (учётные данные в AuthLogin шифруются открытым ключом сервера).
- Движок кадра на соединение без внутренней синхронизации (владелец — соединение):
  инициализация (login-ключ из Init-пакета; game — статический + динамический после
  хендшейка), Encrypt(payload) → кадр, Decrypt(кадр) → payload с проверкой checksum.

Первичные golden-векторы — из тестов референсов (байтовые константы); расширение корпуса
живым трафиком — через P1.6. Источник векторов согласуется с владельцем в S0 (контрольная
точка 1).

**Критерии приёмки.**
- Property-тест раундтрипa encrypt→decrypt == payload (включая паддинг-граничные длины).
- Golden-векторы блоков (Blowfish, XOR, checksum, RSA) зафиксированы байтами; сверка с
  референсом воспроизводима (указан коммит референса).
- Бенчмарки криптоблока в пакете (кадры 40/256/1456 Б — 8-кратные; исходное «1460»
  черновика некратно блоку, 256 добавлен для сопоставимости с якорем la2go — фиксация
  отклонения: реестр план/ревью/P1.1.md, F7); шифр готового кадра —
  0 аллокаций; baseline записан в журнал benchstat-выпиской (ориентир la2go ~864 нс/шифр —
  не бюджет).
- Таблица злых входов: обрезанный кадр, размер не кратен 8, битый checksum → детерминированная
  ошибка, не паника.
- Ворота зелёные; зависимостей нет — ни внутренних (checkdeps), ни внешних (allowlist
  в checkdeps пуст; Blowfish — собственный порт из BSD-3/GPL референсов с атрибуцией —
  решение владельца на приёмке S9, откат F1: реестр план/ревью/P1.1.md, F31).

**Ревью-профиль:** S2 — инвариантщик, безопасник, перформансер, прагматик; S8 — + доменщик,
тестировщик.

**Зависимости:** нет. Первая задача фазы — первый полный прогон конвейера, её метрики
калибруют бюджеты 2/2/3.

**Ссылки:** r2 §Фаза 1; r4 §«Что переносим»; ADR-0001 (GPL-гигиена портов); ADR-0005
(матрица: crypto без зависимостей; реестр путей — криптоблок).

### P1.2 Бакетный пул буферов — pkg/bufpool — ✅

**Спецификация.** Порт `BytePool` из interlude: бакеты 128/256/512/1024/2048/4096, per-bucket
`sync.Pool`, `Get(size)` → буфер бакета ≥ size (свыше 4096 — прямая аллокация), `Put`;
статистика Get/Put/overflow. Критерий жителя `pkg/`: без доменных зависимостей, полезен вне
проекта (ADR-0005). Конвенция владения буфером документируется здесь же: малые пакеты — стек,
пул — для крупных; дисциплина Put обязательна на горячих путях.

**Критерии приёмки.**
- Таблица бакетов: Get возвращает буфер длины ≥ запрошенной; поведение Put с чужим размером
  определено явно (по исходнику) и протестировано.
- Конкурентный стресс Get/Put под `-race` (CI).
- Бенчмарки Get/Put по бакетам; сравнение с прямой аллокацией записано в журнале.
- Атрибуция порта; `pkg/bufpool` импортирует только stdlib (checkdeps).

**Ревью-профиль:** S2 — инвариантщик, конкурентщик, перформансер, прагматик; S8 — +
тестировщик.

**Зависимости:** нет (контентно независима от P1.1).

**Ссылки:** r4 §«Модель владения пакетом»; ADR-0005 (критерий `pkg/`, реестр путей — пул).

### P1.3 Каталог опкодов и примитивы кодека — internal/protocol — ✅

**Спецификация.** Три части:

1. **Каталог опкодов** Interlude 746 из `_refs/interlude/docs/opcodes.md` (494 записи),
   таблицы по направлениям (S→C и C→S не совпадают); каждая запись сверяется с Mobius/aCis
   до фиксации, расхождения — списком в реестре задачи. Форма: константы + машинная проверка
   (полнота против каталога-источника, уникальность опкода в направлении, имя↔константа
   взаимно однозначны).
2. **Примитивы кодека:** writeD/H/F/Q/S (UTF-16LE, null-терминация) и парные read — порт
   helpers interlude с атрибуцией.
3. **Golden-рамка фикстур:** формат (направление, опкод, имя, байты payload) и загрузчик
   testdata; первичные фикстуры — векторы из референсов, пополнение живым трафиком — P1.6.
   Стабы-образцы скелета (`WriteAttack`, `AttackView`) заменяются живыми примитивами.

Конвенция писателей не вводит механизмов дедупликации на формате — повторная отправка
безвредна (дедупликация спавнов — поведение клиента по objectID, ADR-0004).

**Критерии приёмки.**
- Тест машинно проверяет таблицу: счёт записей равен источнику, опкоды уникальны в
  направлении, имена взаимно однозначны.
- Fuzz-раундтрип каждого примитива write→read == значение (включая UTF-16 строки и
  отрицательные); float — по битам.
- Бенчмарк писателя 40-байтового пакета на стеке: 0 аллокаций (реестр «пакет-писатель»).
- Метод сверки каталога зафиксирован (референсы, версии/коммиты), расхождения — списком.

**Ревью-профиль:** S2 — инвариантщик, безопасник, перформансер, доменщик, прагматик; S8 — +
тестировщик.

**Зависимости:** P1.1, P1.2 по порядку исполнения (контентно — только формат-рамка фикстур).

**Ссылки:** r2 §Фаза 1; r4 (каталог 494, helpers); ADR-0004 (повторные спавн-пакеты); ADR-0005
(protocol без зависимостей; реестр — писатель).

### P1.4 Пакеты логин-флоу и хендшейка — 👀

**Спецификация.** Типизация пакетов по конвенции (писатели S→C для будущего сервера и
сценария-сервера тестов; представления C→S для клиента):

- **Login-протокол — полный:** Init (Blowfish-ключ, session ID), AuthLogin (учётные данные в
  RSA-блобе), LoginOk/LoginFail/AccountKicked, ServerList, PlayOk/PlayFail, GG-пробы (если
  референс их посылает).
- **Game-хендшейк и минимальный вход:** ProtocolVersion, CryptInit/KeyPacket, AuthLogin,
  Logout, CharList, CharSelected — состав по фактуре Mobius (Interlude).

Поля каждого пакета сверяются с Mobius/aCis (атрибуция портов семантики). Пакеты мира не
тиизируются (анти-скоуп) — вне типизированных клиент декодирует по каталогу (P1.5).
`internal/login` (серверный код) — не фаза 1.

**Критерии приёмки.**
- На каждый пакет: golden encode (писатель → байты == фикстура) и golden decode (представление
  над фикстурой → поля).
- Отрицательная таблица: обрезанный payload, чужой опкод, переполненные длины строк →
  детерминированная ошибка, не паника.
- Опкоды пакетов берутся константами из таблицы P1.3 (магические числа запрещены).

**Ревью-профиль:** S2 — инвариантщик, безопасник, доменщик, прагматик; S8 — + тестировщик.

**Зависимости:** P1.1 (RSA/checksum), P1.3 (таблица, рамка фикстур).

**Ссылки:** r2 §Фаза 1 (флоу логина); r4 (l2client, Mobius/aCis как фактура); внешние
референсы r2 (ruk33).

### P1.5 Headless-клиент — internal/l2client + cmd/l2client — 👀

**Спецификация.** Библиотека клиента поверх protocol+crypto (матрица ADR-0005):

- TCP-подключение (deadlines, TCP_NODELAY), разрез байтового потока на кадры — чистая
  функция, общая с будущими проводами сервера (вопрос строки реестра для входящего фрейминга
  решается в задаче правкой ADR-0005, если нужно).
- Криптодвижок на соединение (P1.1), стейт-машина флоу: login → выбор сервера → game-хендшейк.
- Диспетчер по опкодам; читаемый лог трафика: типизированные пакеты — поля, прочие — имя из
  каталога + hex-дамп.
- `cmd/l2client` — тонкая обёртка: адрес, аккаунт, режим логирования.

Тестирование: in-process сценарий-сервер (net.Pipe/localhost), отвечающий golden-байтами
P1.4, — клиент проходит флоу, лог сравнивается с golden. Живая проверка против
референс-сервера (если поднят владельцем) — ручная контрольная точка, не CI. Конкурентность:
горутина чтения + команды каналом; общей мутации нет.

**Критерии приёмки.**
- Интеграционный тест: сценарий-сервер → клиент прошёл логин-флоу до game-хендшейка включительно;
  лог трафика совпал с golden.
- Пакет вне типизированных — в логе с именем из каталога и hex-дампом (тест на таком пакете).
- Таблица злых входов: мусор от сервера, обрыв соединения посреди кадра → клиент не паникует,
  завершается с ошибкой.
- Бенчмарк разреза потока на кадры.
- `cmd/l2client` собирается; прогон против записанного сценария воспроизводит лог.

**Ревью-профиль:** S2 — инвариантщик, конкурентщик, безопасник, прагматик; S8 — + тестировщик,
доменщик.

**Зависимости:** P1.1–P1.4.

**Ссылки:** r2 §Фаза 1 (headless-клиент — главный актив; боты фазы 4, дифф-тесты); r4
(`pkg/l2client` — задел); ADR-0005 (матрица: l2client ← protocol, crypto).

### P1.6 pcap-analyzer (пере-формулировано: tap + декодер) — 👀

**Спецификация.** Порт `cmd/pcap-analyzer` из interlude: читает pcap-дамп сессии (login+game),
восстанавливает TCP-потоки, извлекает ключи (динамический — из Init/KeyPacket), расшифровывает,
разрезает на пакеты, печатает читаемый лог и выгружает фикстуры в формате P1.3. Логика — в
отдельном внутреннем пакете (новая строка матрицы ADR-0005, правка в задаче); cmd — только
wire-up. Инструмент разработчика: живые дампы в репо не попадают (NCsoft-derived), фиксируются
только производные байтовые фикстуры (разрешённое исключение ADR-0001).

Самотест без живых дампов: синтетический pcap собирается из golden-байтов (сценарий-сервер
P1.5 как генератор) и прогоняется через анализатор — фикстуры на выходе совпадают с входными.

**Критерии приёмки.**
- Синтетический дамп → полный конвейер pcap → фикстуры; фикстуры совпали с исходными
  (раундтрип инструмента).
- Прогон на живом дампе владельца (если есть) — ручная контрольная точка: лог совпал с
  ожиданием, фикстуры пополнили testdata.
- Живые дампы в репо отсутствуют (проверка тестируемым списком расширений).

**Ревью-профиль:** S2 — инвариантщик, прагматик; S8 — + тестировщик.

**Зависимости:** P1.3 (формат), P1.4 (состав флоу), P1.5 (сценарий-сервер как генератор).

**Ссылки:** r4 (pcap-analyzer — источник фикстур); ADR-0001 (исключение для фикстур).

### P1.7 Fuzz-смоук в CI — ⬜

**Спецификация.** Активация заглушки `ci.yml`: fuzz-цели protocol (раундтрип примитивов и
пакетов), crypto (малорменные кадры), фрейминг (обрывы потока). Смоук `-fuzztime=10s` на CI;
seed corpus в `testdata/fuzz`; находки фаззера → фикс + пополнение corpus регресс-тестом.
Локальная команда длинного фаззинга задокументирована.

**Критерии приёмки.**
- CI-шаг активен и зелёный; заглушка-комментарий снят.
- Каждая цель детерминированно падает на злом входе (не паника) — проверено тестом.
- Найденные фаззером входы (если были) зафиксированы регресс-тестами.

**Ревью-профиль:** облегчённый режим (самопроверка + ворота + один ревьюер + владелец).

**Зависимости:** P1.3–P1.5.

**Ссылки:** r2 §Фаза 1 (fuzz); план/p0.md P0.2 (таблица активации ворот); ADR-0006 §6
(облегчённый режим).

## Порядок исполнения

```
P1.1 (крипта) → P1.2 (bufpool) → P1.3 (опкоды+кодек) → 📊 контрольная точка 2
→ P1.4 (пакеты логин-флоу) → P1.5 (headless-клиент) → P1.6 (pcap-analyzer) → P1.7 (fuzz CI)
```

- P1.1 и P1.2 контентно независимы (порядок между ними не существен); остальное — по
  зависимостям.
- Все задачи — полный конвейер ADR-0006, кроме P1.7 (облегчённый); ведущая сессия ведёт по
  одной задаче за раз.
- Первые три задачи — первый полный опыт конвейера: их метрики обязательны в журнал
  (контрольная точка 2).

## Анти-скоуп (в фазу 1 НЕ входит)

- Серверный код: login-сервер (`internal/login`), game-провода (`internal/conn`),
  шлюз, транспорт, мир — фазы 3+; в фазе 1 допустим только тестовый сценарий-сервер внутри
  тестов l2client.
- Типизация всех 494 опкодов и пакеты мира/боя — по потребности фаз 3+ (вне типизированных
  клиент декодирует каталогом + hex).
- Энкод-стадия per-client FIFO (слэбы, ADR-0004) — со шлюзом и миром; в фазе 1 только
  криптоблок и писатели.
- gRPC-стыки (loginlink, admin), репликация, персист — фазы 3+.
- Боты и нагрузочные сценарии — фаза 4 (клиент лишь закладывает основу).
- Версии протокола кроме Interlude 746 — не поддерживаются.
