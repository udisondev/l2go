# p2 — План фазы 2: Статические данные — датапак и geodata

Исполнение [r2.md](../research/r2.md) §Фаза 2. Гео-дизайн — [r1.md](../research/r1.md); референсы —
[r4.md](../research/r4.md) (клоны `_refs/` вне репозитория) и GPL-каноны (Mobius/aCis). Карта
пакетов и реестр горячих путей — [ADR-0005](../docs/adr/0005-karta-komponentov.md): строки
`internal/data` и `internal/geo` уже в матрице (обе без зависимостей), правка ADR нужна только
для новых рёбер/подпакетов. Лицензионная гигиена — [ADR-0001](../docs/adr/0001-licenzionnaya-poziciya.md):
данные NCsoft-derived в репо не коммитятся. Конвейер — [ADR-0006](../docs/adr/0006-revyu-konveyer-zadach.md),
реестры находок — `ревью/<ID>.md`. Конвенции планов — [README.md](README.md).

**Цель фазы:** контент становится данными с машинной проверкой целостности. Парсеры датапака L2J
(предметы, NPC, спавны, дроплисты, зоны, скиллы) дают типизированные иммутабельные структуры и
**отчёт валидации**, где битая ссылка = ошибка сборки данных, а не строчка в логе. Геодата
раскладывается в off-heap представление из r1 (байты блоков + zero-copy лукапы), поверх него —
примитивы `canMove` / `getNearestZ` / `canSee` как чистые функции. Сборка и загрузка разделены:
валидация исходников — на сборке статики, рантайм грузит компилированный артефакт (release-сборка
владельца вшивает его в бинарарь). Фаза 3 получает на вход проверенную статику: walking skeleton
не отлаживает одновременно интеграцию и данные.

**Оценка:** 6–8 агентных сессий + контрольные точки владельца (источники данных, ручные полные
прогоны, приёмки ✅).

## Выход фазы (Definition of Done)

- [ ] `internal/data`: загрузчик категорий датапака в типизированные структуры; ссылочная
      целостность машинно проверяется (дроп→предмет, спавн→NPC, спавн→территория, скилл→предмет);
      нарушение = ошибка загрузки.
- [ ] Каркас отчёта валидации: записи (категория, файл, ID/строка, код), счётчики, коды выхода;
      один и тот же код работает в CI (синтетика), в локальном полном прогоне и при старте
      сервера (фаза 3).
- [ ] `cmd/l2data`: `check <корень данных>` — загрузить всё зарегистрированное, напечатать отчёт;
      тонкий wire-up без логики.
- [ ] Компилированный артефакт статики: `l2data build` (парсинг + валидация + компиляция) и
      быстрый `Load` без копирования в кучу; транспорт — mmap внешнего файла (dev/CI) и embed за
      build-тегом (release владельца: сервер = один файл); эквивалентность «артефакт == парсинг
      исходников» машинно проверяется; числа сборки/загрузки — в журнал.
- [ ] `internal/geo`: парсер L2J-геодаты → off-heap mmap-представление (region→block→cell→layers)
      с валидацией структуры; примитивы `canMove`/`getNearestZ`/`canSee` с бенчмарками
      (реестр ADR-0005 «Геодата: canMove/пасфайнд») и 0 аллокаций на лукапе.
- [ ] Синтетические фикстуры (сгенерированы проектом, не NCsoft-derived) в `testdata` для CI;
      реальные данные — вне репо, отсутствие в репо машинно проверяется по расширениям.
- [ ] Fuzz-смоук CI дополнен целями парсеров (малформленный XML, битые гео-блоки).
- [ ] Ноль внешних зависимостей (allowlist в checkdeps пуст).
- [ ] Ручные полные прогоны на реальном датапаке и геодате владельца — выжимки отчётов в журнал.

## Ключевые решения плана (с отвергнутыми альтернативами)

1. **Разделение сборки и загрузки: исходники XML парсятся и валидируются при сборке статики,
   рантайм грузит компилированный артефакт.** `l2data build/check` — парсинг дистрибутива и
   отчёт валидации (битая ссылка = красная сборка данных); сервер и тесты грузят артефакт — без
   XML и без файлового разбора на старте. Артефакт — одноразовый кэш, а не формат персистенции:
   несовпадение версии схемы или хэша входов = пересбор, миграций не существует как класса.
   Альтернативы отвергнуты: БД (pgx + goose референсов — персист-слой статике не нужен,
   зависимость и инфраструктура); парсинг при каждом старте (работа, не меняющаяся между
   запусками, оплачена каждым тестом и рестартом фаз 3–6); кодогенерация в Go-исходник
   (линк-налог на каждую сборку, NCsoft-derived в исходнике, перекомпиляция пакета на каждую
   правку поля).
2. **Формат-канон датапака — Mobius, ветка Interlude.** Уже канон проводов фазы 1 (сверка
   каталога опкодов — ноль расхождений значений) и XML-first: все категории читаются stdlib
   `encoding/xml`, ноль зависимостей сохраняется. aCis (микс SQL+XML) — второй оракул для
   выборочной сверки значений, но не формат-источник: SQL-дамп-парсер — новая поверхность без
   потребителя. Финальное слово за КТ-1: датапак на диске владельца может оказаться другим
   дистрибутивом.
3. **Данные живут вне репо.** Каталог вне git (путь — флаг/env, решается в S0 P2.1); в репо —
   только синтетические фикстуры и производные числа в журнале. Подмодуль или отдельный репо
   отвергнуты: усложнение CI против буквы ADR-0001 («в репо не коммитятся»). Полный прогон
   валидации — ручная КТ, CI работает на синтетике.
4. **Полнота типизации — по потребителю.** Скиллы фазы 2 — структурный каркас (id/уровень/цели/
   тайминги/флаги/цепочки уровней) с сохранением сырых параметров эффектов; глубина полей —
   фазам 4/6, где появляются потребители формул. Тот же принцип, что и типизация опкодов в
   фазе 1: поля без потребителя — источник агентских галлюцинаций.
5. **Примитивы гео — в фазе 2, не в фазе 3.** Чистые функции над иммутабленной статикой —
   идеальная агентская почва (оракул: синтетическая геометрия + семантика GeoEngine канона);
   фаза 3 остаётся тонкой интеграцией. Пасфайнд (A*, flow-field, граф слоёв) — анти-скоуп:
   r1/r2 относят его к фазам 4/6.
6. **Порядок задач — по критическому пути фазы 3, артефакт — последним.** Скелету нужны
   предметы, NPC+спавны, гео, `canMove` — это первые четыре задачи; зоны и скиллы потребуются
   позже и переносятся без переделок (входящих зависимостей нет). Артефакт (P2.7) — после того,
   как P2.1–P2.6 зафиксируют схемы всех категорий: формат компилируется один раз, а не
   эволюционирует шесть раз.
7. **Целостность = ошибка, неизвестное = счётчик.** Битая ссылка или дубликат ID роняет сборку
   данных (буква r2: «разрыв = ошибка сборки»); неизвестные enum-значения и непокрытые поля —
   счётчик с выпиской в отчёте: это широта данных, а не целостность. Политика уточняется в S2
   первой задачи.
8. **Транспорт статики — два, без копирования в кучу.** Исходники (XML) читаются через
   `io/fs.FS` (`os.DirFS` над путём — флаг/env). Артефакт: dev/CI — `syscall.Mmap` внешнего
   файла; release — embedded-байты за build-тегом `embedded` (файл-бэкированные страницы
   бинараря, спрос-пейджинг ОС, вне Go-кучи). Рабочий цикл владельца: подложить данные →
   `l2data build` → `go build -tags embedded` → сервер = один исполняемый файл. Решение
   владельца: бинарари не публикуются, сервер личный — лицензионная позиция ADR-0001 не
   затронута; появление дистрибуции — повод пересмотреть ADR. Сжатие артефакта не применяется
   (embed не сжимает; геодате нужен random access; размер владельца не беспокоит) —
   gzip-упаковка остаётся разрешённой эволюцией.

## Задачи

Формат: каждая задача — spec-first слайс для агента; проработка и уточнение — стадии S0–S4
конвейера. Критерии приёмки фальсифицируемы. Статусы: ⬜ не начата, 🔄 в работе, 👀 на ревью
человека, ✅ принято, ⛏ заблокирована.

### P2.1 Рамка датапака + категория «предметы» — internal/data, cmd/l2data — ✅

**Спецификация.** Каркас загрузки статики и первая категория на нём:

- Корень данных: `io/fs.FS` (`os.DirFS` над путём — флаг/env; данные вне репо). Граница fs.FS
  фиксируется сразу: исходники читаются одинаково из каталога и из `embed.FS`. Пакет
  `internal/data` рождается с кодом (строка матрицы есть); раскладка плоская, подпакет — только
  явной нуждой, это правка ADR-0005.
- Манифест входов: детерминированный хэш состава данных (файлы + хэши содержимого),
  вычисляется при загрузке: идентичность версии данных для реплея (D1–D6) и основа кэша P2.7.
- Каркас: регистрация категорий, контекст загрузки (корень, счётчики), сквозная идентификация
  места ошибки (файл+строка или ID); политика «целостность = ошибка, неизвестное = счётчик».
- Категория «предметы»: типизированная структура (id, имя, тип, слоты, вес, цена, stackable,
  кристаллизация и т.п.) — набор полей по минимальному потребителю фазы 3 (инвентарь, дроп,
  подбор) плюс тривиальное из формата; дубли ID — ошибка.
- `cmd/l2data`: `check` — загрузить зарегистрированные категории, напечатать отчёт, код выхода
  0/1. Тонкий wire-up, логика в пакете.
- Синтетическая мини-фикстура предметов в `testdata` (наша, не из дистрибутива) — база CI.
- Машинная проверка «данные не в репо» (список расширений/масок дистрибутива) — тестом.

**Критерии приёмки.**
- Синтетика грузится, поля совпадают с ожиданием (golden путь загрузки).
- Манифест-хэш детерминирован: два прогона над одним составом — одинаковое значение (машинный
  тест).
- Таблица злых входов: битый XML, обрезанный файл, дубликат ID, число за границами домена
  (включая знак), отсутствующий обязательный атрибут — детерминированная ошибка с местом, не
  паника; неизвестные enum-значения (тип предмета, set-ключи) — счётчик в отчёте (решение 7).
- Fuzz-цель малформленного XML добавлена в CI-смоук; находки — регресс-тесты.
- `cmd/l2data check` на синтетике: зелёный отчёт, exit 0; на подложенном злом входе
  (дубликат ID) — exit 1 с перечнем; битые ссылки — с P2.2 (перекрёстные ссылки появятся
  вместе с NPC и дроплистами).
- Ручной прогон владельца на полном датапаке — выжимка отчёта в журнал (КТ-3).
- Ворота зелёные; `internal/data` без зависимостей; внешних require нет.

**Ревью-профиль:** S2 — инвариантщик, безопасник, перформансер, прагматик; S8 — + доменщик,
тестировщик.

**Зависимости:** нет; первая задача фазы, в S0 закрывается КТ-1.

**Ссылки:** r2 §Фаза 2; ADR-0001 (данные вне репо, исключения только для фикстур протокола);
ADR-0005 (матрица: data без зависимостей; плоская раскладка); r4 (датапак-подходы референсов
отвергнуты — решение 1).

### P2.2 NPC, спавны, дроплисты — ✅

**Спецификация.** Витрина ссылочной целостности фазы. Формат — Mobius Interlude; факты
проработки — плоский состав без custom (custom пропускается, как у предметов P2.1): 82
NPC-файла `stats/npcs/` (максимум 507 КБ, каталог 13.6 МБ), 6519 NPC, дублей ID нет
(custom — ещё 15 файлов/24 NPC); 186 спавн-файлов `spawns/` (рекурсивно, максимум 249 КБ),
3751 блок, 11875 точечных и 9879 территориальных записей; 3630 территорий — все с
инлайн-геометрией, межфайловых ссылок на территории ноль, имена уникальны, атрибуты
shape/rad/собственный name — ноль вхождений, banned_territory 17; `zones=`/`selection=` —
ноль вхождений; дроп: 2069 NPC с drop, 1569 со spoil, 10708 групп, 39633 предмета; minion-
ссылок 540 (57 с атрибутом max); атрибут title — 2259; битых ссылок дроп→предмет (против
базы 9208), миньон→NPC — ноль; спавн→NPC — один случай: NPC 80000 (fake player, определение
только в custom), плюс 76 записей «точка и территория» и 29 точечных без heading; 4 шанса
>100 — все у Antharas (29019: 200; 29066–29068: 148.76); один min>max (22200-22299.xml:1319).

- **Каркас ссылок.** Единый механизм: ссылки копятся при разборе ({категория, файл, строка,
  владелец, вид, ключ}), разрешаются один раз после всех категорий Load; неразрешённая —
  запись-ошибка с местом (строковый ключ — в Message). Ссылки регистрируются только для
  записей, вошедших в статику (проигравший дубликат ID не оставляет фантомных ссылок).
  Порядок категорий не влияет на проверку. «Отложенный реестр» плана фазы сводится к этому
  механизму: в каноне геометрия территории лежит в том же файле, что и спавн, поэтому
  закрытие ссылок происходит в конце той же загрузки, не в P2.5. Каркас загрузчиков
  остаётся слайсом функций-загрузчиков, интерфейс категории не заводится (закрытие
  отложенного решения P2.1).
- **Граница «типизировано/raw-bag/пропущено» — одно правило:** плоский скалярный атрибут или
  лист поддерева → raw-bag с путевым ключом (stats.vitals.hp, equipment.rhand,
  ai.clanList.clan, npc.sex); поддерево без потребителя → SkippedElements; типизируется
  только то, что имеет потребителя фаз 3–4 или нужно ссылке. Дубликаты bag-ключей — побеждает
  последний, счётчик (как P2.1).
- **NPC** (`stats/npcs/*.xml`, корень `list`, вложенные каталоги — SkippedDirs): дубли ID —
  ошибка. Типизировано: Name, Title (потребитель — репликация NpcInfo фазы 3), Level int32
  (дефолт канона 85 при отсутствии + счётчик), Type (дефолт «Folk»; словарь типов канона,
  неизвестный — счётчик с квалификацией npc.type.*), Race (словарь рас, неизвестная —
  счётчик npc.race.*), AggroRange и ClanHelpRange int32, IsAggressive bool, Clans []string,
  IgnoreNpcIDs []NpcID (ссылки NPC→NPC — каркас), CollisionRadius/CollisionHeight float64.
  Миньоны (`parameters/minions/npc`) — MinionRef{NpcID, Count, Max, RespawnTime,
  WeightPoint} (Max — семантика getCount канона: при Max>Count число миньонов случайно в
  [Count,Max]); ссылки миньон→NPC — каркас. Прочее — raw-bag по единому правилу (включая
  npc.sex, npc.displayId, parameters.*, stats.hitTime, collision.grown, ai.*,
  sNpcPropHpRate и т.п.). Атрибут name спавн-блока (121 вхождение, не атрибут записи) —
  счётчик NamedBlocks.
- **Дроплисты** — подсекция NPC (`dropLists/{drop,spoil}/{group,item}`): DropList{Type,
  Groups []DropGroup{Chance, Items []Drop{ItemID, Min, Max, Chance}}, Items []Drop};
  порядок файла сохраняется (осознанное отклонение: канон сортирует при загрузке —
  нормализация останется за потребителем фазы 4). Домены: шанс — обязательное
  неотрицательное конечное число (канон: parseDouble без дефолта; минус, NaN,
  неразбор или отсутствие — ошибка; >100 — счётчик ChanceOver100); min/max —
  целые ≥ 0 (отрицательные/неразбор — ошибка; min>max — счётчик MinOverMax,
  в каноне один случай); отсутствие id — ошибка. Ссылка дроп→предмет — каркас.
- **Спавны** (`spawns/**/*.xml`, рекурсивный обход; `list` без enabled — ошибка разбора
  файла, `enabled="false"` — файл пропущен и посчитан): спавн-блок name?/zone?. Территория
  (инлайн) — Territory{Name — имя блока zone (собственный name-атрибут не читается,
  счётчик), MinZ, MaxZ, Nodes [][2]int32, Banned (сырые территории-исключения: узлы, minZ,
  maxZ)}; отсутствие minZ/maxZ или x/y у узла — структурная ошибка; Shape/Rad — raw-bag
  (terr.shape/terr.rad) до P2.5; глобальный реестр по имени, любой дубликат имени — ошибка.
  Записи NpcSpawn{NpcID, Point{X,Y,Z,Heading,RespawnDelay}? , Territory string?, Count,
  RespawnDelay}: точка и территория могут присутствовать обе (76 записей; канон при обеих
  спавнит в случайную точку территории, а точку и heading игнорирует — выбор остаётся за
  потребителем фазы 3; данные сохраняют обе); ни той, ни другой — ошибка; Heading дефолт −1
  (канон) + счётчик; Count дефолт 1; отсутствие RespawnDelay — 0 и счётчик; единицы
  RespawnDelay/RespawnTime — секунды; respawnRandom, chaseRange, periodOfDay, листья
  AIData — raw-bag спавна (spawn.*); ссылки спавн→NPC и спавн→территория — каркас;
  **спавн NPC из диапазона fake players 80000–89999 без определения — счётчик
  FakePlayersSkipped, не ошибка** (порт семантики checkTemplate канона: гейт
  FakePlayersConfig; единственный случай — Others/FakePlayers.xml, id 80000).
- **Память.** Raw-bag NPC ≈ 240–260 тыс. записей; оценка ≈ 25–30 МБ резидентно, суммарная
  статика ≈ 40–45 МБ — осознанная цена «ничего не теряется». Путевые ключи интернируются
  словарём загрузки (~100 уникальных ключей на ~250 тыс. вхождений); значения — как есть.
- **Static/Dump/отчёт.** Доступ: Item(id), Npc(id), Territory(name) — по значению; Spawns()
  — слайс статики в детерминированном порядке (путь файла, позиция; сортировка при
  загрузке). Контракт пакета расширяется и фиксируется в doc-комментарии: записи
  возвращаются по значению, все вложенные слайсы/мапы — только чтение (bag — через Set,
  как P2.1); методы-счётчики не вводятся, Len() удаляется — единственный источник чисел
  Report. Dump: канонический текст NPC по id — включая dropLists (порядок файла) и minions
  (сверка артефакта P2.7 слепа без них), территорий по имени, спавнов по порядку. Счётчики
  отчёта: Npcs, Spawns, Territories, DropItems, Files, UnknownTypes/UnknownKeys с
  квалификацией категории (npc.type.X, npc.race.Y, npc.key.Z, spawn.key.W; предметные
  ключи P2.1 без изменения), MissingLevel/MissingType, ChanceOver100, MinOverMax,
  WithoutRespawnDelay, WithoutHeading, FakePlayersSkipped, NamedBlocks, DisabledFiles;
  Entry.ID обобщается с ItemID до int64 (ID записи категории).
- **Атрибуция.** Порты семантики NpcData/SpawnData (дефолты, домены, гейт fake players,
  семантика minion Max) — источником в doc-комментариях по образцу P2.1.

**Критерии приёмки.**
- Синтетика с намеренно битыми ссылками (дроп→несуществующий предмет, спавн→несуществующий
  NPC вне диапазона 80000–89999, спавн→несуществующая территория, миньон→несуществующий
  NPC, ignoreNpcId→несуществующий NPC) — каждая ловится отдельной записью отчёта, сборка
  красная; тест машинный.
- Дубли NPC и территорий, шанс-минус/NaN, min/max-минус, спавн без точки и территории,
  territory без minZ/maxZ, list без enabled — отдельные записи-ошибки; шанс >100, min>max,
  отсутствие level/name/heading/respawnDelay, fake-player-спавн — счётчики, сборка зелёная.
- Реальный датапак канона (плоский состав) грузится без ошибок целостности; выжимка
  счётчиков — в журнал (КТ-3).
- Fuzz-цель на новых парсерах в CI; злые входы — ошибка с местом, не паника; разбор
  итеративный по токенам (как P2.1), без рекурсии по глубине.
- Бенчмарки: синтетический — в репо (CI исполняет с фазы 4); реальный набор (env-путь) —
  ручной baseline в журнал для P2.7: ns/op, B/op, allocs/op, резидентный heap после Load,
  счётчики категорий; эталон P2.7 — полный состав Load.

**Ревью-профиль:** S2 — инвариантщик, доменщик, перформансер, прагматик; S8 — + тестировщик.

**Зависимости:** P2.1 (каркас, предметы).

**Ссылки:** r2 §Фаза 2 (дроп→предмет, спавн→NPC); r4 (генераторы референсов — не переносим);
ADR-0001 (атрибуция портов).

### P2.3 Геодата: формат, парсер, mmap-представление — internal/geo — ✅

**Спецификация.**

- Формат L2J-геодаты; канон семантики чтения — GeoEngine канона (aCis/Mobius, порт с
  атрибуцией); константы и раскладка — из исходника канона, не по памяти (предупреждение r1:
  l2off и L2J форматы различаются). l2off — анти-скоуп.
- Представление: region→block (flat/complex/multilayer)→cell→layers, NSWE-флаги, высоты.
  Декодер работает над `[]byte` и не знает источника байтов: `syscall.Mmap` внешнего файла
  (Windows — платформа владельца, обязательная проверка в задаче) или embedded-байты артефакта
  P2.7. Лукап ячейки — индексная арифметика O(1) поверх байтов, без копирования и без syscall
  на ячейку.
- Валидация в общем каркасе отчётов: структура файла, типы блоков, размеры, счётчик слоёв,
  sanity NSWE; разрушенная структура — ошибка загрузки.
- Синтетические гео-блоки (наши байты): все три типа блоков, многослойность, границы регионов.

**Критерии приёмки.**
- Golden: синтетические байты ↔ декодированные структуры (все типы блоков, многослойность).
- Злые входы: обрезанный файл, неверный тип блока, слой вне лимита, выход за регион —
  детерминированная ошибка с местом, не паника; fuzz-цель в CI-смоуке.
- Лукап ячейки: 0 аллокаций, бенчмарк; представление не расширяет Go-кучу (маппинг вне кучи —
  фиксируется тестом/бенчем памяти).
- Ручной прогон владельца на реальной геодате: файлы открываются, отчёт валидации чист или
  выписан — выжимка в журнал (КТ-3).

**Ревью-профиль:** S2 — инвариантщик, безопасник, перформансер, прагматик; S8 — + доменщик,
тестировщик.

**Зависимости:** P2.1 (каркас отчётов — гео-валидация в том же формате).

**Ссылки:** r1 (структура geodata, mmap/off-heap, «сверять по парсеру-референсу»); AGENTS-инвариант
6 (статика read-only, off-heap); ADR-0005 (матрица: geo без зависимостей).

### P2.4 Геодата: примитивы движения и LOS — ✅

**Спецификация.** Три чистые функции поверх представления P2.3:

- `canMove(from, to)` → дальняя достижимая точка: supercover-обход (Amanatides–Woo по r1),
  анти-срез диагонали (угловая ветка — оба ортогональных флага), кламп до последней валидной
  ячейки.
- `getNearestZ(x, y, z)`: резолв ближайшего слоя с step-height; в multilayer — ближайший
  связный слой (не «телепорт на мост»).
- `canSee(from, to)` (LOS): трек Z линии по ячейкам, рельеф выше линии → перекрытие.
- Канон семантики и порогов — GeoEngine канона (порт с атрибуцией); расхождения канонов —
  списком в реестр задачи (прецедент: канон паддинга P1.1).
- Тестовая геометрия — синтетические карты (P2.3): стена, L-угол, мост над проходом, лестница
  step, обрыв, плоский блок (broad-phase-случай).

**Критерии приёмки.**
- Таблица синтетических геометрий: ожидания детерминированы (кламп-точка, blocked, слой).
- Property-инварианты: возвращённая кламп-точка сама достижима из from; blocked ⇒ тест
  называет запрещающий фактор (NSWE/stepZ) — свидетельство в тесте, не «false и всё».
- Бенчмарки `canMove`/`canSee`/`getNearestZ` (реестр ADR-0005 «Геодата: canMove/пасфайнд»);
  0 аллокаций; baseline в журнал (benchstat-выписка).
- Диагональный срез угла невозможен — тест на L-стене (анти-чит-сценарий r1).

**Ревью-профиль:** S2 — инвариантщик, безопасник, доменщик, перформансер, прагматик; S8 — +
тестировщик.

**Зависимости:** P2.3.

**Ссылки:** r1 (DDA, три места типовых багов, LOS); r2 §Фаза 3 (гео-валидация движения —
потребитель); ADR-0005 (реестр путей).

### P2.5 Зоны — ✅

**Спецификация.**

- Категория «зоны»: типы зон Interlude по канону (peace/combat, spawn-территории, города,
  урон и т.п. — состав по дистрибутиву), формы (полигон/прямоугольник/цилиндр), координаты,
  принадлежность точки зоне.
- Валидация: пустая/вырожденная геометрия — ошибка (в том числе геометрия территорий,
  загруженных в P2.2: точки-узлы, minZ/maxZ, формы). Ссылки спавн→территория закрываются
  уже в P2.2 концом той же загрузки (в каноне геометрия территории инлайн в спавн-файлах),
  реестр неразрешённых ссылок после Load пуст по построению; тест на битую территорию —

- Поля — по потребителю (спавн-территории фазы 3; прочие типы — данные без глубокой

**Критерии приёмки.**
- Point-in-zone: внутри/снаружи/граница — таблица тестов на каждой форме.
- Битая ссылка спавн→территория ловится машинным тестом в P2.2; после полной загрузки
  синтетики неразрешённых ссылок нет.
- Fuzz-цель; злые входы — ошибка с местом; ручной полный прогон (КТ-3).

**Ревью-профиль:** S2 — инвариантщик, доменщик, прагматик, перформансер (расширено в ходе
задачи: решение о горячем пути point-in-zone — реестр P2.5 F8); S8 — + тестировщик.

**Зависимости:** P2.1 (каркас), P2.2 (территории спавнов — геометрия для валидации).

**Ссылки:** r2 §Фаза 2 (зоны в составе категорий); ADR-0004 (AoI-сетка ≠ зоны — зоны остаются
датой, видимость их не импортирует).

### P2.6 Скиллы — структурный каркас — 🔄

**Спецификация.** Формат — Mobius Interlude (элементный, не set/val); семантика чтения —
DocumentSkill/DocumentBase/Skill канона (порт с атрибуцией). Факты проработки (машинный
обход каталога канона XML-парсером): каталог `stats/skills/` — 33 файла верхнего уровня
(максимум 716 КБ — 01200-01299.xml, ~5,4 МБ), `custom/` — 4 файла/6 скиллов (пропускается,
как у предметов P2.1), `documentation.txt` — не-XML (фильтр расширения, без счётчика —
не теряется: не категория); корень `list` без enabled-атрибутов; 2700 элементов `skill`
(2694 без custom), все id уникальны (дублей 0, включая custom), атрибуты id/name/levels
присутствуют всегда; сумма levels 15311, максимум 80, единичных 1301; энчанты — только
enchantGroup1 (258 скиллов: 175 со значением 1, 83 со значением 2) и enchantGroup2
(227: 145/82), значения 1/2; элементов enchant1 485, enchant2 637, enchant1effects 76,
enchant2effects 21, enchantNconditions — 0; таблицы: 5496 шт., 74 237 значений, 261
уникальное имя, длина ≠ levels у 921 (проверка «длина == levels» ложнокрасная); легаси
`<set>` — 0, инлайн-атрибуты levelValues/subLevelNValues — 0, вложенных детей у прямых
элементов — 0; типизированные поля бывают `#`-ссылками (itemConsumeId 49, abnormalTime 9,
reuseDelay 8, hitTime 8, isDebuff 1, isMagic 1 — скилл 4483) — резолв таблиц обязателен уже
для каркаса; override энчанта типизированного поля бывает и строковым литералом (скиллы 254/302:
`<enchant1 name="operateType">A2`, `name="isDebuff">true`); предметные ссылки: itemConsumeId
275 элементов + 49 таблиц (0 = нет ссылки), itemConsumeCount 276 + 47, itemConsumeSteps 3;
скилл→скилл ссылки (channelingSkillId 9, displayId 6, #triggeredLevel 32) — вне скоупа, raw;
условия `conditions` 355 (атрибуты msg/msgId/addName, вложенные условия), контейнеры эффектов:
effects 2172, selfEffects 8, channelingEffects 4, startEffects 2, endEffects 1, pve/pvpEffects
0; объём raw: 2284 контейнера эффектов (11828 узлов) + 1040 узлов условий, 26126 прямых
элементов; корень всех файлов несёт только xsi-атрибуты схемы.

- **Генерация уровней (порт DocumentSkill):** термины: r — суффикс имени атрибута
  enchantGroupR (r ∈ 1..8), group — числовое значение этого атрибута. Базовые уровни
  1..levels; энчант-маршрут r существует только при атрибуте enchantGroupR и содержит
  size(group) уровней: group < 3 → 30, иначе 15; номер уровня = 101 + 40·(r−1) + i,
  i = 0..size−1 (C6-адаптация канона: маршрут 1 — уровни 101+, маршрут 2 — 141+). Порядок
  Skill-записей: база, затем маршруты по возрастанию r.
- **Резолв значений (порт DocumentBase.parseElementValue/parseBeanSet/getTableValue):**
  прямой элемент `<key>значение</key>` — значение = текст (конкатенация при вложенности,
  семантика getTextContent); `#ref` — таблица ref по индексу: базовый уровень L → [L−1],
  энчант-уровень → наследование последнего базового значения [levels−1] (прямые элементы
  переapply-ятся на энчант-уровнях), override `<enchantR name="key">…</enchantR>` →
  [i] по подиндексу маршрута; override применяется к типизированным полям при любом виде
  значения — литерал или `#`-ссылка; применение значений — в порядке файла, для одного
  ключа побеждает последний по файлу среди прямых элементов и enchantR (семантика
  StatSet.set канона; в дисте override всегда после прямых элементов). При ошибке
  `table` поле уровня остаётся с дефолтом канона, запись-ошибка внесена, уровень
  материализуется, сборка красная (прецедент buildItem: дефолт + ошибка). Пустой текст —
  пропуск со счётчиком EmptyValues, в raw-bag не попадает (канон пропускает молча).
  Таблица обязана начинаться с `#`
  (иначе ошибка разбора файла, канон роняет IllegalArgumentException); повтор имени
  таблицы внутри скилла — побеждает последняя, счётчик DupTables (канон: HashMap.put).
  **Разрыв цепочки уровней — ошибка:** таблица, на которую ссылается прямой элемент,
  отсутствует или её длина < levels; таблица ссылки enchantR — отсутствует или короче
  размера маршрута (канон здесь молча подставляет пустую строку, что теряет уровень) —
  новый код отчёта `table`; запись с местом (файл, строка, id скилла) и именем таблицы.
  Атрибуты корня list игнорируются (xsi-схема); корень ≠ list — ошибка root каркаса,
  skill-корень канона не поддерживается.
- **Типизированная оболочка** — запись уровня `Skill{Name string, OperateType string,
  TargetType string, ID SkillID, Level int32, HitTime int32, ReuseDelay int32,
  AbnormalTime int32, IsMagic int32, IsDebuff bool}` (поля по убыванию размера)
  материализуется при загрузке для
  каждого уровня (база + энчанты, ~30 тыс. записей, ~3 МБ): материализация и есть машинная
  проверка цепочки. Дефолты канона (Skill.ctor): HitTime/ReuseDelay/AbnormalTime/IsMagic 0,
  IsDebuff false, TargetType SELF; OperateType обязательна (в дисте есть всегда; канон при
  отсутствии бросает исключение и молча теряет запись уровня — мы даём ошибку attr на весь
  скилл). Домены: тайминги int32 ≥ 0 (мс; abnormalTime — сек), отрицательное/неразбор/
  переполнение — ошибка number; IsMagic — неразбор числа ошибка number, число вне
  {0,1,2,3} — счётчик skill.isMagic.*, поле хранит фактическое значение; IsDebuff —
  true/false, иначе ошибка number (прецедент is_stackable P2.1); OperateType — словарь
  канона SkillOperateType (A1 A2 A3 A4 CA1 CA5 DA1 DA2 P T; в дисте 7 значений),
  неизвестная — счётчик skill.operateType.*; TargetType — словарь TargetType канона
  (38 значений: AREA AREA_CORPSE_MOB AREA_FRIENDLY AREA_SUMMON AREA_UNDEAD AURA
  AURA_CORPSE_MOB AURA_FRIENDLY BEHIND_AREA BEHIND_AURA CLAN CLAN_MEMBER COMMAND_CHANNEL
  CORPSE CORPSE_CLAN CORPSE_MOB ENEMY_SUMMON FLAGPOLE FRONT_AREA FRONT_AURA GROUND HOLY
  NONE ONE OWNER_PET PARTY PARTY_CLAN PARTY_MEMBER PARTY_NOTME PARTY_OTHER PC_BODY PET
  SELF SERVITOR SUMMON TARGET_PARTY UNDEAD UNLOCKABLE; в дисте 27), неизвестная — счётчик
  skill.targetType.*, отсутствие — дефолт SELF + счётчик MissingTargetType.
- **Определение скилла** `SkillDef{ID, Name, Levels int32, Enchant []SkillEnchant,
  Base []Skill, EnchLvls [][]Skill, tables, set, enchantOverrides, raw []RawNode}` —
  исходная форма и материализованные уровни для фаз 4/6: SkillEnchant{Route int8}
  (размер маршрута = len соответствующего слайса EnchLvls); уровни — слайсы в def
  с преаллокацией по известному числу (Base длины levels, EnchLvls — по маршруту;
  0 аллокаций на лукап), map — только по id defs (2694 записей): лукап
  Skill(id, level) = def по id → уровень ≤ levels → Base[level−1], иначе маршрут
  r = (level−101)/40 + 1 и подиндекс level − (101+40·(r−1)) с проверкой границ. Таблицы
  (имя без `#` → значения, доступ — метод `Table(name)`, конвенция: имя без `#`, как
  хранится); raw-bag прямых элементов (ключ = имя элемента / name атрибут set, значение
  как в файле, `#`-ссылки не резолвлены, метод `Set(key)`); bag хранит все прямые
  элементы в исходной файловой форме, включая типизированные ключи (прецедент предметов
  P2.1: Set("weight") возвращает файловое значение): Set(key) — форма def без резолва,
  материализованное поле уровня — резолв по уровню, включая override/наследование;
  overrides энчантов
  (route → ключ → значение, метод `EnchantValue(route, key)`); контейнеры эффектов/условий —
  RawNode{Name, Attrs (отсортированы), Text (trim), Children} — иммутабельное минимальное
  дерево, комментарии отбрасываются, доступ — `Raw() []RawNode`. `SkillDef(id)` — по
  значению, вложенные слайсы/мапы только чтение (контракт пакета). Цепочка уровней
  представлена самими записями и маршрутами def (prev/next вычислимы: base 1..N, энчант
  101+40·(r−1)+i) — избыточные указатели prev/next не хранятся (дублирование = рассинхрон).
  Строки интернируются словарём загрузки (прецедент keyDict P2.2): ключи raw-bag, имена
  таблиц, ключи enchantOverrides, имена элементов/атрибутов RawNode, словарные значения
  OperateType/TargetType; Name уровней разделяет строку def.
- **Дубли и ссылки:** повтор `<skill id>` — ошибка dup_id (уровни всегда пересекаются:
  оба генерируют 1..levels), побеждает первая запись (как предметы). Предметная ссылка:
  itemConsumeId после резолва по уровню ≠ 0 → linkRef (kind linkItem, владелец id скилла,
  место — файл/строка элемента или таблицы, в Message уровень) — общий каркас P2.2;
  регистрируется на каждый уникальный (скилл, предмет) с места первого вхождения уровня —
  таблица одинаковых id не плодит копий ошибки; itemConsumeCount без Id — данных нет
  (id=0 = нет ссылки, канон).
- **Границы каркаса (осознанно, регистрируются в реестре):** параметры эффектов/условий —
  raw без валидации (потребитель — фазы 4/6); их `#`-ссылки резолвятся иначе, чем
  типизированные поля — базовый уровень [L−1], энчант-уровень с собственным контейнером
  enchantR-эффектов — подиндекс маршрута [i], fallback базовых эффектов на энчант-уровне —
  [levels−1] (семантика DocumentSkill для фаз 4/6, каркас не применяет); скилл→скилл
  ссылки (channelingSkillId, displayId, triggeredLevel) — raw: канон сам не проверяет их
  при загрузке (валидация на месте использования), #triggeredLevel требует резолва таблиц
  эффектов — интерпретация фаз 4/6; инлайн-атрибуты levelValues/subLevelNValues и любые
  чужие атрибуты прямых элементов и самого `<skill>` — счётчик UnknownKeys с квалификацией
  skill.attr.* (не потеря молча, отдельного map нет); вложенные дети прямого элемента —
  текст конкатенируется как в каноне + счётчик NestedDirect; `<enchantR>` без enchantGroupR —
  мёртвый override, счётчик OrphanEnchants (канон игнорирует молча); enchantGroupR ∉ 1..8
  или значение ≤ 0 — ошибка attr.
- **Отчёт:** счётчики Skills (defs), SkillLevels (всего), EnchantedSkills (defs с ≥1
  маршрутом), SkillTables, MissingTargetType, OrphanEnchants, NestedDirect, DupTables;
  EmptyValues — переиспользуемый каркасный счётчик (пустой текст прямого элемента);
  чужие атрибуты и unknown-enum — в существующие UnknownKeys/UnknownTypes с квалификацией
  (skill.attr.*, skill.operateType.*, skill.targetType.*, skill.isMagic.*); новый код
  записи `table` (битая/короткая таблица). Dump: defs по возрастанию ID — атрибуты,
  маршруты, таблицы (имя отсортировано), set (ключи отсортированы), overrides (route,
  ключи), raw-деревья (каноническая сериализация: имя, attrs по имени, текст, дети); затем
  уровни по возрастанию (id, level) — все типизированные поля. Формат стабилен — золотое
  сравнение и сверка артефакта P2.7.
- **Атрибуция:** порты семантики DocumentSkill (генерация уровней, C6-номера, наследование
  энчантов, индексация таблиц), DocumentBase (parseElementValue/parseTable, «имя с #»,
  getTextContent), Skill.ctor (дефолты полей) — источником в doc-комментариях, GPLv3.

**Критерии приёмки.**
- Синтетика: golden загрузки — значения типизированных полей по уровням совпадают с
  ручным ожиданием (таблица на hitTime, энчант-наследование последнего базового значения,
  override enchant2, isDebuff через таблицу); каждый заявленный уровень (база и энчанты)
  достижим через Skill(id, level); уровни вне диапазона — ok=false.
- Злые входы — детерминированные ошибки с местом, не паника: битый XML, обрыв, дубль
  `<skill id>`, levels 0/минус/не-число, отсутствие id/name/levels/операции, таблица без
  `#` в имени, `#`-ссылка на отсутствующую таблицу, таблица короче levels при прямой
  ссылке, таблица короче размера маршрута при enchantR-ссылке, hitTime −1, isDebuff «да»,
  isMagic «abc», enchantGroup9/0; таблица длины ровно levels с прямой `#`-ссылкой —
  зелёная (граница условия); счётчики (сборка зелёная): неизвестные
  operateType/targetType/isMagic-число, отсутствие targetType, orphan enchant3 без
  группы, вложенный прямой элемент, чужой атрибут у skill/прямого элемента;
  itemConsumeId → несуществующий предмет — красная через общий каркас ссылок.
- Целостность цепочки: подложенный разрыв (таблица 3 значений у levels=5 скилла с
  `<hitTime>#hit</hitTime>`) — красная сборка, в записи названа таблица и уровень.
- Реальный датапак канона (плоский состав, custom пропущен) — ручной прогон: 0 ошибок
  целостности; выжимка счётчиков в журнал (КТ-3); прогноз: 2694 скилла, 15311 базовых
  уровней, 258 defs с энчантами (485 маршрутов: G1 258, G2 227 — G2 всегда вместе с G1),
  14550 энчант-уровней, 29861 записей уровней, 5496 таблиц, 27 значений targetType,
  7 operateType; резидентный heap после Load — в выжимку.
- Fuzz-цель FuzzLoadSkills в CI-смоуке; находки — регресс-тесты.
- Бенчмарки: BenchmarkLoadSynth расширяется скиллами — состав отражает распределение
  дистрибутива (десятки defs, levels от 1 до 80, таблицы 30–80 значений, энчант-маршруты
  с override, raw-деревья эффектов и условий); BenchmarkSkillLookup — hit/miss лукап
  Skill(id, level) на синтетике с уровнями и маршрутами, гейт 0 аллокаций
  (AllocsPerRun, прецедент P2.5); реальный набор (env-путь) — ручной baseline в журнал
  для P2.7 (ns/op, B/op, allocs/op, resident heap после Load, счётчики). Строка реестра
  горячих путей ADR-0005 для лукупа не добавляется: рантайм-потребитель появится в фазе 4
  — тогда строка и бенчмарк против реального паттерна (отсрочка зафиксирована в реестре
  задачи).
- Ворота зелёные; внешних зависимостей нет; доступ к статике — без мутируемых ссылок.

**Ревью-профиль:** S2 — инвариантщик, доменщик, перформансер, прагматик; S8 — + тестировщик.

**Зависимости:** P2.1 (каркас, предметы для ссылок).

**Ссылки:** r2 §Фаза 2 (скиллы как таблицы) и §Фаза 6 (table-движок эффектов — потребитель
каркаса); решение 4 (полнота по потребителю); решение 7 (целостность = ошибка, неизвестное =
счётчик).

### P2.7 Компилированный артефакт статики + embed-транспорт — ⬜

**Спецификация.** Разделение сборки и загрузки (решения 1 и 8), после фиксации схем всех
категорий:

- `l2data build`: загрузить всё (P2.1–P2.6) путём парсинга исходников, прогнать валидацию
  (отчёт = отчёт сборки; разрыв = красная сборка, артефакт не обновляется), скомпилировать
  единый плоский артефакт: манифест (версия схемы, хэш входов P2.1) + категории + геодата как
  есть (байты блоков, без перекодирования). Кодирование категорий — плоское собственное или
  `encoding/gob` (stdlib); выбор — бенчмарком в задаче.
- `Load` быстрый путь: сверить манифест → hit: байты артефакта без копирования в кучу (внешний
  файл — `syscall.Mmap`; embed — глобальный `[]byte` над rodata), категории декодируются в
  типизированные структуры, геодата отдаётся zero-copy поверх байтов; miss — прозрачный
  пересбор с логом. Парсинг исходников остаётся явным путём (`l2data check`) и в CI.
- embed-транспорт: артефакт складывается в gitignored-каталог внутри модуля; файл с
  `//go:embed` — за build-тегом `embedded`; цепочка владельца: подложить данные →
  `l2data build` → `go build -tags embedded` → сервер = один файл (Makefile-цель).
- CI: синтетика на обоих транспортах (внешний файл и embed); путь парсеров покрыт тестами
  `l2data check` всегда.

**Критерии приёмки.**
- Эквивалентность: статика из артефакта равна статике парсинга тех же исходников (машинный
  тест на синтетике полного состава).
- Битая ссылка в исходниках → `l2data build` красный, артефакт не обновлён.
- Чужая версия схемы/хэш входов → пересбор; цикл «изменил один XML → пересобрался артефакт»
  воспроизводим.
- Числа в журнал на полных данных: время `check` (парсинг), время `build`, время `Load` из
  артефакта (внешний файл и embed).
- Сборка с тегом `embedded` на синтетике: бинарарь содержит статику, загрузка без внешних
  файлов; сборка с тегом без артефакта падает внятной ошибкой.
- Гео-лукапы поверх embedded-байтов — 0 аллокаций (перенос критерия P2.3).
- Артефакт и gitignored-каталог в репо не попадают (машинная проверка); ноль внешних
  зависимостей; ворота зелёные.

**Ревью-профиль:** S2 — инвариантщик, безопасник, перформансер, прагматик; S8 — + тестировщик.

**Зависимости:** P2.1–P2.6 (схемы категорий зафиксированы — формат артефакта компилируется
один раз).

**Ссылки:** r2 §Фаза 2 (отчёты валидации); AGENTS-инвариант 6 (статика read-only, off-heap);
ADR-0001 (данные вне репо; решение владельца о непубликации бинарарей); ADR-0003 D1–D6
(идентичность данных для реплея — хэш манифеста).

## Порядок исполнения

```
P2.1 (рамка+предметы) → P2.2 (NPC/спавны/дроп) → P2.3 (гео-парсер) → P2.4 (примитивы)

```

- Первые четыре задачи — критический путь фазы 3 (скелету нужны предметы, NPC+спавны, гео,
  `canMove`); зоны и скиллы переносятся без переделок, если фазу придётся резать; артефакт —

- Все задачи — полный конвейер ADR-0006; ведущая сессия ведёт по одной задаче за раз.
- Правка ADR-0005 в ходе фазы ожидается только на новые рёбра/подпакеты (появятся — правкой
  решения, как требует карта).

## Анти-скоуп (в фазу 2 НЕ входит)

- Пасфайнд: A*, иерархический A*, flow-field, граф переходов слоёв — фазы 4/6 (r1/r2).
- Оптимизация загрузки сверх артефакта (сжатие, распараллеливание парсинга, инкрементальные
  пересборы) — только по измерениям (perf.md). Сжатие не применяется: embed не сжимает,
  геодате нужен random access; gzip-упаковка артефакта — разрешённая эволюция.
- Runtime-кеш статики (LRU/вытеснение/TTL) — статика целиком в памяти и иммутабельна:
  вытеснение = латентные всплески повторной загрузки, TTL = недетерминизм без причины,
  LRU-счётчики = точка синхронизации на горячем пути (против lock-free шаринга инварианта 6).
  Постатейное вытеснение большого объёма уже делает ОС: страницы mmap/embed — LRU ядра, read-only,
  без кода. Кешироваться могут только производные вычисления (мемоизация пасфайнда/LOS) — фазы 4+,
  по измерениям, LRU без TTL и только для чистых функций (вытеснение влияет на скорость, не на
  результат).
- Публикация бинарарей со встроенными данными и любая дистрибуция наружу — не планируется
  (решение владельца: сервер личный); если появится — пересмотр ADR-0001.
- Типизация полей эффектов скиллов, формулы урона/статов — фазы 4/6 (каркас хранит raw).
- AI-правила и бихевиоры как данные, аггро-таблицы глубже флагов — фаза 6.
- l2off-формат геодаты, версии кроме Interlude, мультидатапачность — не поддерживаются.
- Серверный код и потребители статики (мир, спавн-движок, инвентарь) — фаза 3+.
- Правка самих данных датапака/геодаты и балансные решения — фаза 2 только читает и валидирует.
- Валидация «смысла» данных (баланс шансов, правильность цифр) — вне фазы: только структурная
  и ссылочная целостность.
